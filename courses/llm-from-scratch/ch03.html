How Attention Actually Works

The hardest chapter in the book, and the one everything else rests on. Attention is really just three operations — a dot product, a softmax, and a weighted sum — applied in a particular order. Every number in these labs is computed live, and matches the book's printed output exactly.

3.1

The problem with long sequences

Before transformers, translation used an encoder–decoder RNN. The encoder read the source sentence one word at a time, updating a hidden state as it went, trying to squeeze the meaning of the whole sentence into that one final state. The decoder then took that single state and generated the translation.

You can already see the flaw. Everything the decoder knows about a forty-word sentence has to fit through one fixed-size vector, and the decoder cannot reach back to any earlier encoder state. Long-range dependencies get lost.

3.2

Attention arrives

In 2014 the Bahdanau attention mechanism modified the encoder–decoder RNN so the decoder could selectively reach any part of the input at every decoding step. Three years later researchers found the RNN wasn't needed at all — and the transformer, with self-attention, replaced it entirely.

The "self" in self-attention

Ordinary attention relates two sequences — an input and an output, as in translation. Self-attention relates a sequence to itself: every position weighs the relevance of every other position in the same sequence. That's the whole distinction.

3.3

Simple self-attention, without trainable weights

We start with a stripped-down version — no learnable parameters at all — to isolate the mechanism. The goal is to compute a context vector for each token: an enriched embedding that carries information about that token and every other token in the sequence.

The running example is the sentence "Your journey starts with one step", already embedded as six three-dimensional vectors. Three dimensions is unrealistically small — it just fits on a page.

A dot product multiplies two vectors element-wise and sums the results. The bigger it is, the more aligned the two vectors — which is exactly why attention uses it to measure how much one token should attend to another.

Three steps to a context vector

Fix one token as the query. Then:

  • Step 1 — attention scores. Dot the query with every token, including itself.
  • Step 2 — attention weights. Softmax those scores so they're positive and sum to 1.
  • Step 3 — context vector. Multiply each input vector by its weight and add them all up.

Work through it below. Choose any query token and step through the three stages.

All tokens at once

Doing that for every token individually needs a nested loop. Matrix multiplication does the whole thing in one line: attn_scores = inputs @ inputs.T, then a row-wise softmax. The result is a 6×6 matrix where row i, column j is how much token i attends to token j.

3.4

Adding trainable weights

The version above has nothing to learn. Real self-attention — scaled dot-product attention — introduces three weight matrices that are learned: Wq, Wk and Wv. Each input vector is projected through all three to produce a query, a key and a value.

The mechanism then changes only slightly: scores come from query·key instead of input·input, and the context vector is a weighted sum of values instead of raw inputs.

Why "query", "key" and "value"?

The names come from databases. The query is what you're searching for — the token currently being processed. Each token also carries a key, like an index entry, used to match against the query. And a value, the actual content retrieved once the match is scored. Attention is a soft database lookup where you retrieve a blend of every value, weighted by how well its key matched.

Why divide by √dk

Before the softmax, scores are divided by the square root of the key dimension. This is the "scaled" in scaled dot-product attention, and it isn't cosmetic.

As the embedding dimension grows — over 1,000 in real LLMs — dot products get large. Feed large numbers into softmax and it starts behaving like a step function: one weight goes to nearly 1, the rest to nearly 0. Gradients through that are almost zero, and learning stalls. Watch it happen.

3.5

Causal attention: hiding the future

A GPT generates left to right, so when it processes position i it must not see positions after i. During training the whole sentence is present at once, so we have to enforce this deliberately — by masking everything above the diagonal of the attention matrix.

The book shows two ways to do it, and they give identical results. Toggle between them.

Both produce row 2 = [0.5517, 0.4483, 0, 0, 0, 0], matching the book. The −∞ route is preferred because it's one step instead of three — e−∞ = 0, so softmax zeroes those positions for free. Note: this lab uses the attention weights from SelfAttention_v2 (the trainable version), which is what the book masks in section 3.5 — not the simpler weights from lab 4.
Is there information leakage?

It looks suspicious that masked positions were included in the softmax denominator before being zeroed. But renormalising afterwards is mathematically the same as having run softmax over only the unmasked positions to begin with. The masked positions contribute nothing to the final distribution — no leakage.

Dropout on the attention weights

One more addition, purely to fight overfitting: dropout randomly zeroes some attention weights during training. Everything surviving is scaled up by 1/(1−rate) so the average magnitude stays constant. Dropout is only active during training — it's switched off for inference.

3.6

Multi-head attention

One attention mechanism learns one way of relating tokens. Run several in parallel — each with its own Wq, Wk, Wv — and each head can specialise in a different kind of relationship. Concatenate their outputs and you get a richer representation.

There are two implementations. The intuitive one stacks separate CausalAttention modules. The efficient one uses a single large weight matrix and splits the result into heads by reshaping — one matrix multiplication instead of one per head.

The chapter in one line

score = q·k, scale by √dk, mask the future, softmax, weight the values, sum. That sequence — repeated across several heads and stacked in twelve layers — is the entire engine of a GPT. Chapter 4 builds everything around it.
