21.1

Why lists aren't enough

Read · ~4 minPractice · ~8 min

The problem. A shop raises every price by 5%. You have the prices in a list: [40, 60, 120, 200]. In pure Python you reach for a loop, or — since Unit 12 — a comprehension: [p * 1.05 for p in prices]. It works. Now make the list a million prices long and do it forty times a second, which is roughly what a real data pipeline asks for. The comprehension is suddenly the slow part of the program, and worse: you're still writing the machinery of the loop when all you wanted to say was "multiply everything by 1.05".

The idea, in plain words. NumPy gives you a new kind of container — an array — that takes the multiplication personally. You write prices * 1.05 and every number inside moves. No loop, no comprehension, no for. Underneath, the multiplication happens in compiled C over a solid block of memory, which is why it's tens of times faster; on the surface, your code finally says what you meant.

Two lines get you there. import numpy as np — the as np nickname is a universal convention, and every piece of NumPy code on Earth uses it — then np.array([40, 60, 120, 200]) to turn a list into an array.

There is one honest catch, and it's the trade that buys the speed: an array holds one type. All ints, or all floats — not a mix, and certainly not names alongside numbers. That single type is called the array's dtype, and because every slot is the same size, NumPy can lay the whole array out as one unbroken run of memory and let the processor tear through it. A Python list can hold a string, a float and a duck; that flexibility is exactly what makes it slow.

Trace it by hand — the same job, two containers
prices = [40, 60, 120, 200] taxed_list = [p * 1.05 for p in prices] arr = np.array([40, 60, 120, 200]) taxed_arr = arr * 1.05

Line 2: the comprehension does what you'd do by hand — take 40, multiply, keep it; take 60, multiply, keep it; four separate multiplications, four separate Python objects created. The result is a list: [42.0, 63.0, 126.0, 210.0].

Line 4: np.array(...) copies those four numbers into one block of memory, all of them ints, and remembers "this is a run of whole numbers, four of them".

Line 5: here's the whole unit in one line. arr * 1.05 does not mean "repeat the array" (that's what * does to a list — remember Unit 5). It means "multiply each element". A brand-new array comes back, and because 1.05 is a decimal, its dtype is float:

[ 42. 63. 126. 210.]

Note the printing: no commas, and the trailing dots are NumPy saying "these are floats". Arrays print differently from lists, and you'll get used to it faster than you expect.

Common confusion

[1, 2, 3] * 2 gives [1, 2, 3, 1, 2, 3] — a list repeated. np.array([1, 2, 3]) * 2 gives [2 4 6] — every number doubled. Same symbol, completely different meaning, decided entirely by what's on the left. This is Unit 2's rule ("the type decides what the operator means") coming back with a new type, and it catches everyone once.

Worked example

Task: raise four prices by 5% both ways, and look at what each container gives back. Thinking: run it and compare the two printed lines carefully — commas versus no commas is your first clue about which world you're in. Note: this is the first block on the page that imports NumPy, so the runner spends about 15 seconds downloading the library before it starts. That happens once; every block after this is instant.

21.2

Vectorised arithmetic — describing the whole

Read · ~3 minPractice · ~10 min

The problem. Multiplying by 1.05 was one operation. Real work needs the rest: add a bonus to every score, subtract one array from another to get differences, divide quantities by totals to get proportions, and — constantly — ask a question of every element at once ("which of these are above 50?").

The idea, in plain words. Every arithmetic operator works on arrays, and every one of them works element-wise. Two flavours:

  • Array and a single number — a + 5, a * 2, a / 100. The single number is applied to every element. (NumPy calls this broadcasting: the lone number is stretched to cover the array.)
  • Array and array — a + b, a * b. Position by position: first with first, second with second. [10, 20] * [3, 4] gives [30, 80] — not a matrix multiplication, just neighbourly arithmetic down the line. Both arrays must be the same length; if they aren't, NumPy stops you with an error (and 21.3 explains what it's really complaining about).

Comparisons work the same way, and this is where it starts to feel like magic. a > 25 doesn't give you one True or False — it gives you a whole array of them, one answer per element. That's called a boolean array, and it is the single most useful object in NumPy; section 21.4 spends its whole life cashing it in. A small bonus: .sum() on a boolean array counts the Trues, because True counts as 1.

Trace it by hand — one line, four answers
a = np.array([10, 20, 30, 40]) b = np.array([1, 2, 3, 4]) print(a + b) print(a > 25)

Line 3: NumPy walks the two arrays in step — 10+1, 20+2, 30+3, 40+4 — and builds a new array from the four answers. Nothing is changed in place; a and b are untouched.

[11 22 33 44]

Line 4: the same walk, but the question is "bigger than 25?" — asked of 10 (no), 20 (no), 30 (yes), 40 (yes). Four answers, one array:

[False False True True]

The extra space before each True is NumPy lining the column up — False is a character wider. Cosmetic, but worth recognising so it doesn't look like a bug.

Key idea
The operation is applied to every element at once. You stop writing the loop and start describing the whole. Say scores + 5 out loud as "every score, plus five" — that sentence, not the loop, is now your unit of thought.
Worked example

Task: two arrays and a scalar, put through every operator worth knowing. Thinking: predict each line before you run it — especially the division, which turns ints into floats exactly as / always has (Unit 2's rule, unchanged).

21.3

Shape — the thing that will bite you later

Read · ~4 minPractice · ~10 min

The problem. Real data isn't a single row of numbers. Marks come as a table: students down the side, subjects across the top. An image is a grid of pixels. Lists could fake this with lists-inside-lists, but nothing kept track of the layout, and every operation meant nested loops. An array knows its own layout — and once there's a layout to get wrong, getting it wrong becomes the number-one source of errors in every numerical program ever written.

The idea, in plain words. Every array carries a shape: a tuple saying how many along each direction. Ask for it with .shape.

  • np.array([10, 20, 30, 40]) has shape (4,) — one direction, four elements. Flat. A row. This is 1-D, and .ndim says 1.
  • np.array([[1, 2, 3], [4, 5, 6]]) has shape (2, 3) — 2 rows, 3 columns, written as a list of lists, one inner list per row. .ndim says 2. Rows first, always: shape reads (rows, columns).

Two tools come with it. np.arange(12) builds [0 1 2 … 11] — Unit 4's range(), but it hands back a real array. And .reshape(3, 4) takes the same twelve numbers and re-lays them as 3 rows of 4. Reshaping never changes the numbers or their order; it only changes how they're grouped. The one rule: the new shape must hold exactly as many slots as the old one — twelve numbers go into (3, 4) or (2, 6) or (12, 1), but never into (5, 3).

And here is the house rule, borrowed from the LLM notes and worth more than anything else in this unit: say the shape out loud at every step. "marks is (4, 3). Mean along axis 1 gives (4,). Compare to a scalar, still (4,)." Programmers who do this out of habit spend their evenings on ideas; programmers who don't spend them on shape errors. These same shapes, incidentally, are exactly what the LLM series means when it talks about tensor shapes — a tensor is this idea with more directions, and nothing more mysterious than that.

Trace it by hand — twelve numbers, three shapes
data = np.arange(12) grid = data.reshape(3, 4) print(data.shape) print(grid.shape) print(grid.ndim)

Line 1: twelve numbers, 0 through 11, in one flat row. Shape (4,)-style: (12,). One direction.

Line 2: the same twelve numbers, re-grouped four at a time: row 0 is 0–3, row 1 is 4–7, row 2 is 8–11. Nothing moved; the fence moved. Shape (3, 4).

Lines 3–5: read the shapes back. Note the lone comma in (12,) — that's Python's way of writing a one-item tuple, not a typo:

(12,) (3, 4) 2
Fig. 1 — The state of an array. Shape reads (rows, columns) and never the other way round. Every time an array changes hands in your program, this picture should change with it — out loud.
Common confusion

(3,) is not (3, 1). The first is a flat row of three numbers — one direction, printed as [1 2 3]. The second is a 2-D array with three rows and one column each, printed as three stacked lines. They hold the same three numbers and NumPy treats them as different objects with different rules. When an operation fails with a shape complaint and the numbers "look right", this is almost always what happened: somewhere a (3,) met a (3, 1). Say the shape out loud and the mismatch announces itself.

Worked example

Task: build a 1-D and a 2-D array, interrogate both, and reshape one of them twice. Thinking: before each print, say the shape out loud. Then check whether NumPy agrees with you.

21.4

Indexing, slicing & boolean masks

Read · ~3 minPractice · ~10 min

The problem. You have a marks table: four students down, three subjects across. You want one student's Physics mark. You want the entire Maths column. You want only the marks that passed. With lists-of-lists the first is awkward, the second needs a comprehension, and the third needs another one.

The idea, in plain words. Everything you learned in Unit 5 still applies — positions count from 0, : slices, negatives count from the end — with one addition for 2-D: one index per direction, separated by a comma, rows first.

  • a[1, 2] — row 1, column 2. One number.
  • a[0] — the whole of row 0, as a 1-D array.
  • a[:, 0] — read it as "every row, column 0": the whole first column. The colon means "all of this direction". This is the move a list of lists could never make in one step, and you will use it constantly.
  • a[1:3, 0:2] — slices work in both directions at once: rows 1 and 2, columns 0 and 1. A rectangular block.

Then the payoff of 21.2. A boolean array can be used as an index: scores[scores >= 50]. Read it inside-out — scores >= 50 makes a True/False array of the same length, and putting that inside the brackets means "keep the elements where it says True". This is called a mask, and it replaces the filtering comprehension from Unit 12 entirely. [s for s in scores if s >= 50] becomes scores[scores >= 50]: same meaning, said once instead of three times.

Like a filter, a mask usually gives back a shorter array, and nothing marks the gaps — the same honest warning Unit 12 gave about comprehensions still stands.

Trace it by hand — one table, four questions
grid = np.array([[10, 20, 30], [40, 50, 60], [70, 80, 90]]) print(grid[1, 2]) print(grid[:, 0]) print(grid[grid > 45])

Setup: shape (3, 3) — say it out loud.

grid[1, 2]: row 1 (the middle row, [40, 50, 60]), then column 2 within it → 60. A single number, not an array.

grid[:, 0]: every row, column 0 → the first number from each row → [10 40 70]. A 1-D array of shape (3,), pulled straight down through the table.

grid[grid > 45]: the inside first — grid > 45 is a (3, 3) grid of True/False. Used as an index, it collects the Trues in reading order (left to right, top to bottom) and hands them back flat:

60 [10 40 70] [50 60 70 80 90]

Note that last shape change: a mask on a 2-D array gives a 1-D result, because the survivors don't form a rectangle any more. Say it out loud: "(3, 3) in, (5,) out."

Key idea
a[:, 0] is "every row, column 0" — a whole column in one step. And a boolean array inside the brackets is a filter: scores[scores >= 50] keeps exactly the elements whose answer was True.
Worked example

Task: pull single cells, whole rows, whole columns, a block, and a masked selection out of one 3×3 grid. Thinking: before each line, say what shape you expect back — a number, a (3,), or something else. That habit is the entire skill.

21.5

Aggregations & axis — which way does it collapse?

Read · ~4 minPractice · ~10 min

The problem. A summary is a whole array boiled down to one number: the total, the average, the smallest, the spread. Easy enough on a flat array. But on a marks table, "the average" is ambiguous — do you mean each student's average across their subjects, or each subject's average across the students? Both are wanted, constantly, and they are different numbers.

The idea, in plain words. The summary tools are methods on the array: .sum(), .mean(), .min(), .max(), and .std() (the standard deviation — how spread out the numbers are; a small std means everyone scored alike). Called plainly on a 2-D array, each one flattens everything and gives a single number for the whole table.

To summarise part way, add axis=. Here is the sentence to memorise, because it's the one everybody gets backwards: axis is the direction that disappears.

  • axis=0 collapses the rows — it runs down each column and gives you one number per column. On a (4, 3) marks table that's one number per subject, shape (3,).
  • axis=1 collapses the columns — it runs across each row and gives you one number per row. On the same table that's one number per student, shape (4,).

Check yourself with shapes rather than intuition: (4, 3) with axis=0 deletes the 4 and leaves (3,); with axis=1 it deletes the 3 and leaves (4,). Say it out loud and you can't get it wrong; guess from the word "axis" and you'll get it wrong half the time forever.

One more, small but useful: .argmax() gives the position of the largest element rather than its value (and .argmin() the smallest). That position is what you feed back into a list of names to answer "who?" instead of "how much?".

Fig. 2 — marks.mean(axis=0) runs down the columns and leaves one number per subject; marks.mean(axis=1) runs across the rows and leaves one number per student. Read the shapes, not the arrows: (4, 3) minus axis 0 is (3,); (4, 3) minus axis 1 is (4,).
Common confusion

"axis=0 means rows, so it gives me row averages" — no, and this is the single most common NumPy mistake in existence. axis=0 means the row direction is the one being consumed: it walks down through the rows and hands back one number per column. If you can't remember the arrow, remember the shape: whichever number you name in axis= is the one deleted from the shape tuple. (4, 3) with axis=0 → (3,). That test never lies.

Worked example

Task: summarise a 2×4 array whole, then along each axis. Thinking: the eight numbers were chosen so the standard deviation comes out exactly 2 — mean 5, and the spread around it is tidy. Predict the shape of each of the last two lines before running.

21.6

Your build — the marks report, NumPy edition

Read · ~2 minPractice · ~12 min

Unit 12 ended with a marks report: a loop over zip(), a comprehension for the passers, another for the distinctions, an aligned line per person. It was a fine program and it earned its checkpoint. Now build the same report out of one 2-D array — and count the loops you write. There should be none.

The table is four students by three subjects, shape (4, 3). Names and subjects stay in ordinary Python lists, because an array holds one type and these are text: the array carries the numbers, the lists carry the labels, and an index is what connects them. Everything you need is in hand: axis=1 for per-student, axis=0 for per-subject, a boolean mask summed for the pass count, .argmax() for the top scorer, and Unit 2's f-strings — including {name:<8}, which pads a name out to eight characters so the columns line up.

print(f"{subjects[2]:<8}{subject_avg[2]:.2f}")
print(f"Class average: {marks.mean():.2f}")
print(f"Passed: {(student_avg >= 50).sum()} of {student_avg.size}")
print(f"Top scorer: {names[top]} ({student_avg[top]:.2f})")

Count the arithmetic: two mean calls with an axis, one plain mean for the whole table, one masked sum, one argmax. Five lines replace every loop and comprehension in Unit 12's version, and each one says what it means. That's the whole argument for arrays — speed is the bonus, clarity is the point.

21.7

Problem bank — everything at once

Practice · ~12 min

Four mixed problems. Vectorised arithmetic, masks, shape and axis, in combinations — and not a for among them. In order; they get meaner.

B1Celsius to Fahrenheit, all at once

Four temperatures in Celsius. Convert the whole array in one expression — c * 9 / 5 + 32 — and print the result, then the hottest in Fahrenheit to two decimals.

[32. 50. 68. 86.] Hottest: 86.00
Show solution
import numpy as np

c = np.array([0, 10, 20, 30])
f = c * 9 / 5 + 32
print(f)
print(f"Hottest: {f.max():.2f}")

Three operations, four temperatures, one line. The trailing dots in the printout are NumPy telling you the division made these floats — the same rule / has followed since Unit 2.

B2Who passed, and how many

Seven scores. Print the passing ones (50 or more) as an array, then a line saying how many passed out of how many sat. Use a mask for the first and the same comparison summed for the second.

[91 78 85 62 55] 5 of 7 passed
Show solution
import numpy as np

scores = np.array([91, 45, 78, 85, 62, 39, 55])
passed = scores[scores >= 50]
print(passed)
print(f"{passed.size} of {scores.size} passed")

Store the mask result once and both lines can use it — passed.size is the count, no second comparison needed. ((scores >= 50).sum() gives the same 5.)

B3Reshape, then summarise both ways

Take the numbers 1 to 12 with np.arange(1, 13), lay them out as 3 rows of 4, and print: the grid's shape, the row sums, then the column sums. Say each shape out loud first — one of these comes back with three numbers and one with four.

(3, 4) [10 26 42] [15 18 21 24]
Show solution
import numpy as np

grid = np.arange(1, 13).reshape(3, 4)
print(grid.shape)
print(grid.sum(axis=1))    # across each row  → 3 numbers
print(grid.sum(axis=0))    # down each column → 4 numbers

Row 0 is 1+2+3+4 = 10, row 1 is 26, row 2 is 42 — that's axis=1, three results because there are three rows. The column sums come back four-long. If you had them the other way round, re-read the shape test: (3, 4) minus axis 1 is (3,).

B4Stretch — normalise to 0–1

Squashing numbers into the range 0 to 1 is the most common preparation step in all of machine learning, and the formula is one line of what you learned today: (x - x.min()) / (x.max() - x.min()) — subtract the smallest from everything, then divide everything by the span. Print the normalised array rounded to two decimals with np.round(norm, 2), then confirm the smallest is 0 and the largest is 1.

[0. 0.25 0.5 0.75 1. ] min 0.00, max 1.00
Show solution
import numpy as np

x = np.array([10, 20, 30, 40, 50])
norm = (x - x.min()) / (x.max() - x.min())
print(np.round(norm, 2))
print(f"min {norm.min():.2f}, max {norm.max():.2f}")

Two vectorised operations and two aggregations, and the smallest value always lands on 0 with the largest on 1 by construction. The ragged spacing in the printed array is NumPy padding each number to a common width — cosmetic, and a good reminder to print scalars with f-strings when you care about exact output. What this normalising is for — why models want their inputs on a common scale — belongs to the Machine Learning stage; today you own the grammar of it.
