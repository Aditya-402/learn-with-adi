5.1

One box, many slots — your first list

Read · ~3 minPractice · ~10 min

Let's try to understand why one box per thing stops working.

Somebody sends you to the shop. Milk, eggs, bread, tea, sugar. Five separate slips of paper? Of course not. One slip, five lines.

But so far we have been writing item1, item2, item3 — one box each. Add one item and you must edit the program.

That does not scale, right? A week needs seven boxes. A class of marks needs sixty.

So keep the shopping slip in your mind. It is one thing, with many lines inside it.

Python gives you exactly that: one labelled box with a row of numbered slots. Think of railway station lockers — one cupboard, many numbered doors.

That box with numbered slots is what we call a list.

Now the part that trips up everybody. Slot numbers start at zero. The number is not "which one" — it is how far from the front.

Negative numbers count from the other end. fruits[-1] is the last item, however long the list is. No counting on your part.

Ask for a slot that does not exist and Python stops with an IndexError. It almost always means your slot number is off by one.

The form
fruits = ["apple", "banana", "cherry"] fruits[0] # read one slot — counting starts at zero fruits[-1] # the last slot, counting from the back len(fruits) # how many slots are there

Square brackets to build the box. Square brackets again to open one slot.

Reading the slots — line by line, with the slot numbers named
  1. fruits = ["apple", "banana", "cherry"]One box, three slots.
  2. print(len(fruits))len counts the slots — three.
  3. print(fruits[0], fruits[2])The first and the third.
  4. print(fruits[-1])One step from the back.
What you should see3 apple cherry cherry
Fig. 1 — The list box. The slot number is a distance from the front. That is why the first item lives at 0, and why fruits[1] is the second item.
Careful here

The number in the brackets is steps from the front, not 1st, 2nd, 3rd. So fruits[1] is the second item. Everyone gets bitten by this once.

Key idea
A list is one box with numbered slots. The number counts steps from the front — first item [0], last item [-1]. And len() tells you how many slots there are.
Now you run it

A metro line, four stations. Count with len(), front with [0], back with [-1]. Predict all three lines, then run.

5.2

Changing a list — append, insert, remove, pop

Read · ~3 minPractice · ~10 min

Now let's try to understand what happens when the list has to change.

Go back to that shopping slip. You buy the milk, so you strike it off. Somebody calls and says add rice, so you write rice at the bottom. The slip does not become a new slip. It is the same paper, with different lines on it.

A Python list behaves the same way. It carries its own little toolkit, and you reach for a tool with a dot. tasks.append("study") means "tasks, do your append thing".

Four tools cover almost everything you will need today.

tooldoesexample
.append(x)add x in a new slot at the endtasks.append("study")
.insert(i, x)squeeze x in at slot i; everything after shifts righttasks.insert(0, "call home")
.remove(x)delete the first slot holding the value xtasks.remove("study")
.pop(i)take out slot i and hand you the item; .pop() alone takes the lastdone = tasks.pop(0)

Notice the split there. remove works by value — delete the milk, wherever it is sitting. pop works by slot — take out whoever is standing at the front, and hand him to me.

After any removal the slots renumber themselves. There are never gaps.

Changing a box's contents in place like this has a name. We call it mutation.

The form
tasks.append("study") # add one slot at the end tasks.insert(0, "call home") # squeeze in at slot 0 tasks.remove("study") # delete by value done = tasks.pop(0) # take slot 0 out, and keep the item

Read the dot as "do your … thing". The list on the left, the tool on the right.

A morning's to-dos — what the box holds after each line
  1. tasks = ["wash dishes"]One slot to begin with.
  2. tasks.append("study")A new slot at the end.
  3. tasks.insert(0, "call home")Into the front; the rest shift right.
  4. tasks.remove("wash dishes")It goes; the rest close ranks.
  5. print(tasks)Python's own list notation.
What you should see['call home', 'study']
Fig. 2 — What memory holds after each line. append, insert and remove all reached into the same box. Nothing was ever replaced.
Careful here

tasks.append("rest") and tasks = ["rest"] look like cousins. They are opposites. The first reaches into the box you already have and adds one slot. The second builds a brand new one-slot list and stores it into the box. Then Unit 2's rule fires: a box holds one thing, so whatever was there is gone.

One more trap. tasks = tasks.append("rest") leaves tasks holding None. Append changes the box and hands back nothing. So never store its answer.

Now you run it

A party guest list. Alan says yes, Edsger must be seated second, then Ada leaves early. Add at the end is append, add at a slot is insert, take out and keep is pop. Predict each printed list before you Run.

5.3

Slices & membership — chunks and questions

Read · ~2 minPractice · ~8 min

Sometimes you do not want one slot. You want a chunk of them.

Think of a row of seats in a cinema. Your friends are in seats two, three and four. You do not point at each seat separately, right? You say "that row, from here to here". Python has the same move.

days[1:3] means: start at slot 1, and stop before slot 3. Leave one side blank and Python fills it in for you. days[:2] is from the very front. days[2:] is to the very end.

And what you get back is a new list. The original box is untouched. That is what makes this a safe thing to do.

A chunk of a list, taken like this, is what we call a slice.

The second tool today is not a chunk at all. It is a question. "Wed" in days asks whether any slot holds that value, and answers True or False. Those are Unit 3's booleans, so the answer drops straight into an if. not in asks the opposite.

A small bonus. Both tricks work on strings too. "Python"[0:2] is "Py", and "y" in "Python" is True.

The form
days[1:3] # slots 1 and 2 — start in, end out days[:2] # from the very front days[2:] # to the very end "Wed" in days # a question — True or False

A colon inside the brackets means a range, not one slot.

Carving up the week
  1. days = ["Mon", "Tue", "Wed", "Thu", "Fri"]Five slots, 0 to 4.
  2. print(days[1:3])Slots 1 and 2 only.
  3. print(days[:2])From the front, stopping before 2.
  4. print(days[2:])Slot 2 onward; together, the week.
  5. print("Wed" in days)Is "Wed" in any slot? Yes.
What you should see['Tue', 'Wed'] ['Mon', 'Tue'] ['Wed', 'Thu', 'Fri'] True
Careful here

Start included, end excluded. So days[1:3] gives you two items, not three. It feels stingy until you see the gift. The count is always end minus start. And days[:k] with days[k:] joins straight back into the whole list, with nothing doubled.

Now you run it

A race has finished. Print the podium, then the rest of the field, then answer two "did they even run?" questions. First three is [:3], the rest is [3:], and the questions are in.

5.4

Loops meet lists — the payoff

Read · ~2 minPractice · ~10 min

Now Unit 4's loop finally gets something worth looping over.

Let us be honest about last unit. The loops you wrote there counted numbers, and counting numbers is not very thrilling. But the things actually worth repeating over are nearly always sitting in a list. Every task on the slip. Every price on the bill. Every mark in the class.

And for can walk a list straight away. No slot numbers at all.

Each pass, Python refills the loop box — here price — with the next slot's contents, front to back. Then it runs the indented body once. When the slots finish, the loop stops. You cannot fall off the end, because you never touched a slot number.

One small habit. Name the loop box after one of the things: price, task, mark. Then the line reads like plain English.

Bolt this onto Unit 4's accumulator and averages fall out. A running-total box, add each item, divide by len() at the end.

Now a small confession. Python ships sum(prices) ready-made, so the average is only sum(prices) / len(prices). I made you build it by hand first on purpose. A built-in means much more once you know what it is quietly doing.

The form
for price in prices: print(price)

Read it as: for each thing in that box, do this. The loop box takes one slot's contents at a time.

A loop over a list — three slots, three passes
  1. prices = [40, 25, 30]Three slots in one box.
  2. for price in prices:price takes each slot in turn.
  3. print("Rs", price)Indented — once per slot.
What you should seeRs 40 Rs 25 Rs 30
Trace it by hand — the accumulator walking a list
prices = [40, 25, 30] total = 0 for p in prices: total = total + p print("Total:", total)

Before the loop: total holds 0.

Pass 1: p holds 40, so total becomes 40.

Pass 2: p is refilled with 25, so total becomes 65.

Pass 3: p is refilled with 30, so total becomes 95.

After the loop: the slots are finished, and the print runs once.

Total: 95
Key idea
for item in my_list: hands you each slot's contents in order, with no slot numbers needed. Pair it with an accumulator for totals, or with an if for counting matches. Then let sum() and len() handle the routine cases.
Now you run it

From a list of marks, print the class average and how many scored 80 or above. The average is the sum over len one-liner. The count is Unit 3's if sitting inside the loop, ticking a counter only when the test passes. Five marks — predict both numbers first.
