5.1

One box, many slots — your first list

Read · ~4 minPractice · ~10 min

The problem. Every box so far holds exactly one thing. Now try a shopping list: milk, eggs, bread, tea, sugar. Five boxes — item1, item2, item3… — five prints, and "add one more item" means editing the program itself. Boxes don't scale. A week needs seven, a class of marks needs sixty.

The idea, in plain words. A list is one labeled box divided into numbered slots. Write the values between square brackets, commas between:

fruits = ["apple", "banana", "cherry"]

One label, any number of values — and three moves to start with:

  • len(fruits) counts the slots — here, 3. (Yes, the same len() works on strings; it counts whatever the thing is made of.)
  • fruits[0] reads a slot by number — and the numbering starts at zero, because the slot number is really a distance: how many steps from the front. fruits[0] is at the front itself, zero steps in.
  • Negative numbers count from the back: fruits[-1] is the last item, fruits[-2] second-to-last — no len() gymnastics needed.

Ask for a slot that doesn't exist — fruits[3], when the slots are 0, 1 and 2 — and Python stops with IndexError: list index out of range. Same drill as Unit 1: read the error report's last line first; an IndexError almost always means your slot arithmetic is off by one.

Trace it by hand — reading the slots
fruits = ["apple", "banana", "cherry"] print(len(fruits)) print(fruits[0], fruits[2]) print(fruits[-1])

Line 1: one box fruits, three slots: slot 0 holds "apple", slot 1 "banana", slot 2 "cherry".

Line 2: len(fruits) counts slots → 3.

Line 3: slot 0 and slot 2, comma-printed with the usual single space.

Line 4: -1 steps in from the back → the last slot.

3 apple cherry cherry
Fig. 1 — The list box. The slot number is a distance from the front, which is why the first item lives at 0 — and why fruits[1] is the second item, not the first.
Common confusion

The number in the brackets is not "1st, 2nd, 3rd". It's steps from the front — so fruits[1] is one step in: the second item. Every programmer alive was bitten by this exactly once; make your bite a small one. When a program grabs the wrong item — or dies with an IndexError — check the slot number first and count from zero on your fingers.

Key idea
A list is one box with numbered slots. The number counts steps from the front — first item [0], last item [-1] — and len() tells you how many slots there are.
Worked example

Task: a metro line has four stations in a list — report how many stops there are, the terminus at each end. Thinking: count with len(), front with [0], back with [-1] — no need to know the list is four long. Predict all three lines, then run.

5.2

Changing a list — append, insert, remove, pop

Read · ~4 minPractice · ~10 min

The problem. A real list never sits still. You buy the milk and cross it off; a new task lands on top of the day. If lists were frozen at birth you'd have to rebuild the whole box for every change. They aren't — lists come with handles for changing the contents in place.

The idea, in plain words. A list carries its own toolkit, reached with a dot: tasks.append(…) means "tasks, do your append thing". Four tools cover almost everything:

tooldoesexample
.append(x)add x in a new slot at the endtasks.append("study")
.insert(i, x)squeeze x in at slot i; everything after shifts righttasks.insert(0, "call home")
.remove(x)delete the first slot holding the value xtasks.remove("study")
.pop(i)take out slot i and hand you the item; .pop() alone takes the lastdone = tasks.pop(0)

Note the split: remove works by value ("delete the milk, wherever it is"), pop works by slot ("take out whatever is at the front — and give it to me"). After any removal, the slots renumber so there are never gaps.

Trace it by hand — a morning's to-dos
tasks = ["wash dishes"] tasks.append("study") tasks.insert(0, "call home") tasks.remove("wash dishes") print(tasks)

Line 1: one slot: ["wash dishes"].

Line 2: new slot at the end: ["wash dishes", "study"].

Line 3: squeezed in at slot 0, everything shifts right: ["call home", "wash dishes", "study"].

Line 4: the slot holding "wash dishes" is deleted; the rest close ranks: ["call home", "study"].

Line 5: printing a whole list shows Python's own notation — brackets, quotes, commas:

['call home', 'study']
Fig. 2 — The state of memory across the trace. append, insert and remove all reached into the same box; nothing was reassigned.
Common confusion

tasks.append("rest") and tasks = ["rest"] look like cousins and are opposites. The first reaches into the existing box and adds a slot — same box, changed contents (that's mutation). The second builds a brand-new one-slot list and stores it into the box, and Unit 2's rule fires: a box holds one thing, so everything that was there is gone. Related trap: tasks = tasks.append("rest") leaves tasks holding None — append changes the box and hands back nothing, so never store its answer.

Worked example

Task: run a party guest list: Alan RSVPs, Edsger must sit second, then Ada leaves early. Print the list at each stage and see the slots shuffle. Thinking: add-at-end is append, add-at-a-slot is insert, take-from-a-slot-and-keep is pop. Predict each printed list before running.

5.3

Slices & membership — chunks and questions

Read · ~3 minPractice · ~8 min

The problem. Sometimes you don't want one slot — you want a chunk: the top three from a leaderboard, everyone except the first, the weekend from the week. And sometimes you don't want any slot at all, just an answer: is milk already on the list?

The idea, in plain words. A slice reads a range of slots in one go: days[1:3] means "from slot 1 up to but not including slot 3" — start included, end excluded. Leave an end blank and it means "from the very front" or "to the very end": days[:2] is the first two, days[2:] is everything from slot 2 on. A slice hands you a new list — the original is untouched, which makes slicing the safe way to work with part of a list.

The other tool is a question: "Wed" in days asks whether any slot holds that value and answers True or False — the same booleans Unit 3 runs on, so the answer drops straight into an if. not in asks the opposite. (Bonus: both tricks work on strings too — "Python"[0:2] is "Py", and "y" in "Python" is True.)

Trace it by hand — carving the week
days = ["Mon", "Tue", "Wed", "Thu", "Fri"] print(days[1:3]) print(days[:2]) print(days[2:]) print("Wed" in days)

Line 2: slots 1 and 2 — slot 3 is excluded. Two items, not three.

Line 3: from the front up to (not including) slot 2.

Line 4: slot 2 to the end. Notice lines 3 and 4 together rebuild the whole week — the 2 is excluded on one side and included on the other, so nothing is doubled and nothing is lost.

Line 5: is "Wed" in any slot? It is.

['Tue', 'Wed'] ['Mon', 'Tue'] ['Wed', 'Thu', 'Fri'] True
Common confusion

days[1:3] gives two items, not three — the end slot is left out. It feels stingy until you see the gift: the count is always stop − start (3 − 1 = 2), and days[:k] + days[k:] always seams back into the whole list with no overlap. Python chose the convention that makes the arithmetic clean; trust it, and when a slice comes up short by one, look at the end number.

Worked example

Task: from a race's finishing order, print the podium (first three), the rest of the field, and answer two "did they even run?" questions. Thinking: "first three" is [:3], "the rest" is [3:], and the questions are in.

5.4

Loops meet lists — the payoff

Read · ~3 minPractice · ~10 min

The problem. Unit 4's loops counted numbers. But the things worth repeating over are almost always in a list: print every task, add up every price, count every high score. Writing prices[0], prices[1], prices[2] by hand is the five-boxes problem sneaking back in through the window.

The idea, in plain words. for walks a list directly:

for price in prices:
    print(price)

Each pass, Python refills the loop box — here price — with the next slot's contents, front to back, and runs the indented body once per slot. No slot numbers, no len(), no way to fall off the end. Name the loop box after one of the things (price, task, mark) and the code reads like English.

Bolt this onto Unit 4's accumulator pattern and averages fall out: a running-total box, add each item, divide by len() at the end. And once you've built that with your own hands, a confession: Python ships sum(prices) ready-made, so the average is just sum(prices) / len(prices). These notes made you earn it first — built-ins mean more when you know what they're quietly doing.

Trace it by hand — the accumulator walks a list
prices = [40, 25, 30] total = 0 for p in prices: total = total + p print("Total:", total)

Setup: total starts at 0.

Pass 1: p holds 40 → total becomes 40. Pass 2: p refilled with 25 → 65. Pass 3: p refilled with 30 → 95.

After the loop: the list is walked out, and the print runs once:

Total: 95
Key idea
for item in my_list: hands you each slot's contents in order, no indexes needed. Pair it with an accumulator for totals and averages, an if for counting matches — and then let sum(), len() and friends do the routine cases.
Worked example

Task: from a list of marks, print the class average and how many scored 80 or above. Thinking: the average is the sum/len one-liner; the count is Unit 3's if inside the loop, ticking a counter only when the test passes. Predict both numbers first — there are five marks.

5.4 · P1Greet the team

One loop, one print inside it: greet every member on their own line, matching the goal exactly (comma-print does the spacing).

Hello, Ada Hello, Alan Hello, Grace
Show solution
team = ["Ada", "Alan", "Grace"]

    print("Hello,", name)

Three slots, three passes, three greetings. Add a fourth teammate to the list and the loop needs no editing — that's the whole point.

5.4 · P2A week of rain

Total the week's rainfall with the accumulator pattern — by hand, no sum() this once — and report it in one f-string to match the goal.

Total: 15 mm
Show solution
rain = [2, 0, 5, 1, 0, 3, 4]
total = 0
for r in rain:
    total = total + r
print(f"Total: {total} mm")

Start at zero, add every slot, report once after the loop. (Then whisper sum(rain) to yourself and move on.)

5.4 · P3Stretch — numbers for humans

Print the menu numbered from 1 — people don't order "dish zero". Keep a counter box beside the loop: start it at 1, use it in an f-string, raise it each pass. (This exact pattern powers the build below.)

1. dosa 2. idli 3. vada
Show solution
menu = ["dosa", "idli", "vada"]
n = 1
for item in menu:
    print(f"{n}. {item}")
    n = n + 1

Python counts slots from 0; humans count from 1. The counter box translates between the two worlds at the print — the display changes, the list doesn't.

5.5 · P1The to-do list

Follow the numbered comments: read 3 tasks with a for loop (Unit 4's range(3)), appending each; print Your list: then the tasks numbered from 1; ask Which task is done? and remove that task; print Still to do: and the renumbered list. Inputs fixed: three tasks, then the one to cross off.

Add a task: buy milk Add a task: study Python Add a task: call home Your list: 1. buy milk 2. study Python 3. call home Which task is done? study Python Still to do: 1. buy milk 2. call home
Show solution
tasks = []
for i in range(3):
    task = input("Add a task: ")
    tasks.append(task)
print("Your list:")
n = 1
for task in tasks:
    print(f"{n}. {task}")
    n = n + 1
done = input("Which task is done? ")
tasks.remove(done)
print("Still to do:")
n = 1
for task in tasks:
    print(f"{n}. {task}")
    n = n + 1

Ask → append → number → remove → number again. Notice the numbering block appears twice, copy-pasted — feel that itch; Unit 7 exists to scratch it (you'll fold it into a function and call it twice).

5.5 · P2The top scorer

Find the highest score the manual way: a best box starting at the first score, a loop over the list, and an if that promotes any score that beats the current best. Print Top score: and the winner. No shortcuts — build the machine once.

Top score: 92
Show solution
scores = [67, 92, 45, 88, 73]
best = scores[0]
for s in scores:
    if s > best:
        best = s
print("Top score:", best)

The "best-so-far" pattern: seed with the first item, challenge it with every item, keep the winner. And now the confession: max(scores) does exactly this in one call (min() is its twin). You were allowed the shortcut the moment you could build it yourself — that trade is how these notes work.

5.6

Problem bank — everything at once

Practice · ~12 min

The mixed set. Slots, mutation, slices, membership, loops — plus arithmetic from Unit 2 and branching from Unit 3. In order; they get meaner.

B1Backwards

Print the three words in reverse order, one per line. Two honest routes: negative indexes (5.1), or a while loop counting a slot number down from len(words) - 1 (Unit 4). Take either.

three two one
Show solution
words = ["one", "two", "three"]
i = len(words) - 1
while i >= 0:
    print(words[i])
    i = i - 1

Start at the last slot, step down to 0. (For three items, three prints with [-1], [-2], [-3] also pass — and for the curious, Python has a party trick: the slice words[::-1] is the whole list reversed. File it away.)

B2The shopping bill

Total the prices with a loop and an accumulator, and print it with Unit 2's money formatting — two decimals, exactly as the goal shows.

Total: 198.75
Show solution
prices = [45.50, 120.00, 33.25]
total = 0
for p in prices:
    total = total + p
print(f"Total: {total:.2f}")

Accumulator plus :.2f — format at the exit, as always. (sum(prices) earns full marks too.)

B3Is it in stock?

Ask Looking for? and answer with an f-string either way: Yes, <item> is in stock or Sorry, no <item> today. Input fixed to tea — write both branches anyway; shops run out.

Looking for? tea Yes, tea is in stock
Show solution
stock = ["soap", "rice", "tea", "salt"]
item = input("Looking for? ")
if item in stock:
    print(f"Yes, {item} is in stock")
else:
    print(f"Sorry, no {item} today")

Membership feeds the if; the f-string reuses the customer's own word in the reply. Four units in one screenful.

B4Stretch — the great divide

Split the numbers into two new lists — evens and odds — using Unit 2's % to test each one (n % 2 == 0 means even), and print both lists to match the goal. Start-empty-and-append, twice over.

Evens: [2, 4, 10] Odds: [7, 9, 3]
Show solution
nums = [7, 2, 9, 4, 10, 3]
evens = []
odds = []
for n in nums:
    if n % 2 == 0:
        evens.append(n)
    else:
        odds.append(n)
print("Evens:", evens)
print("Odds:", odds)

One pass, two destinations — the loop reads, the if routes, the appends collect. Sorting things into buckets like this is a shape you'll reuse constantly, all the way into the ML stage.
