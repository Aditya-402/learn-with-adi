11.1

import & math — your library card

Read · ~4 minPractice · ~9 min

The problem. You need a square root. You could write the maths yourself — guess, refine, loop — but somebody solved this decades ago, tested it against everything, and shipped it with Python. Where is it, and how do you get at it?

The idea, in plain words. Python comes with a library attached — hundreds of shelves of pre-built tools, called the standard library. Each shelf is a module: a file of functions somebody wrote so you don't have to. The line import math is you flashing your library card at the maths shelf: Python fetches the shelf once and gives you a single new name, math, through which everything on it is reached.

Reached how? With a dot: math.sqrt(16) reads as "from the math shelf, the sqrt tool, applied to 16". Think of the module as one big labeled box that holds other labeled things — the dot opens the box and picks one. A few residents of the maths shelf:

tooldoesexamplegives
math.sqrt(x)square root — always a floatmath.sqrt(16)4.0
math.piπ, ready-made (a value, not a function — no parentheses)math.pi3.141592653589793
math.floor(x)round down to a whole numbermath.floor(4.7)4
math.ceil(x)round up to a whole numbermath.ceil(4.2)5

There is a second form: from math import sqrt pulls one tool off the shelf and lets you write bare sqrt(16). Handy — but in these notes we prefer the dotted form while you're learning: math.sqrt tells every reader exactly which shelf the tool came from, and your own names can never collide with borrowed ones. Use from … import when a name is long and used constantly; you'll see us do exactly that with dates in 11.3.

Trace it by hand — the shelf in action
import math side = math.sqrt(2) print(math.floor(side), math.ceil(side)) print(f"{side:.4f}")

Line 1: the math shelf is fetched; one new box, math, now exists.

Line 2: math.sqrt(2) → 1.4142135623730951 (a float, as always). Stored in side.

Line 3: floor rounds down → 1; ceil rounds up → 2. Comma-print, one space between.

Line 4: Unit 2's formatting, still on duty: four decimal places, rounded.

1 2 1.4142
Fig. 1 — import math doesn't copy code into your file; it fetches the shelf once and hands you one name. The dot in math.sqrt is you reaching into that box for one tool. Every other shelf works the same way.
Common confusion

After import math, writing bare sqrt(16) dies with NameError: name 'sqrt' is not defined. The import gave you one name — math — not a bag of loose tools. Either keep the dot (math.sqrt) or import the tool itself (from math import sqrt). Mixing the two habits is the classic slip.

Key idea
Imports go once, at the top of the file. From then on module.name reaches any tool on that shelf — and the dot tells every reader exactly where the tool came from.
Worked example

Task: a square plot of land covers 240 square metres — how long is each side, and between which two whole-metre lengths does it fall? Thinking: side = √240, which is math.sqrt; the whole-metre brackets are floor and ceil; :.2f keeps the display civilised. Run and study.

Import math, then print the square root of 144 and π shown to two decimals — two f-string prints, matching the goal exactly.

11.2

random — dice, draws & the replay switch

Read · ~4 minPractice · ~8 min

The problem. Everything you've built so far is a machine on rails: same inputs, same output, every single run. But games need dice, quizzes need surprise questions, and — flag planted in the prereq card — machine learning needs shuffled data. How does a rail-riding machine produce surprise?

The idea, in plain words. The random shelf. Three tools cover most of daily life:

  • random.randint(a, b) — a whole number between a and b, both ends included. A die is random.randint(1, 6) — and yes, it can roll a 6.
  • random.choice(some_list) — one item picked from a list (Unit 5's lists, new party trick).
  • random.shuffle(some_list) — rearranges the list in place, like riffling a deck. It returns nothing; the list itself changes.

Now the honest part. The computer can't truly roll dice — it's a rail-rider to its bones. What random gives you is a mathematical recipe that spits out numbers so thoroughly scrambled they behave random. Each run starts the recipe from a different point (the clock, roughly), which is why every run differs. And that's exactly the lever: random.seed(42) pins the starting point, so the recipe replays the same scrambled sequence every run. Same seed, same "random" numbers, forever.

Why would anyone want predictable randomness? Because repeatable beats surprising whenever you need to check work: testing a game, debugging a simulation — and, one day soon, training a model where you shuffle the data, get 94% accuracy, and need tomorrow's rerun to mean the same thing. Every serious ML experiment sets a seed for exactly this reason. Series 01 readers have seen seed(42) in the wild; this is where it comes from.

Trace it by hand — one possible run
import random print(random.randint(1, 6)) print(random.randint(1, 6))

Line 2: the recipe hands over its next scrambled number, squeezed into 1–6. Say it's a 4. Line 3: the next number from the recipe — say a 1. One possible run:

4 1

Run it again and you'll almost certainly see different numbers — the recipe started somewhere else. Now add random.seed(42) as line 2 and run twice more: identical output both times, whatever the numbers turn out to be. The seed is a replay switch, not a number-chooser.

Fig. 2 — The seed doesn't choose nicer numbers; it pins where the scrambling recipe starts, so every run replays the same stream. Repeatable "randomness" is what makes experiments — games today, ML models later — checkable.
Common confusion

random.randint(1, 6) includes both ends — it can return 6. But Unit 4's range(1, 6) stops at 5. Python's two famous "between" tools disagree about the right-hand end, and every programmer has been bitten once. Dice: randint(1, 6). Six loop turns: range(6).

Worked example

Task: a lunch spinner — pick today's lunch from a list, roll a die for who pays. Thinking: choice for the pick, randint for the die. No seed, so it's a genuine surprise: run it three or four times and watch both answers change.

11.3

datetime — the calendar shelf

Read · ~4 minPractice · ~9 min

The problem. "How many days until the exam?" You could count on your knuckles past month lengths and a possible leap year — or you could let the shelf that knows every calendar rule since 1582 do it.

The idea, in plain words. The datetime module holds date-and-time machinery; the piece we need today is date. Because datetime.date is a mouthful you'd type forty times, this is the promised moment where from … import earns its keep:

  • from datetime import date — pull the date tool off the shelf, once, at the top.
  • date(2026, 8, 15) — build a date: year, month, day, in that order. It checks you: date(2026, 2, 30) is refused, because February 30th doesn't exist.
  • date.today() — ask the machine's clock for the current date. Different tomorrow, by design.
  • Subtracting two dates gives a gap object; its .days is the whole-day count between them — leap years, month lengths, all handled.

One honesty note about date.today(): any program that uses it prints something different next week. Perfect for real life, useless for a checked exercise — so in this unit, today() problems are run-only, and every checked answer is built from fixed dates. (Sound familiar? It's the seed idea again, worn by a calendar.)

Trace it by hand — days to New Year
from datetime import date newyear = date(2027, 1, 1) today = date(2026, 8, 15) gap = newyear - today print(f"{gap.days} days to New Year")

Lines 3–4: two date boxes — no clock involved, both fixed.

Line 5: date minus date → a gap (a timedelta, to give it its docs name) stored in gap. It knows August has 31 days and 2026 isn't a leap year, so nothing for you to knuckle-count.

Line 6: .days reads the whole-day count out of the gap — an int, f-string-ready:

139 days to New Year
Common confusion

print(newyear - today) does not print 139 — it prints 139 days, 0:00:00, the gap object's long-winded self-description. The number you want lives inside it: (newyear - today).days. Subtracting dates gives a gap, and .days is how you read it.

Worked example

Task: a live countdown — how many days from actual today until next New Year. Thinking: date.today() supplies the moving part, the subtraction does the maths. Run-only, proudly: it will answer differently next week, and that's the point.

11.3 · P1Days left in the year

Fixed dates only: from date(2026, 8, 15) to New Year's Eve, date(2026, 12, 31) — subtract, read .days, print the goal exactly.

Days left in 2026: 138
Show solution
from datetime import date

today = date(2026, 8, 15)
last_day = date(2026, 12, 31)
gap = last_day - today
print(f"Days left in 2026: {gap.days}")

16 left in August, then 30 + 31 + 30 + 31 — the module counted so you didn't have to. Note .days, not the bare gap.

11.3 · P2New Year to Independence Day

How many days from date(2026, 1, 1) to date(2026, 8, 15)? Build both dates, subtract, and print the goal exactly — mind the word days at the end of the sentence.

From New Year to Independence Day: 226 days
Show solution
from datetime import date

newyear = date(2026, 1, 1)
iday = date(2026, 8, 15)
gap = iday - newyear
print(f"From New Year to Independence Day: {gap.days} days")

Aug 15 is day 227 of the year, and 227 − 1 = 226 days between them. Fence-posts: the gap counts steps, not dates touched.

11.3 · P3Stretch — Python's age in days

Python was first released on 20 February 1991. Using the fixed "today" of date(2026, 8, 15), print how many days old Python is — one subtraction across 35 years and nine leap days, done in a blink.

Python is 12960 days old
Show solution
from datetime import date

born = date(1991, 2, 20)
today = date(2026, 8, 15)
age = today - born
print(f"Python is {age.days} days old")

Every leap year from 1992 to 2024 is silently accounted for. This is the standard library's whole pitch: decades of edge cases, pre-handled.

11.4

Reading the library — docs, help() & the pip shelf

Read · ~4 minPractice · ~6 min

The problem. Three shelves down, hundreds to go — and no set of notes can walk you through them all. The skill that actually scales isn't memorising tools; it's reading the catalogue. What does a documentation page say, and how do you decode it?

The idea, in plain words. Every entry in Python's docs has the same three-part shape. Here is a real one, from the random page:

random.randint(a, b)

Return a random integer N such that a <= N <= b.

The shape of every docs entry: a signature (the tool's name and the blanks you fill — a and b are placeholders, not magic words), a one-line description (note it settles our inclusive-ends question in nine words), and usually an example below. Read signature → description → example, in that order, and any entry opens up.

You can also interrogate a shelf without leaving your code. dir(math) lists every name on the shelf — a table of contents. help(math.sqrt) prints that tool's docs entry right into the output. Between the two, you can explore a module you've never seen, which is precisely how programmers meet new shelves.

And the shelves beyond — pip, in one paragraph
The standard library ships with Python; but there's a bigger building next door: hundreds of thousands of shared libraries written by everyone — the tools behind data science and ML included. pip is the installer that fetches one onto your machine (pip install requests, typed in a terminal, not in Python), after which you import it like any shelf. It can't run inside this page — but it works in Colab and on your own machine, and the local-setup appendix walks you through it when the time comes. For now: standard library = included; pip = the shelf of everyone's libraries.
Worked example

Task: explore the math shelf without opening a browser. Thinking: dir for the table of contents, help for one entry. The output is long — that's what real exploring looks like. Skim it, spot factorial in the list; you'll use it in P1.

11.5

Your build — the dice duel

Read · ~2 minPractice · ~10 min

Everything from this session in one small arcade: two players roll dice, a winner is declared, a lucky draw picks a prize-winner — and because the first two are checked, they run on the replay switch. Stage 3 pulls the seed out and lets the dice be dice.

11.5 · P1Stage 1 — the duel, seeded

Seed with 42, then roll two dice for Player 1 and two for Player 2 (randint(1, 6), four calls, in that order). Report each player's rolls and total with f-strings, then declare the result with if/elif/else: Player 1 wins!, Player 2 wins! or It's a tie!. The seed makes your output checkable — that's it doing its job.

Player 1 rolls 6 and 1 (total 7) Player 2 rolls 1 and 6 (total 7) It's a tie!
Show solution
import random

random.seed(42)
p1a = random.randint(1, 6)
p1b = random.randint(1, 6)
p2a = random.randint(1, 6)
p2b = random.randint(1, 6)
p1 = p1a + p1b
p2 = p2a + p2b
print(f"Player 1 rolls {p1a} and {p1b} (total {p1})")
print(f"Player 2 rolls {p2a} and {p2b} (total {p2})")
if p1 > p2:
    print("Player 1 wins!")
elif p2 > p1:
    print("Player 2 wins!")
else:
    print("It's a tie!")

Four seeded rolls always land the same way, so the duel replays identically every run — which is exactly why the checker can mark it. Order matters: the seed pins the stream, and each randint takes the next number from it.

11.5 · P2Stage 2 — the lucky draw

Fresh seed of 42 (seed again — it restarts the stream), then random.choice from the six names in the starter list, and announce the winner exactly as the goal shows.

The lucky winner is Farhan!
Show solution
import random

random.seed(42)
names = ["Adi", "Bela", "Chitra", "Dev", "Esha", "Farhan"]
winner = random.choice(names)
print(f"The lucky winner is {winner}!")

Same seed, same pick, every run. Re-seeding rewinds the tape to the start — without line 3, the choice would continue the stream from wherever the last random call left it.

11.5 · P3Stage 3 — dice set free

The same duel with the seed deleted. Run it five times; feel how the game only became a game once the replay switch came out. No check — chance doesn't sit exams.

B3The seeded shuffle

Seed with 42, shuffle the four names, print the list itself (yes, with its brackets and quotes — that's what printing a list looks like, from Unit 5). The seed makes even a shuffle checkable.

['Chitra', 'Bela', 'Dev', 'Adi']
Show solution
import random

random.seed(42)
order = ["Adi", "Bela", "Chitra", "Dev"]
random.shuffle(order)
print(order)

Shuffle in place, then print the list — remember shuffle returns nothing, so it can't live inside the print. Seeded, the "random" order is the same every run: reproducibility again, now rearranging lists.

B4Stretch — password of the day

Build an 8-character password by looping 8 times (Unit 4) and gluing on one random.choice from the letters-and-digits string (Unit 8 — a string is a sequence, so choice happily picks from it). Keep the seed line and the same password comes back every run — swap the seed for a new day, new password. Run-only: try a few seeds.

Show solution
import random

random.seed(42)
letters = "abcdefghijklmnopqrstuvwxyz0123456789"
password = ""
for i in range(8):
    password = password + random.choice(letters)
print(f"Password of the day: {password}")

Four units shake hands: a loop builds up a string one random pick at a time, and the seed turns "random" into "same for everyone with the same seed" — which is why it's a password of the day, not of the moment.
