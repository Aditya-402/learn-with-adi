8.1

Strings are sequences — you already know this

Read · ~3 minPractice · ~10 min

The problem. Your programs have treated text as a sealed parcel — store it, print it, glue it. But real work happens inside the text: the first letter of a name, the last three characters of a filename, whether a word hides in a sentence. How do you get in?

The idea, in plain words. You've been in all along. A string is a sequence — a list of characters wearing one coat — and every tool from Unit 5 works on it without modification:

  • word[0] is the first character, word[-1] the last — same counting-from-zero, same negative shortcut.
  • word[1:4] slices out characters 1, 2 and 3 — start included, stop excluded, exactly like list slices.
  • len(word) counts characters; for ch in word: visits them one at a time; "go" in word asks whether that piece of text appears anywhere inside.

One rule is new, and it matters: a string is immutable — frozen at birth. You can read any character, but you cannot overwrite one. To "change" a string, you build a new one and store it (often back in the same box). The practice below makes you feel this.

Trace it by hand — list tools, on text
word = "mango" print(word[0], word[-1]) print(word[1:4]) print(len(word)) print("go" in word)

Line 2: character 0 is m; character -1 (last) is o. Comma-print puts one space between.

Line 3: slice from 1 up to (not including) 4 → characters 1, 2, 3 → ang.

Line 4: five characters. Line 5: does "go" appear inside "mango"? Yes — mango → True.

m o ang 5 True
Fig. 1 — Unit 5's row of boxes, back again. Positive indices count from the front, negative from the back; every slicing rule carries over character for character.
Common confusion

If strings behave like lists, surely s[0] = "X" works? It does not — it dies with TypeError: 'str' object does not support item assignment. Lists can be edited in place; strings can't. The characters are read-only. To change one, build a new string from pieces — "X" + s[1:] — and store it. This isn't Python being difficult; frozen strings are what make them safe to use as dictionary keys and cheap to share.

Worked example

Task: interrogate a filename with nothing but Unit 5 tools: how long is it, what's its first character, what are its last three, and is there a dot in it? Thinking: four questions, four tools you already own — just aimed at text. Predict all four outputs, then run.

8.2

The everyday methods — clean, change case, check ends

Read · ~4 minPractice · ~8 min

The problem. Real text arrives messy. Users type "yes " with a stray space and your == check fails for a reason you cannot see. Names arrive in random capitalisation. Filenames need checking. Editing all this by slicing alone would be miserable.

The idea, in plain words. Every string carries a toolkit of methods — small built-in machines you call with a dot: word.upper(). Think of Unit 7's functions, pre-packaged and bolted onto every string. The everyday six:

methoddoesexamplegives
.upper() / .lower()change case"adi".upper()"ADI"
.title()Capitalise Each Word"ada lovelace".title()"Ada Lovelace"
.strip()trim whitespace at both ends" hi ".strip()"hi"
.replace(a, b)swap every a for b"co-op".replace("-", "")"coop"
.startswith(x) / .endswith(x)check the ends"file.png".endswith(".png")True

And the rule that unifies them, straight from 8.1: strings are frozen, so no method ever edits the string — every method hands back a new one. name.upper() on its own line changes nothing; you must catch the result: shout = name.upper(), or store it back over the old box.

Trace it by hand — methods return, they don't edit
name = "adi" shout = name.upper() print(shout) print(name)

Line 2: .upper() reads the frozen "adi", manufactures a brand-new "ADI", and hands it over. The new string lands in shout; the original sits untouched in name.

Lines 3–4: two boxes, two different strings:

ADI adi
Common confusion

Writing msg.replace("a", "b") on its own line and wondering why msg didn't change is the classic string bug. The method did its work — then the new string evaporated, uncaught. Frozen strings can't be edited in place, so the fix is always the same: catch the result — msg = msg.replace("a", "b"). If a string method "didn't work", you almost certainly dropped its return value.

Worked example

Task: the invisible-spaces bug, live. The visitor typed yes — or so they believe; their finger caught the space bar on the way out. Watch the honest == check fail, then watch .strip() rescue it. The input here is fixed to yes  (with a trailing space).

The first check says False and len rats out the stowaway: 4 characters, not 3. Rule of thumb from today onward: strip anything a human typed before comparing it.

8.3

Split, join & search — between text and lists

Read · ~3 minPractice · ~10 min

The problem. A sentence is one string, but you want its words. A line from a spreadsheet — "Ada,36,London" — is one string, but you want its three fields. Slicing by hand would mean counting commas like an accountant.

The idea, in plain words. Two methods form a revolving door between text and Unit 5's lists:

  • .split() — string in, list out. "a big cat".split() → ['a', 'big', 'cat']. With no argument it splits on any run of whitespace; give it a separator — line.split(",") — and it cuts at every comma instead.
  • .join() — list in, string out. The glue goes first: " ".join(words) reassembles with spaces, "-".join(words) with dashes. Split then join, and you've laundered a string through list-land and back.

For finding things within a string, two more: .count(x) says how many times x appears, and .find(x) says the index where it first starts — or -1, its polite way of saying "not there". (find is in's chattier sibling: in says whether, find says where.)

Trace it by hand — the revolving door
line = "Ada,36,London" parts = line.split(",") print(parts) print(parts[0]) back = "-".join(parts) print(back)

Line 2: cut at every comma → a real Unit 5 list of three strings: ['Ada', '36', 'London']. Note '36' is text — split never converts; that's still int()'s job, at the door.

Line 4: lists index as always. Line 5: glue the pieces back with dashes:

['Ada', '36', 'London'] Ada Ada-36-London
Key idea
.split() turns a string into a list; "glue".join() turns it back. That round trip — plus "name,age,city".split(",") — is the exact move that reads spreadsheet-style data files, which is where this series is headed.
Common confusion

.split() and .split(" ") are not the same machine. Bare .split() treats any run of whitespace as one cut and ignores the ends — " a b ".split() → ['a', 'b'], clean. .split(" ") cuts at every single space and keeps the empty scraps between them. For human-typed text, use the bare version; save .split(",") and friends for data with a deliberate separator.

Worked example

Task: one line of spreadsheet-style data — name, age, city, comma-separated. Pull it apart, use the fields, and re-export it with a different separator. Thinking: split on the comma, index the list, join with what the other program expects. This is data wrangling in miniature.

8.4

Formatting, the deep dive — columns that line up

Read · ~4 minPractice · ~8 min

The problem. Unit 2's :.2f made single numbers presentable. But print a receipt — names on the left, prices on the right — and everything staggers, because Tea and Samosa are different lengths. Real programs print tables. How do you make columns?

The idea, in plain words. The f-string braces accept a width. {name:<10} means "write name in a lane exactly 10 characters wide, pushed left (<), padding the rest with spaces". {price:>7.2f} means "a lane 7 wide, pushed right (>), two decimals". Same-width lanes on every row ⇒ columns that line up, whatever the contents. (Format at the exit, as always — the boxes keep their real values.)

Second tool: \n inside any string is not two characters on screen — it's an instruction meaning "start a new line here". print("To do:\n- milk") prints two lines with one call. You've seen \n in this series' checked goals all along; now it's yours to write.

Trace it by hand — one receipt row
print(f"{'Tea':<10}{12.5:>7.2f}")

Lane 1: 'Tea' is 3 characters; the lane is 10 wide, pushed left → Tea + 7 spaces.

Lane 2: 12.5 becomes 12.50 (5 characters); the lane is 7 wide, pushed right → 2 spaces + 12.50.

Glued together — 17 characters exactly (dots shown for the spaces you can't see):

Tea······· ··12.50
Tea 12.50
Fig. 2 — Widths make lanes; < and > choose which wall the contents hug. Numbers hug the right so their digits align; names hug the left so your eye can scan them.
Worked example

Task: a canteen receipt — header, three items, a rule, a total — with the price column aligned to the paisa. Thinking: every line uses the same two lanes: :<10 for the name, :>7.2f for the amount (the header uses :>7 since "Price" isn't a number). The divider is Unit 2's old friend, string repetition: "-" * 17.

8.5 · P2The signup gatekeeper

Rules: a username needs at least 4 characters and no spaces; a password needs at least 8 characters and at least one digit. The username checks are written for you. Add the password checks — for the digit, loop over the password with a found_digit flag that starts False and flips True if any character is in "0123456789". Inputs fixed: meetu, learn2code.

Username? meetu Password? learn2code Username OK Password OK
Show solution
username = input("Username? ")
password = input("Password? ")

if len(username) < 4:
    print("Username too short")
elif " " in username:
    print("Username cannot contain spaces")
else:
    print("Username OK")

found_digit = False
for ch in password:
    if ch in "0123456789":
        found_digit = True

if len(password) < 8:
    print("Password too short")
elif not found_digit:
    print("Password needs a digit")
else:
    print("Password OK")

The flag pattern from Unit 4, hunting through a string: assume False, sweep every character, flip on evidence. Once it clicks, wrap each rule-set in a Unit 7 function — check_username(u) returning the message — and this becomes reusable in any program.

8.5 · P3Stretch — the shift cipher

Slide every letter one step along the alphabet: a→b, b→c … and z wraps to a. For each character, alphabet.find(ch) gives its position; add 1; and % 26 — Unit 2's remainder, in its natural habitat — wraps 26 back to 0. Build the secret string character by character (8.1's new-string pattern) and print it.

afcsb
Show solution
alphabet = "abcdefghijklmnopqrstuvwxyz"
word = "zebra"
secret = ""
for ch in word:
    spot = alphabet.find(ch)
    secret = secret + alphabet[(spot + 1) % 26]
print(secret)

z is position 25; 25 + 1 = 26; 26 % 26 = 0 → a. The remainder operator turns the alphabet into a circle — z→a, e→f, b→c, r→s, a→b, and "zebra" whispers "afcsb". Julius Caesar encrypted army orders with exactly this (shift 3); you've just built a two-thousand-year-old cipher in six lines.

Problem bank — everything at once

Practice · ~12 min

The mixed set. Indexing, slicing, methods, split/join, and one delightful trick you haven't met yet. In order; they get meaner.

B2The word counter

Print how many words the sentence has, in the exact format shown. One line of counting logic — you built the pieces in 8.3.

Words: 9
Show solution
sentence = "the quick brown fox jumps over the lazy dog"
print("Words:", len(sentence.split()))

Split to a list, len the list — the counting you once did with a loop-and-counter, now in one honest line.

B3Palindrome patrol

A treat first: the slice word[::-1] — both positions blank, step -1 — walks the whole string backwards, giving the reversed copy in one stroke. Use it to check each word in the list: if a word equals its own reverse, it's a palindrome. Match the goal.

level is a palindrome python is not a palindrome madam is a palindrome
Show solution
words = ["level", "python", "madam"]
for word in words:
    if word == word[::-1]:
        print(word, "is a palindrome")
    else:
        print(word, "is not a palindrome")

"level"[::-1] → "level" — equal, palindrome. "python"[::-1] → "nohtyp" — not. The reversal slice works on lists too; file it among your favourite tricks.

B4Stretch — the text launderer

This string arrived from a form in a shocking state: stray spaces at both ends, a triple space in the middle, chaotic capitals. Clean it to the goal. Hint: bare .split() eats all the whitespace mess (ends included), " ".join() rebuilds cleanly, and .title() fixes the case — one pipeline.

Hello World
Show solution
messy = "  hello   wORLD  "
clean = " ".join(messy.split()).title()
print(clean)

Split shreds away every whitespace sin, join rebuilds with single spaces, title straightens the capitals (it lowercases the rest of each word too — wORLD → World). Chained methods read left to right: shred, rebuild, dress up. A messy.strip().title() would fix the ends and case but leave the triple space — the split/join pipeline is the full launder.
