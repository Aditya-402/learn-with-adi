1.1

What is a program?

Read · ~2 minPractice · ~8 min

Let's try to understand what a program really is.

You have made tea, or at least watched someone make it, right? Now suppose you write the steps down for a friend who has never entered a kitchen. You write "add sugar to taste". He stops there. Whose taste? How much?

A computer is that friend. Very fast, never tired, zero imagination. It does exactly what you write — nothing more, nothing less.

So the job is easy to say and takes practice to learn: write every step, in order, leaving no gap.

That written-down list of steps is what we call a program. Each line in it is an instruction.

We write ours in Python. It reads almost like English, and it is the language most of the machine-learning world runs on. That is why our journey starts here.

The form
print("anything you want on the screen")

print has nothing to do with paper. It means: show this on the screen.

Your first program — one line, read it with me
  1. print("Hello, world")print — show something. The brackets hold what to show. The quotes hold the exact words.
What you should seeHello, world

One instruction in, one action out. Every program you will ever write is just more of these, one after another.

Fig. 1 — You write the steps, Python follows them to the letter, the screen shows the result. Nowhere in this picture does the machine guess.
Now you run it

Press ▶ Run and watch the panel answer. Then change the words inside the quotes and run it again. It obeys you now.

1.2

Why the quotes?

Read · ~2 minPractice · ~10 min

You have been typing quotes without asking why. Let's try to understand.

Suppose I tell you: say your name. You say "Aditya". Now I tell you: say "your name". You say the words your name.

Same three words. The quotes changed the meaning completely, right?

Python works the same way:

  • With quotes — repeat these characters exactly.
  • Without quotes — this is a name, I should already know it.

So print(Hello) fails. Python looks for something called Hello and finds nothing.

Numbers are different. print(2026) is fine, because digits can never be mistaken for a name.

And a comma lets you print several things together. Python puts one space at each comma.

Text inside quotes has a name. We call it a string — a string of characters, like beads on a thread.

The form
print("some text") # repeated exactly print(25) # a number, no quotes print("Age:", 25) # two things, one space between
Three lines, three different behaviours
  1. print("2 + 3")Quoted, so it is repeated as it is. No arithmetic happens.
  2. print(2 + 3)No quotes, so Python works it out first, then shows the answer.
  3. print("Result:", 2 + 3)Both together. The comma puts one space between them.
What you should see2 + 3 5 Result: 5
Careful here

print("7") and print(7) look the same on screen. They are not the same thing. One is the character 7, the other is the number 7. In Unit 2, when we start doing arithmetic, this difference will matter a lot.

Watch one first

Print I am 10 years old, keeping 10 as a real number. Two pieces of text, one number, joined by commas.

1.3

Errors are messages, not scoldings

Read · ~2 minPractice · ~8 min

Some time in the next ten minutes you will type something Python cannot follow. Everybody does. So let's understand what actually happens.

Go back to our friend in the kitchen. He does not throw the vessel and walk out. He stops and says: I am stuck at this step, and this is what I could not do.

Python does exactly that. The red text is not scolding you. It is the machine telling you where it stopped and why.

Now one habit, and please make it a habit from today: read the last line first. The last line tells you what kind of problem it is. The lines above it only tell you where.

Two kinds will meet you today:

  • Punctuation broken — a missing quote or bracket — so Python could not even read the line. We call that a SyntaxError.
  • A name it does not know — a misspelt instruction, or text without quotes. Python read the line fine. We call that a NameError.
One broken line, and what Python says back
  1. print("Bye)A quote opens, and the line ends before another quote closes it. Python cannot finish reading it.
What you should see print("Bye) ^ SyntaxError: unterminated string literal

Read it from the bottom. SyntaxError — could not read the line. unterminated string — a quote opened and never closed. The little ^ points near the trouble. Now the fix is obvious: close the quote.

Careful here

An error does not mean the computer is damaged, or your earlier work is lost, or that you are bad at this. The program simply stopped at the step it could not do. Fix the line, run again. The machine keeps no grudge.

Watch one first

This one is broken. Run it before fixing it — never fix blind. The last line says NameError: name 'prnt' is not defined. Python read the line, but knows nothing called prnt. Spelling. Correct it and run again.

1.4

Making it listen

Read · ~3 minPractice · ~10 min

So far our program only talks. Every run says the same thing. Can it listen? Let's try to understand.

Think of the delivery boy who calls you: "Sir, which floor?" He asks. He waits. He cannot move until you answer. Then he uses your answer.

input() does exactly that. It shows a question, it stops the program, and it hands back whatever was typed.

But hands it back to where? If nobody catches it, it is gone. So we catch it in a labelled box:

Read the = as store into, right to left. Run input(…), take what comes back, put it in a box labelled name. From that line onwards, writing name means the contents of that box.

That labelled box has a name too. We call it a variable. Unit 2 is all about them. Today one box is enough.

One honest note about this page: a real Python program waits for your keyboard. Here, the Program input field below the code plays that part — it holds the answers, in order, so the checks know what to expect.

The form
box_name = input("your question here ")

Mind the space before the closing quote — that is what keeps the typed answer from touching the question mark.

Ask, store, use — the shape of every interactive program
  1. name = input("What is your name? ")Ask, wait, and keep the answer in a box called name. Say the person types Ada.
  2. print("Hello,", name, "— welcome aboard!")Unquoted name, so Python opens the box and puts the contents in.
What you should seeWhat is your name? Ada Hello, Ada — welcome aboard!
Fig. 2 — Ask, store, use. Which boxes exist, and what is inside each one after every line — that picture is the whole of Unit 2.
Now you run it

The Program input field plays your keyboard, and it holds Ada. Run it. Then change that field to your own name and run again — same steps, different conversation.

1.4 · P1The food critic

Ask What is your favourite food? (note the space before the closing quote), keep the answer in a box called food, then reply. The input is fixed to dosa.

What is your favourite food? dosa dosa sounds delicious!
Show solution
food = input("What is your favourite food? ")
print(food, "sounds delicious!")

The box is read back by writing its name without quotes. The comma gives the space before "sounds".

1.4 · P2Two questions, two boxes

Ask for a name, then a city, keep both, and combine them in one greeting using commas. Inputs are fixed to Ada then Chennai.

What is your name? Ada Which city are you from? Chennai Hello, Ada from Chennai
Show solution
name = input("What is your name? ")
city = input("Which city are you from? ")
print("Hello,", name, "from", city)

Two boxes, both read back by name. Wondering why there is no exclamation mark at the end? Try adding , "!" — the comma sneaks a space in before it. Joining text with no gap needs +, and that is Unit 2's business.
