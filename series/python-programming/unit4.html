4.1

while — repeat while it is true

Read · ~2 minPractice · ~10 min

Let's try to understand what a loop really is.

You have cycled somewhere far, right? You never decide beforehand how many times to pedal. You pedal, you look up, and you ask: have I reached? Not yet — so you pedal again. You stop only when the answer changes.

That is a loop. Python says it almost in English: while this is true, do that.

Three parts: a start, a condition, an update.

That update is your payoff. In Unit 2 you wrote count = count + 1 by hand and it felt like nonsense maths. It was never nonsense — it was waiting for today.

The form
while some_condition: do this and change what it reads

Colon and indent, like if. But it comes back and asks again.

Count to three
  1. count = 1The start — before the loop.
  2. while count <= 3:Asked fresh, every pass.
  3. print(count)Indented — part of the loop.
  4. count = count + 1The update — pushes it towards no.
  5. print("Done")Not indented. Runs once, after.

Careful here

A loop that never ends is an infinite loop. Not a disaster — your program is doing exactly what you said, forever. All of us wrote one in our first week. Ctrl+C stops it; here the runner gives up after twelve seconds. So write one on purpose in P3, and the accidental one gets a shrug instead of a panic.

Now you run it

Five hellos, four lines. How many times is the condition asked? One more than the body runs.

4.2

for + range — when you already know the number

Read · ~2 minPractice · ~10 min

Cycling home, you did not know how many pushes it would take. But plenty of jobs come with the number attached. Ten chapatis. Three cheers. Sixty seconds.

For those, a while makes you do clerical work — a start, a condition, an update. Three chances to slip by one.

So Python gives you a loop with the counting already inside. Plainly: a while loop with the counting done for you.

Write for i in range(5): and Python makes the box i, refills it before every pass, and stops when the numbers run out.

range is the number factory. Three sizes:

  • range(5) → 0 1 2 3 4. Starts at 0, and 5 is not there.
  • range(2, 6) → 2 3 4 5. You say where to start.
  • range(1, 10, 2) → 1 3 5 7 9. The third number is the step. Negative counts down.

Know how many times? Use for. Know only when to stop? That is while country.

The form
for box_name in range(5): do this, once per number

No start, no condition, no update — range handles all three.

Three laps
  1. for lap in range(3):The factory makes 0, 1, 2 — one per pass.
  2. print("Lap", lap)Same line every pass. Only lap changes — a real box.
  3. print("Race over")Numbers finished, loop finished.
What you should seeLap 0 Lap 1 Lap 2 Race over
Careful here

range(5) gives five numbers, and 5 is not one of them. Want 1 to 5? That is range(1, 6).

The off-by-one has not gone. It only moved house — out of the condition, into the stop value. Counts from 0, stops one short.

Watch one first

Squares of 1 to 5. We know how many times, so for. We want 1 to 5, so range(1, 6).

4.3

break & continue — leaving early, skipping one

Read · ~2 minPractice · ~10 min

Picture a bank counter. One queue, the clerk serving people one by one — that is your loop.

Now two ordinary things happen. One man's form is incomplete, so the clerk waves him aside and calls the next. And later the clerk finds the file he was hunting for, and simply shuts the counter.

Both are interruptions. They are not the same interruption at all.

  • break — leave the loop, now. The program carries on after it.
  • continue — abandon this pass only. Back to the top, next value.

Both sit inside an if. An unconditional break would fire on the very first pass, right?

And break unlocks while True: — always true, no natural end, built to be left by a break. Think of milk on the stove. You do not count stirs. You watch, and the moment it rises you take it off. That moment lives mid-work, not at the top.

The form
if this is the moment: break # walk out of the loop if this one is to be skipped: continue # skip the rest of this pass
break — the loop is over
  1. for n in range(1, 6):1, 2, 3, 4, 5 — that was the plan.
  2. if n == 4:False three times, then True.
  3. breakThe loop dies here, mid-pass.
  4. print(n)So it runs on the first three passes only.
  5. print("stopped")Outside, so it still runs.
What you should see1 2 3 stopped
continue — one word changed
  1. continueOnly this pass is abandoned. On to 5 as usual.
What you should see1 2 3 5 stopped
Careful here

Two slips. First, break does not end the program. It ends the loop — everything after it still runs.

Second, people swap the two. Keep the counter in your head: break shuts it, continue waves one man aside.

Watch one first

The first number past 100 that divides by 7. We do not know which one — but % tells us the moment we see it.

4.3 · P1First big square

for n in range(1, 20):

        print(n)
        break

49 slips under; 64 opens the door.

4.4

Counters & accumulators — loops that build an answer

Read · ~2 minPractice · ~10 min

So far our loops print and forget. Each pass sees one value and throws it away.

But the real questions have one answer at the end. What is the total of these bills? How many students passed?

So let's try to understand how one answer survives many passes.

Watch the vegetable vendor weigh your bag. Potatoes, forty — he says forty. Tomatoes, thirty — seventy. Onions, twenty-five — ninety-five. Nothing is written down. He carries one running number in his head, and every item goes into it.

That running number is a box that outlives the loop. Make it before, feed it inside, read it after.

Feed it + 1 instead of a value and it becomes a tally. Put that line under an if and you count only the ones that qualify.

We call that box an accumulator — and when it only counts, a counter.

The form
total = 0 # before — the empty jar for x in ...: total = total + x # inside — each pass drops a coin in print(total) # after — the jar holds the answer
Add up 1, 2, 3, 4
  1. total = 0The jar, on the counter before anybody arrives.
  2. for n in range(1, 5):n is 1, then 2, then 3, then 4.
  3. total = total + nRight side first: 1, then 3, then 6, then 10.
  4. print(total)After the loop. One answer, not four.
What you should see10
Careful here

Putting total = 0 inside the loop is the classic slip. Nothing goes red — the program just hands you a wrong answer with a straight face.

The jar is emptied at the top of every pass, so it holds only the last value. If your total equals the final number, move the init line above the loop.

A shorthand you will meet in the wild
total += x means exactly total = total + x. Same for -= and *=. These notes keep the long form, because it shows the machinery.
Watch one first

Four scores. Two jars, both made before the loop. One is fed every pass, the other only when the if agrees.

4.5

Your build — guess my number, v2

Read · ~1 minPractice · ~12 min

Unit 3's game judged one guess and finished. That is not a game — it is a decision in a game's clothes.

Version 2 is the real thing, and it is this whole unit in one program. A while holding the tries, if/elif/else giving hints inside it, and a break at the win.

Then a gentler one, to let for show off.

4.5 · P1The game, complete

Secret is 7, three tries. Ask, convert at the door, count the try, then judge.

Your guess? 3 Too low. Your guess? 9 Too high. Your guess? 7 Got it in 3 tries!
Show solution
secret = 7
tries = 0
while tries < 3:
    guess = int(input("Your guess? "))
    tries = tries + 1
    if guess == secret:
        print(f"Got it in {tries} tries!")
        break
    elif guess < secret:
        print("Too low.")
    else:
        print("Too high.")

Count the try before you judge, or the winning message is short by one.

4.5 · P2The times-table printer

One f-string does a line, for does the rest. Keep the number in a box n.

7 x 1 = 7 7 x 2 = 14 7 x 3 = 21 7 x 4 = 28 7 x 5 = 35 7 x 6 = 42 7 x 7 = 49 7 x 8 = 56 7 x 9 = 63 7 x 10 = 70
Show solution
n = 7
for i in range(1, 11):
    print(f"{n} x {i} = {n * i}")

Now change n to 13 and print a table no schoolbook wall ever carried.

4.6

Problem bank — everything at once

Practice · ~12 min

Nothing new. Both loops, both doors, jars of every kind. In order — they get meaner.

B1The countdown

Either loop works. Pick one, then work out how you would have written the other.

5 4 3 2 1 Liftoff!
Show solution
for n in range(5, 0, -1):
    print(n)
print("Liftoff!")

Liftoff! is un-indented, or the rocket launches five times.

B2The famous sum

Add every number from 1 to 100. Gauss was clever about it; you get to be lazy.

5050
Show solution
total = 0
for n in range(1, 101):
    total = total + n
print(total)

Gauss paired 1+100, 2+99 — fifty pairs of 101. Your loop would do a million just as calmly.

B3The average machine

Keep asking until -1 arrives — a sentinel. Do not count it. Average to two decimals.

Score (-1 to stop)? 40 Score (-1 to stop)? 70 Score (-1 to stop)? 55 Score (-1 to stop)? -1 Average: 55.00
Show solution
total = 0
count = 0
while True:
    score = int(input("Score (-1 to stop)? "))
    if score == -1:
        break
    total = total + score
    count = count + 1
print(f"Average: {total / count:.2f}")

Milk on the stove — the stopping moment appears mid-work, so while True plus break.

B4Stretch — the digit shredder

Add the digits of 4728: % 10 peels off the last digit, // 10 shreds it away.

Digit sum: 21
Show solution
n = 4728
total = 0
while n > 0:
    total = total + n % 10
    n = n // 10
print("Digit sum:", total)

Here the update line is a division. Anything that drives the condition towards False will do.

Before you go to Unit 5

Go and break a loop or two

Take the guessing game from 4.5 and make it yours. Give the player five tries. Make it rude when he guesses too high. Then break it on purpose. Remove the update line and watch it spin. Move total = 0 inside a loop and see the wrong answer arrive with a straight face. Fix them both — you will learn more from those two than from ten copied programs.

Then in Unit 5 we fix the squeeze you must have felt today. A box holds one thing, so fifty scores meant fifty asks and nothing was kept. Unit 5 gives you the list — many values in one labelled box. And the loops you just learned were built for exactly this.

One question before you go. Your loop asked for five scores, one after another. At the end of it, how many of those five were still in memory?
