4.1

while — repeat while true

Read · ~4 minPractice · ~10 min

The problem. Print the numbers 1 to 100. With what you know, that's a hundred print lines — and "keep asking until the guess is right" can't be written at all, because you don't know in advance how many lines it needs. Programs must be able to say keep doing this while something is true.

The idea, in plain words. Tell the literal-minded kitchen helper "wash a dish while the sink has any" and one instruction covers five dishes or fifty. Python's version is while condition: followed by an indented body — the same colon-and-indent rule as if. But where if checks once and moves on, while checks, runs the body, and comes back to check again. Only when the condition turns False does the program step past the loop. Every useful while has three parts:

  • The start — a box created before the loop: count = 1.
  • The condition — a Unit 3 comparison that reads the box: count <= 3.
  • The update line — the line inside the body that changes the box: count = count + 1. This is Unit 2's "nonsense in maths" line, finally at home. Without it, the condition can never change its mind.
Trace it by hand — watch the boxes go round
count = 1 while count <= 3: print(count) count = count + 1 print("Done")

Visit 1: count holds 1 → 1 <= 3 is True → body runs: prints 1, box becomes 2. Back to the top.

Visit 2: box holds 2 → True → prints 2, box becomes 3. Back up.

Visit 3: box holds 3 → True → prints 3, box becomes 4. Back up.

Visit 4: box holds 4 → 4 <= 3 is False → the loop is over; the program continues after it.

1 2 3 Done
visit to the topcount holdscount <= 3 ?so…
11Trueprints 1 · count → 2
22Trueprints 2 · count → 3
33Trueprints 3 · count → 4
44Falseloop ends — on to print("Done")

That table is the loop table — one row per visit to the top: what the boxes hold, what the condition says, what happens. It's the labeled-box trace from Unit 2, folded into rows. From now on, whenever a loop confuses you, these notes will say one thing: draw the table.

Fig. 1 — the loop cycle. Check → body → update → back to the check. The only exit is the condition turning False — which is exactly why the update line is sacred.
Key idea
Every while has three parts: a box created before (the start), a comparison that reads it (the condition), and a line inside that changes it (the update). Forget the update and the condition never changes its mind — the loop runs forever.
Common confusion

An infinite loop is not a disaster — it's a program doing exactly what you said, forever. Every programmer writes one within their first week. In a terminal, Ctrl+C stops it; in Colab, the stop button; and the runner on this page gives up politely after about 12 seconds. P3 below has you write one on purpose, so the first accidental one is a shrug instead of a panic.

Worked example

Task: Unit 2's stretch needed one line per +1. Print five numbered hellos — with four lines of code, total. Thinking: start at 1, keep going while count <= 5, update inside. Before you run: how many times does the condition get checked? (Hint: one more than the body runs.)

4.1 · P1Your first loop

Write a while loop that prints the numbers 1 to 4, one per line. All three parts: start, condition, update. Draw the loop table on paper first if you're unsure where it stops.

1 2 3 4
Show solution
n = 1
while n <= 4:
    print(n)
    n = n + 1

The loop table has five rows: four True visits, one final False at n = 5 that ends it.

4.1 · P3The deliberate infinite loop

This loop has no update line the condition cares about — n only grows, and n > 0 stays True forever. Run it on purpose. Watch the runner spin, then stop it for you after ~12 seconds with a friendly message. That's the worst an infinite loop can do to you here. Then add one line to make it end and print escaped.

Show the fix
n = 1
while n > 0 and n < 1000000:
    n = n + 1
print("escaped")

Any change that lets the condition turn False works — a cap, a different comparison, or flipping the update to n = n - 1 (which ends it after one pass). The lesson: the condition can only say stop if something inside the loop moves it toward False.

4.1 · P4Stretch — count down by twos

Print 10, 8, 6, 4, 2 — one per line — with a while loop. The update line subtracts. Mind the condition: should it be > 0 or >= 2? (Trick question — try both and see.)

10 8 6 4 2
Show solution
n = 10
while n > 0:
    print(n)
    n = n - 2

Both conditions work here because n lands exactly on 0 — the loop table proves it. When steps don't divide evenly, the two conditions differ; the table catches that too.

4.2

for + range — counted repetition

Read · ~4 minPractice · ~10 min

The problem. "Do this exactly 10 times" is the most common loop in existence — and with while it costs you three pieces of bookkeeping (start, condition, update), each a chance to be off by one or loop forever. Counting shouldn't be this manual.

The idea, in plain words. Python has a loop with the counting built in: for is a while with the counting done for you. Write for i in range(5): and Python creates the box i, refills it with the next number before every pass, and stops by itself when the numbers run out. No start line, no condition to fumble, no update to forget. range is the number factory, and it comes in three sizes:

  • range(5) — starts at 0, gives 0 1 2 3 4. Five numbers, and 5 itself is not one of them.
  • range(2, 6) — start where you say: 2 3 4 5. Still stops one before the stop value.
  • range(1, 10, 2) — a third number sets the step: 1 3 5 7 9. A negative step counts down: range(5, 0, -1) → 5 4 3 2 1.

So which loop when? If you know how many times before the loop starts, use for. If you only know when to stop — a right guess, a sentinel, a condition — that's while country.

Trace it by hand — the same machine, hidden
for lap in range(3): print("Lap", lap) print("Race over")

Pass 1: range hands the box lap a 0 → prints Lap 0. Pass 2: box refilled with 1 → Lap 1. Pass 3: box refilled with 2 → Lap 2.

Then range has nothing left, the loop ends on its own, and the program moves past it — exactly the while cycle from Fig. 1, with the check and the update handled behind the curtain:

Lap 0 Lap 1 Lap 2 Race over
Common confusion

range(5) produces five numbers, and 5 is not one of them — it starts at 0 and stops one before the stop value. Want 1 to 5 inclusive? That's range(1, 6). The off-by-one you'd have fumbled in a while condition is still lurking here; it just moved into the stop value. Memory hook: range counts from 0 and stops one short.

Worked example

Task: print the squares of 1 through 5, one per line, in sentences. Thinking: we know how many times — five — so for. We want 1..5, not 0..4, so range(1, 6). The loop variable is a real box: use it in the f-string, square it, anything.

Print Hip hip hooray! exactly three times using for and range — one print line in the whole program. (The loop variable doesn't have to be used; it just counts.)

for i in range(3):
    print("Hip hip hooray!")

range(3) → 0, 1, 2 — three passes. Nobody reads i; it's purely the engine.

4.2 · P3Stretch — evens only, no if

4.3

break & continue — leaving early, skipping one

Read · ~3 minPractice · ~10 min

The problem. You're searching a stack of exam papers for the first failing score. The moment you find it, you're done — but your loop's condition only gets asked at the top of each pass. Encoding "stop the instant I know" into the condition means flag boxes and tangled logic. There should be an exit door inside the loop.

The idea, in plain words. There are two doors, and they do very different things:

  • break — leave the loop, now. Mid-pass, mid-body, the loop is over and the program continues after it. Use it the moment you know you're finished.
  • continue — abandon this pass only. Skip the rest of the body, go back to the top, carry on with the next value. The loop itself keeps going.

Both live inside an if — Unit 3 earning its keep — because an unconditional break would fire on pass one. And break unlocks an honest idiom you'll see everywhere: while True: — a condition that's always True, a loop that never ends by itself, designed to be left by a break when the real stopping moment arrives mid-body. That beats contorting a condition to say something it can't say cleanly.

Trace it by hand — the exit door
for n in range(1, 6): if n == 4: break print(n) print("stopped")

Passes 1–3: n is 1, 2, 3 — the if is False each time, so each prints. Pass 4: n is 4 → the if fires → break → the loop dies instantly. No 4 printed, no pass 5, straight to the line after the loop:

1 2 3 stopped

Swap break for continue and only the 4 goes missing — the loop finishes its run: 1 2 3 5 then stopped.

Common confusion

Two mix-ups, both common. First: break ends the loop, not the program — everything after the loop still runs. Second: swapping the two — break is "we're done here" (leave the whole loop), continue is "not this one" (skip one value, keep looping). If you remember one image: break is walking out of the room; continue is skipping one dish on the conveyor.

Worked example

Task: find the first number past 100 that's divisible by 7. Thinking: we don't know which number it is — but we know it the moment we see it (% from Unit 2 says so). So: march upward with for, and break at the discovery. No flag boxes, no clever condition — the exit sits exactly where the knowledge appears.

4.3 · P1First big square

Find the first number whose square is bigger than 50: loop upward from 1, and the moment n * n > 50, print n and break. One number in the output, nothing else.

8
Show solution
for n in range(1, 20):
    if n * n > 50:
        print(n)
        break

7 × 7 = 49 sneaks under; 8 × 8 = 64 triggers the door. Without break, 9 through 19 would print too.

4.3 · P3Stretch — stop at the meeting point

Print the numbers from 1 upward, but the first number divisible by both 2 and 3 ends the show: print found and that number instead, then stop. Unit 3's and meets Unit 2's % meets today's break.

1 2 3 4 5 found 6
Show solution
for n in range(1, 11):

Order matters inside the body: the check must come before the print, or 6 prints as a plain number first. Trace it both ways and see.

4.4

Counters & accumulators — loops that build an answer

Read · ~4 minPractice · ~10 min

The problem. So far our loops print and forget. But the questions worth asking come with one answer at the end: what's the total of these bills? the average score? how many passed? Each pass sees one value; the answer needs all of them. Something must survive the passes.

The idea, in plain words. A box that outlives the loop. Create it before the loop, feed it inside, read it after. That's the accumulator pattern, and it's three lines of shape:

wherelinewhy
before the looptotal = 0an empty jar on the counter
inside the bodytotal = total + xeach pass drops its coin in
after the loopprint(total)the jar holds the answer

A counter is the same jar fed + 1 at a time — and put the feeding line under an if and you get the count-matching pattern: how many scores are 50 or more? — if score >= 50: passed = passed + 1. Total, count, biggest-so-far, all of statistics-by-hand: one jar each, all fed inside the same loop.

Trace it by hand — the jar fills
total = 0 for n in range(1, 5): total = total + n print(total)

Before: total holds 0. Pass n=1: 0 + 1 → jar holds 1. Pass n=2: 1 + 2 → 3. Pass n=3: 3 + 3 → 6. Pass n=4: 6 + 4 → 10.

Loop over, jar read out:

10

Draw the loop table with two box columns — n and total — and watch one column feed the other. That's the whole pattern.

Key idea
Init before, update inside, read after. The accumulator's opening line lives before the loop for the same reason the jar goes on the counter before the coins: put it inside and every pass starts with a fresh empty jar.
Common confusion

Writing total = 0 inside the loop is the classic slip. No error appears — the program runs, and the jar is quietly emptied at the top of every pass, so it ends up holding only the last value. If your total suspiciously equals the final number, the init line has wandered inside. Move it up.

A shorthand you'll meet in the wild
total += x means exactly total = total + x — same for -=, *=. These notes will keep writing the long form a little while yet, because the long form shows the machinery. Read either fluently.
Worked example

Task: four exam scores arrive one by one; report the total and how many passed (50 or more). Thinking: two jars — total and passed — both before the loop; a for asks four times (convert at the door!); one jar fed every pass, the other only when the if agrees. Inputs fixed: 62, 38, 71, 50.

4.4 · P1The little sum

Sum the numbers 1 to 10 with a loop and one accumulator, and print just the total. (Check yourself: the answer ends in 5.)

55
Show solution
total = 0
for n in range(1, 11):
    total = total + n
print(total)

range(1, 11) for 1..10 — stop one past the last number you want. The print sits after the loop: one answer, not ten running totals.

4.4 · P2Count the evens

Ask Number? five times (convert at the door) and count how many entered numbers are even — % 2 from Unit 2 decides. Print the count in the exact sentence shown. Inputs fixed: 7, 12, 9, 4, 10.

Number? 7 Number? 12 Number? 9 Number? 4 Number? 10 Even numbers: 3
Show solution
evens = 0
for i in range(5):
    n = int(input("Number? "))
    if n % 2 == 0:
        evens = evens + 1
print("Even numbers:", evens)

Count-matching: the jar only gets a coin when the if agrees. 12, 4 and 10 pass the % 2 test.

4.4 · P3Stretch — king of the hill

Three scores arrive; report the highest — no max(), just an accumulator with a twist: a biggest jar that a new score only replaces if it's bigger. Inputs fixed: 34, 78, 56.

Score? 34 Score? 78 Score? 56 Highest: 78
Show solution
biggest = 0
for i in range(3):
    score = int(input("Score? "))
    if score > biggest:
        biggest = score
print("Highest:", biggest)

The update isn't an addition this time — it's a conditional replacement. 34 beats 0, 78 beats 34, 56 doesn't beat 78. Same skeleton: init before, update inside, read after.

4.5

Your build — guess my number, v2

Read · ~2 minPractice · ~12 min

Unit 3's guessing game could judge a guess — one guess, one verdict, game over. That's a decision without repetition, which is to say: not really a game. Version 2 is the real thing, and it's this whole unit in one program: a while with a tries counter, if/elif/else giving hints inside it, and break at the moment of victory. Then a second, gentler build — the times-table printer every schoolbook wall promised you — to let for show off.

4.5 · P1The game, complete

The secret is 7; the player gets at most 3 tries. Each round: ask Your guess? (convert at the door), count the try, then judge — correct prints Got it in N tries! and breaks; too low prints Too low.; too high prints Too high.. The scripted player guesses 3, then 9, then 7.

Your guess? 3 Too low. Your guess? 9 Too high. Your guess? 7 Got it in 3 tries!
Show solution
secret = 7
tries = 0
while tries < 3:
    guess = int(input("Your guess? "))
    tries = tries + 1
    if guess == secret:
        print(f"Got it in {tries} tries!")
        break
    elif guess < secret:
        print("Too low.")
    else:
        print("Too high.")

Every piece of the unit is in here: the counter is the update line, the condition caps the tries, break ends the game at the win. Count the try before judging, or the winning message reports one try too few.

4.5 · P2The times-table printer

Print the full 7-times table, 1 through 10, one line per product, in exactly the schoolbook shape — an f-string with three blanks does one line, for does the rest. Keep the number in a box n so changing one character reprints any table.

7 x 1 = 7 7 x 2 = 14 7 x 3 = 21 7 x 4 = 28 7 x 5 = 35 7 x 6 = 42 7 x 7 = 49 7 x 8 = 56 7 x 9 = 63 7 x 10 = 70
Show solution
n = 7
for i in range(1, 11):
    print(f"{n} x {i} = {n * i}")

Ten schoolbook lines from three lines of code — and expressions live happily inside the braces. Change n to 13 and you've printed a table no schoolbook wall ever had.

4.6

Problem bank — everything at once

Practice · ~12 min

The mixed set. Both loops, both doors, jars of every kind — plus arithmetic and conditions from Units 2 and 3. In order; they get meaner.

B1The countdown

Count down from 5 to 1, one number per line, then print Liftoff!. Either loop works — pick one, and know how you'd write the other. (If you choose range, remember the step can be negative.)

5 4 3 2 1 Liftoff!
Show solution
for n in range(5, 0, -1):
    print(n)
print("Liftoff!")

Or the while version: n = 5; while n >= 1: print(n); n = n - 1. Note Liftoff! is outside the loop — un-indented — or it launches five times.

B2The famous sum

Add up every number from 1 to 100 and print the total — the sum a schoolboy named Gauss did in seconds by being clever. You get to be lazy instead: a loop and a jar. One number in the output.

5050
Show solution
total = 0
for n in range(1, 101):
    total = total + n
print(total)

Gauss paired 1+100, 2+99 … fifty pairs of 101 → 5050. Your loop found the same answer by brute honesty — and would find 1-to-a-million just as calmly.

B3The average machine

Keep asking Score (-1 to stop)? until -1 arrives — the sentinel, a value whose only job is to say "stop asking". Don't count it, don't add it: break the moment you see it. Then print the average of the real scores to two decimals. Scripted entries: 40, 70, 55, then -1.

Score (-1 to stop)? 40 Score (-1 to stop)? 70 Score (-1 to stop)? 55 Score (-1 to stop)? -1 Average: 55.00
Show solution
total = 0
count = 0
while True:
    score = int(input("Score (-1 to stop)? "))
    if score == -1:
        break
    total = total + score
    count = count + 1
print(f"Average: {total / count:.2f}")

while True + break is the sentinel loop's natural shape — the stopping moment lives mid-body, where no top-of-loop condition can see it cleanly. Two jars (total and count), and :.2f dresses 55.0 as 55.00 at the exit.

B4Stretch — the digit shredder

Sum the digits of 4728 — 4 + 7 + 2 + 8 — using a while and Unit 2's B2 trick: % 10 peels off the last digit, // 10 shreds it away. Loop while the number still has digits left. When does n itself make a fine condition?

Digit sum: 21
Show solution
n = 4728
total = 0
while n > 0:
    total = total + n % 10
    n = n // 10
print("Digit sum:", total)

The loop table: n 4728→472→47→4→0, total 8→10→17→21. The update line is a division this time — anything that drives the condition toward False qualifies. Unit 2's digit trick, now working for numbers of any length.
