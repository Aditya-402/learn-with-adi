12.1

The pattern behind the loop

Read · ~4 minPractice · ~10 min

The problem. Count how many times you've typed this exact shape: make an empty list, loop over an old list, append something to the new one. Here it is three times in a row — read all three before you continue:

# double each number doubled = [] for n in numbers: doubled.append(n * 2) # grab each word's length lengths = [] for w in words: lengths.append(len(w)) # SHOUT each name shouted = [] for name in names: shouted.append(name.upper())

Squint. Every version is the same machine with one part swapped: the expression inside the append. Everything else — the empty list, the for line, the .append(...) wrapper — is scaffolding you rebuild by hand every single time.

The idea, in plain words. Python lets you state the finished list directly and skip the scaffolding:

doubled = [n * 2 for n in numbers]

This is a list comprehension, and there is a house way to read it aloud: "a list of n-times-two, for each n in numbers." Say it that way every time and the syntax stops looking like punctuation soup. The square brackets say "I am a list"; the expression before for is what each item becomes; the for n in numbers part is the exact same for line you've written since Unit 4. Same meaning, same result, one line — nothing new is happening in memory, only on your screen.

Trace it by hand — the folded loop, unfolded
numbers = [3, 8, 12] doubled = [n * 2 for n in numbers] print(doubled)

Line 2, right side first, exactly as the loop would run: n takes 3 → 3 * 2 → 6 lands in the new list. n takes 8 → 16 lands. n takes 12 → 24 lands. The finished list [6, 16, 24] is stored into the box doubled. The box numbers is untouched — a comprehension always builds a new list.

[6, 16, 24]
Fig. 1 — The accumulate loop and the comprehension are one machine in two spellings. Only the colored parts carry meaning; the grey scaffolding is what the comprehension deletes.
Common confusion

The order feels backwards at first: the result expression comes before the for, and there's no colon and no append. Don't try to memorise the syntax — memorise the sentence: "a list of <what each becomes>, for each <item> in <source>." Write the sentence, then transcribe it. And no colon means no colon: [n * 2 for n in numbers:] is a SyntaxError.

Key idea
A comprehension is the accumulate-a-new-list loop folded into one expression. If you can write the loop, you already know the comprehension — the skill is translating both directions, fluently.
Worked example

Task: rewrite all three loops from the top of this section as comprehensions and print the results. Thinking: for each, say the sentence first — "a list of len-of-w, for each w in words" — then transcribe. Run it and compare with what the loops would have produced (identical, always).

12.1 · P1Loop → comprehension

This loop computes half-price sale tags. Rewrite it as one comprehension line plus the print. The check only sees the output — but the point is the shape, so hold yourself to one line.

[20, 45, 60]
Show solution

12.1 · P2Comprehension → loop

Translation runs both ways or it isn't fluency. Rewrite this comprehension as the full four-line accumulate loop — empty list, for, append, print — producing the same output.

firsts = []
for w in fruits:
    firsts.append(w[0])

12.2

The condition clause — keep only some

Read · ~3 minPractice · ~8 min

The problem. Half your accumulate loops had an if inside: keep the passing scores, keep the even numbers, keep the long words. Does the folded version have room for the if?

The idea, in plain words. Yes — it bolts on at the end:

passed = [x for x in scores if x >= 50]

Read aloud: "a list of x, for each x in scores, if x is at least 50." Each item is tested at the gate; only the ones that pass get transformed and kept. That gives you three moves with one syntax:

  • Transform only — [x * 2 for x in nums]: every item, changed.
  • Filter only — [x for x in scores if x >= 50]: some items, unchanged. (The transform slot just says x — "keep it as it is".)
  • Both — [x * 2 for x in nums if x % 2 == 0]: test first, then transform the survivors.
Trace it by hand — every item visits the gate
nums = [7, 12, 5, 20] picked = [n * 2 for n in nums if n % 2 == 0] print(picked)

Same trace table as always, one column per question:

itempasses n % 2 == 0?lands in list as
7no (remainder 1)— skipped entirely
12yes24
5no— skipped entirely
20yes40
[24, 40]
Common confusion

Items that fail the if don't land in the list as False, None, or 0 — they are simply not there. A filtered list is usually shorter than its source, and nothing marks the gaps. If your list came out length 2 from a source of length 4, that's the filter doing its job, not data going missing.

Worked example

Task: from a list of exam scores, keep the passes (50 or more) and report how many made it. Thinking: the filter-only shape — transform slot is just s — then len() on both lists for the summary line. Notice the comprehension slots straight into an f-string-fed report.

12.2 · P1Filter only

A week of temperatures. In one comprehension line, keep only the hot days — 30 or above — and print the list.

[31, 35, 40]
Show solution
temps = [31, 24, 35, 28, 40]
hot = [t for t in temps if t >= 30]
print(hot)

Filter-only: the transform slot keeps t as-is, the gate does the choosing.

12.2 · P2Filter and transform together

One line: double only the even numbers. Trace it with the gate table on paper first if the answer isn't obvious — which items even reach the doubling?

[8, 20]
Show solution
nums = [3, 4, 7, 10, 13]
doubled_evens = [n * 2 for n in nums if n % 2 == 0]
print(doubled_evens)

Only 4 and 10 pass the gate; they become 8 and 20. The odd numbers never meet the * 2.

12.3

Dict & set comprehensions — the braces family

Read · ~4 minPractice · ~8 min

The problem. Lists aren't the only thing you accumulate. Unit 6 had you building dicts in loops — and sometimes what you really want is just the unique values, cleaned up. Do those loops fold too?

The idea, in plain words. Same folding, different brackets. Curly braces with a key: value pair build a dict comprehension:

{name: len(name) for name in names}

Read aloud: "a dict of name-to-its-length, for each name in names." And curly braces with a single expression build a set comprehension — a collection that keeps one copy of each value and no particular order:

{w.lower() for w in words}

That one line is the classic dedup-and-normalise move: lowercase everything, and the set silently discards repeats. One house rule, because sets have no order you can rely on: always wrap a set in sorted() before printing it — sorted() hands back an ordered list, so your output is the same on every run (and checkable).

Trace it by hand — one dict, one set
names = ["Ada", "Bob", "Cara"] lengths = {name: len(name) for name in names} print(lengths) words = ["Tea", "tea", "CHAI", "chai"] unique = {w.lower() for w in words} print(sorted(unique))

Line 2: pairs land in insertion order — "Ada"→3, "Bob"→3, "Cara"→4.

Line 6: lowercase each: "tea", "tea" (duplicate, discarded), "chai", "chai" (discarded). Two survivors; sorted() lines them up alphabetically for the print.

{'Ada': 3, 'Bob': 3, 'Cara': 4} ['chai', 'tea']
Common confusion

Curly braces are doing double duty: {k: v for ...} (with a colon) is a dict, {v for ...} (no colon) is a set. And the empty case breaks the pattern: {} is an empty dict, not an empty set — an empty set needs set(). When output surprises you, type(x) settles it, as always.

Worked example

Task: Unit 6's word counter, revisited in comprehension spirit — count each distinct word in a line of text. Thinking: split, dedup with set(), sort for stable order, and let .count() do the tallying in a dict comprehension. Honest note in the solution below the run: the Unit 6 loop is still the better counter — this version re-scans the whole list once per distinct word, where the loop with .get() touches each word exactly once. Not everything should compress; keep both tools.

One dict comprehension: each number maps to its square. Say the sentence first — "a dict of n-to-n-squared, for each n in nums" — then transcribe and print.

{1: 1, 2: 4, 3: 9}

nums = [1, 2, 3]

Key expression, colon, value expression — then the familiar for-clause. Insertion order means the print is predictable.

12.3 · P2Dedup and normalise

Four messy city entries, two real cities. One set comprehension with .strip().title() in the transform slot, then print it sorted() — the house rule.

['Delhi', 'Mumbai']
Show solution
cities = [" delhi", "Delhi ", "MUMBAI", " mumbai"]
clean = {c.strip().title() for c in cities}
print(sorted(clean))

Normalise inside the set comprehension so the set sees identical spellings and can discard the repeats. Then sorted() for a printable, checkable order.

12.3 · P3Stretch — flip a dict

Unit 6's .items() unpacking, now inside a comprehension: build the reverse dict, grade → name. One line plus the print.

{'A': 'Ada', 'B': 'Bob'}
Show solution
grades = {"Ada": "A", "Bob": "B"}
flipped = {g: name for name, g in grades.items()}
print(flipped)

Two names unpack each pair — exactly as in Unit 6's loops — and the comprehension swaps their roles around the colon. (Only safe when the values are unique; repeated values would overwrite each other.)

12.4

The judgment — when NOT to fold

Read · ~4 minPractice · ~8 min

The problem. New tool, new temptation: once comprehensions click, every loop starts looking like a candidate. Some aren't — and a comprehension forced onto the wrong loop is worse code wearing a clever hat. How do you tell?

The idea, in plain words. Ask the two questions, in order:

  • Is it a transform or a filter? A comprehension does exactly two things: change items, choose items. If the loop's body does something — prints, asks for input, updates a running total where each step needs the previous one — it isn't a transform, and it should stay a loop. Never put print() inside a comprehension; a comprehension's job is to produce a value, not to act.
  • Does it fit on one honest line? Honest means you can still say the sentence aloud without breathing twice. The moment a comprehension nests inside another — [[r * c for c in row] for row in grid] is legal — reading it becomes archaeology. Two levels in, unfold back to loops.

One more piece of machinery, shown because you'll meet it in other people's code: the transform slot can hold a conditional expression — "pass" if s >= 50 else "fail" — a value-producing if/else. Note where it lives: before the for, choosing what each item becomes; the trailing if chooses whether the item appears at all. Powerful, and precisely where readability starts to strain — use it when the sentence still reads aloud, not to show off.

Key idea
The two-question test: Is it a pure transform/filter? Does it fit on one honest line? Two yeses → comprehension. Any no → the loop was already the right tool. Choosing the loop is not a failure; it's the judgment this section exists to build.
Worked example

Task: label each score "pass" or "fail" — once as the plain loop, once folded with a conditional expression. Thinking: both are legitimate here (it is a pure transform, and the line reads aloud: "a list of pass-if-fifty-else-fail, for each s"). Run it, confirm they agree, and notice which one your eyes prefer today. Both answers are allowed.

Show what happens & why
[5, 15, 35]

A running balance: each item's result depends on the previous step's result, carried in the balance box. That fails question one — it's not a per-item transform, it's a chain — so the loop is the right tool, full stop. A comprehension forced onto this becomes a puzzle; the loop is a sentence.

12.4 · P2Undo the clever

Someone used a comprehension to do something instead of to build something. Run it as-is and study the last line of output — that's print()'s return value, collected three times. Then rewrite it as the honest loop so the output matches the goal exactly.

1 2 3
Show solution
for n in [1, 2, 3]:
    print(n)

The as-is run ends with [None, None, None] — print() displays things but produces nothing, so the comprehension dutifully collected three nothings. Side effects belong in loops; comprehensions are for values.

12.5

Your build — the marks report

Read · ~3 minPractice · ~12 min

This is the Beginner checkpoint — the victory lap. One program, and every unit you've done reports for duty: Unit 3's grade bands, Unit 4–5's loops and lists, Unit 6's dicts, Unit 7's functions, Unit 8's aligned f-strings, and today's comprehensions doing the harvesting. Take a second to notice that print("Hello, world") was eleven units ago.

One new tool first, promised since Unit 6's .items() unpacking: zip(). You have two parallel lists — names and scores — where position pairs them: the first name goes with the first score, the second with the second. zip(names, scores) closes them like a zipper: loop over it and you get the pairs, ready for the same two-name unpacking you already know: for name, score in zip(names, scores). That's the whole tool.

Fine print on zip
If the lists have different lengths, zip() quietly stops at the shorter one — no error, just missing pairs. For this build the lists are the same length; in real data, check len() first.
12.5 · P1Stage 1 — zip the lists

Loop over zip(names, scores) with two-name unpacking and print each pair with a comma-print, one line per person.

Ada 91 Bob 45 Cara 78 Dev 85 Esha 62
Show solution
names = ["Ada", "Bob", "Cara", "Dev", "Esha"]
scores = [91, 45, 78, 85, 62]
for name, score in zip(names, scores):
    print(name, score)

The zipper pairs by position; the two names unpack each pair — the exact move you learned on .items().

12.5 · P2Stage 2 — the comprehension harvest

Three statistics: the average (sum ÷ count, shown with :.2f); the passing scores (50 or more) as a plain filter; the distinction names (85 or more) — that one needs zip inside the comprehension, unpacking pairs and keeping the name while testing the score.

Average: 72.20 [91, 78, 85, 62] ['Ada', 'Dev']
Show solution
names = ["Ada", "Bob", "Cara", "Dev", "Esha"]
scores = [91, 45, 78, 85, 62]
average = sum(scores) / len(scores)
passed = [s for s in scores if s >= 50]
distinction = [name for name, s in zip(names, scores) if s >= 85]
print(f"Average: {average:.2f}")
print(passed)
print(distinction)

The distinction line is the unit in miniature: pair with zip, unpack, filter on one half, keep the other. Say it aloud — "a list of name, for each name-and-s pair, if s is at least 85."

12.5 · P3Stage 3 — the full report

Assemble everything. Write a grade() function using the Unit 3 bands (85+ → A, 70+ → B, 50+ → C, else F); build a name→grade dict with a dict comprehension over zip; then print the report — a header, one aligned line per person using f"{name:<6}{score:>3} {grades[name]}", and the three summary lines from Stage 2. Match the goal byte for byte; the alignment specs do the column work.

=== MARKS REPORT === Ada 91 A Bob 45 F Cara 78 B Dev 85 A Esha 62 C Average: 72.20 Passed: 4 of 5 Distinction: ['Ada', 'Dev']
Show solution
def grade(score):
    if score >= 85:
        return "A"
    elif score >= 70:
        return "B"
    elif score >= 50:
        return "C"
    else:
        return "F"

names = ["Ada", "Bob", "Cara", "Dev", "Esha"]
scores = [91, 45, 78, 85, 62]

grades = {name: grade(s) for name, s in zip(names, scores)}
average = sum(scores) / len(scores)
passed = [s for s in scores if s >= 50]
distinction = [name for name, s in zip(names, scores) if s >= 85]

print("=== MARKS REPORT ===")
for name, score in zip(names, scores):
    print(f"{name:<6}{score:>3}  {grades[name]}")
print(f"Average: {average:.2f}")
print(f"Passed: {len(passed)} of {len(scores)}")
print(f"Distinction: {distinction}")

Look at what each line owes to which unit: the function to 7, the bands to 3, the dict comprehension to 6 and today, the alignment to 8, the loop to 4. The report loop itself stays a loop — it prints, so the two-question test says so. That's the whole level, in one screen of code you understand completely.

B1Squares, one line

The squares of 1 through 10, one comprehension over range(1, 11), printed as a list.

[1, 4, 9, 16, 25, 36, 49, 64, 81, 100]
Show solution
print([n * n for n in range(1, 11)])

B2Clean the messy list

Real data arrives dirty. One comprehension chaining .strip() and .title() in the transform slot turns this mess into a clean list — order preserved, so no set needed here.

['Ada', 'Bob', 'Cara']
Show solution
raw = ["  Ada ", "bob", " CARA"]
clean = [s.strip().title() for s in raw]
print(clean)

Method chaining from the strings unit, riding in the transform slot. This exact line, or one like it, opens nearly every real data-cleaning script you'll ever write.

B3Prices with tax

From a price dict, build a new dict with 5% tax added — same keys, values times 1.05, rounded with round(..., 2). One dict comprehension over .items().

{'tea': 12.6, 'samosa': 18.9, 'cake': 47.25}
Show solution
prices = {"tea": 12, "samosa": 18, "cake": 45}
taxed = {k: round(v * 1.05, 2) for k, v in prices.items()}
print(taxed)

Keys pass through untouched; values get transformed. Note round() here trims the value itself (floats being floats, per Unit 2's 0.1 + 0.2 story) — where :.2f would only dress the display.

B4Stretch — FizzBuzz, harvested

The interview classic, Beginner-level style: write a helper function fizzbuzz(n) returning "FizzBuzz" for multiples of 15, "Fizz" for 3, "Buzz" for 5, else str(n) — then ask Up to? , convert at the door, and print the whole list via one comprehension. Input fixed to 15. (The messy if/elif logic lives in the function; the comprehension stays a clean sentence — that division of labour is the lesson.)

Up to? 15 ['1', '2', 'Fizz', '4', 'Buzz', 'Fizz', '7', '8', 'Fizz', 'Buzz', '11', 'Fizz', '13', '14', 'FizzBuzz']
Show solution
def fizzbuzz(n):
    if n % 15 == 0:
        return "FizzBuzz"
    elif n % 3 == 0:
        return "Fizz"
    elif n % 5 == 0:
        return "Buzz"
    else:
        return str(n)

limit = int(input("Up to? "))
print([fizzbuzz(n) for n in range(1, limit + 1)])

Test 15 first or it matches 3 and never reaches FizzBuzz — Unit 3's most-specific-first rule. When a transform grows an if/elif ladder, don't cram it into the slot: name it as a function and let the comprehension call it. That's the two tools sharing the work.
