1.1

Meet the machine

Read · ~3 minPractice · ~8 min

The problem. You want a computer to do something for you — greet a visitor, total a bill, rename five hundred files. But a computer cannot be told what you want the way a person can. It doesn't guess, doesn't infer, doesn't fill in gaps. So how do you get work out of it?

The idea, in plain words. Think of the computer as a kitchen helper who is astonishingly fast, never gets tired, and follows a recipe exactly — but has zero imagination. Write "add salt to taste" and this helper freezes: whose taste? how much? A recipe for this helper must spell out every single step, in order, with nothing left to judgment. That written-out recipe is a program, and each line of it is an instruction.

Recipes need a language both sides understand. Ours is Python — a programming language designed to read almost like English, which is why it's the one most of the machine-learning world runs on, and why it's where this whole pathway begins.

Your first instruction is print. Despite the name, it has nothing to do with paper — it means "show this on the screen."

Trace it by hand — your first program, one line
print("Hello, world")

Read it the way Python does, left to right: print — "show something on screen." The parentheses ( ) hold what to show. Inside them, "Hello, world" — the exact text, wrapped in quotes. Python runs the line and the screen shows:

Hello, world

One instruction in, one action out. That's the entire transaction — and every program you will ever write, however large, is just more of these transactions in a row.

Fig. 1 — The whole loop: you write the recipe, Python follows it to the letter, the screen shows the result. No step involves the machine guessing.
Key idea
A program is a recipe with no gaps: every step written out, followed exactly, at incredible speed. The skill you are building in this series is writing gapless recipes.
Worked example — watch one first

Task: make the machine say hello. Thinking: we need one instruction — show text on screen — so: print, parentheses for the what, quotes around the exact words. Press ▶ Run below and watch the screen panel answer. Then change the text between the quotes to anything you like and run it again — it obeys you now.

1.2

print(), properly — and why the quotes

Read · ~3 minPractice · ~10 min

The problem. You've been faithfully typing quotes around text without knowing why. Try leaving them off — print(Hello) — and Python refuses. Why does a machine care about two little marks?

The idea, in plain words. The quotes settle a question Python cannot answer on its own: are these characters words to repeat, or an instruction to follow? It's exactly how quotation marks work in English. In say "your name", you'd literally speak the words your name; in say your name, you'd answer Ada. Same three words — the quotes flip the meaning.

Text wrapped in quotes is called a string (a string of characters, like beads on a thread — the jargon will feel normal within a week). Without quotes, Python treats the word as a name it should already know — and Hello names nothing, so it objects.

Two more moves complete the tool. Numbers need no quotes — print(2026) is fine, because digits can't be confused with instructions. And commas print several things at once: print("Age:", 25) shows Age: 25, with Python politely inserting the space at each comma.

Trace it by hand — three lines, three behaviours
print("2 + 3") print(2 + 3) print("Result:", 2 + 3)

Line 1: quotes say repeat exactly — the screen shows 2 + 3, no arithmetic done.

Line 2: no quotes, so Python works it out — the screen shows 5.

Line 3: both at once, joined by a comma — the screen shows Result: 5.

2 + 3 5 Result: 5

One rule underneath all three: quoted means repeated, unquoted means understood.

Common confusion

print("7") and print(7) both show 7 on screen — so are quotes optional for digits? No: the first is the character 7 (text), the second the number 7. Today they look identical; in Unit 2, when we do arithmetic, "7" + "7" and 7 + 7 give wildly different answers. Plant the distinction now.

Worked example

Task: print I am 10 years old using the number 10 as a number, not as text. Thinking: two pieces of text and a number, joined by commas — Python adds the spaces at each comma, so the strings must not carry extra ones.

1.3

Errors are messages, not verdicts

Read · ~3 minPractice · ~8 min

The problem. Sometime in the next ten minutes you will type something Python cannot follow, and the screen will fill with stern red text. Every beginner's instinct is the same: I broke it. You didn't, and you can't.

The idea, in plain words. Remember the literal-minded kitchen helper. Hand it a recipe step it cannot follow and it doesn't explode, sulk, or improvise — it stops and tells you, quite precisely, where it got stuck and what kind of stuck. That report is an error message. It is the machine holding up its end of the conversation. Experienced programmers see dozens a day; reading them calmly is the actual skill, and it starts here.

Two kinds you'll meet today:

  • SyntaxError — "I couldn't even read that line." Usually a missing quote or bracket — the punctuation broke before the meaning was reached.
  • NameError — "I read it fine, but you used a name I don't know." A misspelled print, or text that forgot its quotes.

And one habit to install on day one: error reports print the location first and the diagnosis last, so read the last line first. It names the kind and the cause; the lines above it just say where.

Trace it by hand — anatomy of one error
print("Bye)

Python reads left to right: print — fine. ( — fine. " — a string begins… and the line ends before another " closes it. Python cannot even finish reading, so it reports:

print("Bye) ^ SyntaxError: unterminated string literal

Last line first: SyntaxError — couldn't read it; unterminated string — a quote opened and never closed. The ^ points near the trouble. Diagnosis in hand, the fix is obvious: close the quote.

Common confusion

An error does not mean the computer is damaged, your earlier work is lost, or you are "bad at this." The program simply stopped at the step it couldn't follow. Fix the line, run again — the machine holds no grudge and remembers no failures.

Worked example

Task: this program is broken; make it print Good morning. Thinking: Run it as is first — never fix blind. The last line of the report says NameError: name 'prnt' is not defined. Python read the line but doesn't know any instruction called prnt — a misspelling. Correct it to print, run again: clean.

1.4

The program listens — input()

Read · ~4 minPractice · ~10 min

The problem. Everything so far talks at you — the same output every run, like a wind-up toy. A conversation needs the program to ask, wait, and use your answer.

The idea, in plain words. The instruction input() does exactly three things: shows a question, pauses the whole program until something is typed, then hands back whatever was typed. But "hands back" to where? If nobody catches the answer, it's gone. So we catch it in a labeled box:

name = input("What is your name? ")

Read the = as "store into", right to left: run input(…), take what comes back, store it in a box labeled name. From that line on, writing name anywhere means the contents of that box. These boxes are called variables, and they're so central they get all of Unit 2 — today, one box is all we need.

One honest note about this page: a real Python program would pause and wait for your keyboard. In these practice boxes the wait is played by the Program input field below the code — it holds the answers the program will receive, in order, so the checks can know what to expect. Same behaviour, just visible in advance.

Trace it by hand — with the state of memory
name = input("What is your name? ") print("Hello,", name, "— welcome aboard!")

Line 1: the question appears, the program stops dead. Suppose Ada is typed. input hands back "Ada" and it lands in the box. Memory now holds: name → "Ada".

Line 2: Python meets the word name — no quotes, so it's a name it should know. It does: box, contents "Ada". It swaps in the contents and prints:

What is your name? Ada Hello, Ada — welcome aboard!
Fig. 2 — The state of memory. Every program you'll ever trace comes down to this: which boxes exist, and what's in each after every line. Unit 2 makes this picture the star.
Key idea
input() asks and hands back; = stores into a labeled box; an unquoted name reads the box back out. Ask → store → use: the shape of every interactive program.
Worked example

Task: the two-line greeter from the trace, live. The Program input field plays your keyboard — it holds Ada. Run it; then change the input to your own name and run again. Same recipe, different conversation.

1.4 · P1The food critic

Write a program that asks What is your favourite food? (note the space before the closing quote), stores the answer in a box called food, and replies with the food's name followed by sounds delicious!. The input field is fixed to dosa so Check knows what to expect.

What is your favourite food? dosa dosa sounds delicious!
Show solution
food = input("What is your favourite food? ")
print(food, "sounds delicious!")

The box is read back out by writing its unquoted name; the comma supplies the space before "sounds".

1.4 · P2Two questions, two boxes

Ask What is your name? then Which city are you from? , keep the answers in two boxes, and combine both in one final greeting using commas. Inputs are fixed to Ada then Chennai.

What is your name? Ada Which city are you from? Chennai Hello, Ada from Chennai
Show solution
name = input("What is your name? ")
city = input("Which city are you from? ")
print("Hello,", name, "from", city)

Two boxes, both read back out by their unquoted names. Wondering why the target has no exclamation mark? Try adding , "!" — the comma sneaks a space in before it. Gluing text with no gaps needs +, which is Unit 2's business.

1.4 · P3Your build — the greeter that answers back

The unit's build, yours to design: a short conversation of at least three questions — name, mood, anything — with a reply after each answer, ending with a sign-off line. Set the Program input field to your own answers (separate them with ⏎). No Check — run it, refine it, make it feel like your program. This is the first thing you have ever built. Keep it.

B3The compliment machine

Ask How old are you? , store the answer in a box called age, and reply using commas so the output matches exactly. Input is fixed to 21.

How old are you? 21 Wow, 21 is a great age!
Show solution
age = input("How old are you? ")

Ask → store → use. The commas place one space either side of the box's contents.

B4Stretch — the mini interview

Three questions — Name? , Favourite colour? , Tea or coffee? — then a one-line summary built from all three boxes with commas. Inputs are fixed to Ada, blue, tea.

Name? Ada Favourite colour? blue Tea or coffee? tea Ada likes blue and drinks tea
Show solution
name = input("Name? ")
colour = input("Favourite colour? ")
drink = input("Tea or coffee? ")
print(name, "likes", colour, "and drinks", drink)

Three boxes, one sentence. You have just written a program with memory, conversation, and structure — on day one.
