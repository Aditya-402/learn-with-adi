2.1

Labeled boxes — variables, properly

Read · ~4 minPractice · ~8 min

The problem. Programs need to keep things around. A bill total must survive from the line that computes it to the line that prints it; a name typed once should be usable five lines later. Where does a program keep what it knows?

The idea, in plain words. In labeled boxes. The line price = 40 does exactly one thing: takes a box, sticks the label price on it, and puts 40 inside. From then on, writing price anywhere means the contents of that box. That's the whole mechanism — and three consequences follow:

  • Read = as "store into", never "equals". Right side first, then into the box on the left. That's why count = count + 1 — nonsense in maths — is perfectly sensible here: work out the right side using the old contents, then store the result back.
  • A box holds one thing. Store something new and the old contents are gone — no warning, no undo.
  • Labels are exact. price, Price and PRICE are three different boxes (Unit 1's case-sensitivity, back again). Labels use letters, digits and underscores, can't start with a digit, and can't contain spaces — total_cost, not total cost.
Trace it by hand — watch the boxes
score = 10 score = score + 5 bonus = score print(score, bonus)

Line 1: box score created, holds 10.

Line 2: right side first: score + 5 → 10 + 5 → 15. Stored back: score now holds 15. The 10 is gone.

Line 3: right side is score → 15. A new box bonus gets a copy: 15. Two boxes now, each holding their own 15.

Line 4: both boxes read out:

15 15
Fig. 1 — Three snapshots of memory. Tracing any program means keeping this picture in your head; these notes will keep drawing it until you do it automatically.
Common confusion

= in Python is not the equals sign from school. It's an arrow pointing left: compute the right, store into the left. Asking whether two things are equal is a different symbol (==) and a different unit — Unit 3. If count = count + 1 still reads like a lie, read it as "new count = old count + 1".

Worked example

Task: a game awards 10 points, then doubles your score, then adds 3. Track it in one box and print the final value. Thinking: one box, three store-intos — each right side uses the box's current contents. Predict the number before you run.

2.2

Numbers & arithmetic — the seven operators

Read · ~4 minPractice · ~10 min

The problem. Boxes that only store are a filing cabinet. Programs earn their keep by computing — totals, splits, percentages, remainders. What arithmetic does Python actually offer?

The idea, in plain words. Python has two kinds of numbers: int — whole numbers like 4 — and float — decimal-point numbers like 4.5 (so called because the point "floats"). Seven operators work on both:

operatordoesexamplegives
+ - *add, subtract, multiply4 * 520
/divide — always a float10 / 42.5
//divide, keep whole part10 // 42
%the remainder10 % 42
**power2 ** 38

The pair // and % answer one everyday question together: share 10 sweets among 4 kids — 10 // 4 says each gets 2, 10 % 4 says 2 are left over. And order follows school rules — multiply and divide before add and subtract — with parentheses to override: (2 + 3) * 4 is 20, 2 + 3 * 4 is 14. When in doubt, add parentheses; they're free.

Trace it by hand — a real bill
samosas = 3 * 15 tea = 2 * 12 bill = samosas + tea print(bill, bill / 2)

Line 1: 3 × 15 → samosas holds 45. Line 2: 2 × 12 → tea holds 24. Line 3: 45 + 24 → bill holds 69.

Line 4: prints the bill and a two-way split — and note the split: 69 / 2 is 34.5, a float. Division always hands back a float, even 10 / 2 → 5.0.

69 34.5
Common confusion

Why does 10 / 2 print 5.0 and not 5? Because / always produces a float — Python won't secretly switch types on you depending on whether the division came out even. Want the whole-number version? That's what // is for: 10 // 2 → 5.

Worked example

Task: 47 students, vans seat 12 each — how many full vans, and how many students overflow into the last one? Thinking: "how many fit" is //, "who's left over" is %. The two operators were made for each other.

2.3

Text vs numbers — the promised showdown

Read · ~4 minPractice · ~8 min

The problem. Unit 1 planted a flag: "7" and 7 look identical on screen but aren't the same thing. Time to cash that in — because a program that asks for a number and tries to do maths with the answer is about to get a surprise.

The idea, in plain words. Every value has a type — text (str), whole number (int), decimal (float) — and the type decides what an operator means. For numbers, + adds. For strings, + glues: "7" + "7" is "77", and "Hello, " + name is the no-gap gluing that Unit 1's P2 hinted at. Mix the two — "7" + 7 — and Python refuses with a TypeError: it won't guess whether you meant 14 or "77".

Here's the trap that catches every beginner: input() always hands back text. Type 25 at a prompt and the box holds "25" — characters, not a number. Before doing maths, convert: int("25") → 25, or float("4.5") → 4.5. (And str(25) goes the other way when you need it.) Curious what a box holds? type(x) tells you — it's the first question to ask when maths misbehaves.

Trace it by hand — the same key, two doors
age = input("Age? ") # types 25 → box holds "25" (text!) next_year = int(age) + 1 print("Next year:", next_year)

Line 1: the box age holds the string "25" — two characters.

Line 2: right side first: int(age) reads the box, converts "25" → 25 (a real int), adds 1 → 26. Stored into next_year. The box age still holds "25" — conversion made a new value, it didn't change the box.

Age? 25 Next year: 26

Skip the int() and line 2 dies with TypeError: can only concatenate str (not "int") to str — Python telling you it found glue-plus and maths-plus in the same expression.

Key idea
The type decides what the operator means. + adds numbers but glues strings; input() always returns a string; int() / float() convert before maths. Half of all beginner bugs live in this box.
Worked example

Task: ask for two numbers and print their real sum — not their gluing. Thinking: convert at the door: wrap each input() in int() immediately, so everything downstream is honest arithmetic. Inputs here are fixed to 8 and 5.

2.4

f-strings — sentences without the scaffolding

Read · ~3 minPractice · ~8 min

The problem. Building sentences from boxes keeps forcing a choice between two clunky tools: commas (which insert spaces you didn't ask for) and gluing (which demands str() around every number). There has to be a way to just… write the sentence.

The idea, in plain words. There is, and it's Python at its most pleasant. Put an f in front of the opening quote and the string becomes a template: anything inside curly braces { } is filled in from your boxes, exactly where you wrote it.

print(f"Hello, {name} from {city}!")

No commas, no gluing, no str() — numbers convert themselves, spaces and punctuation land precisely where you typed them. The f stands for formatted, and it has one more gift: put :.2f after a box name — {price:.2f} — and the number is written with exactly two decimal places. That's money formatting, and the build below runs on it.

Trace it by hand — one template, filled in
name = "Ada" each = 106.666666 print(f"{name} pays {each:.2f} rupees")

Line 3: Python walks the template left to right: {name} → box contents Ada; the literal text stays put; {each:.2f} → 106.666666 written to two decimals → 106.67 (it rounds, not chops):

Ada pays 106.67 rupees
Common confusion

Forgot the f? Then print("Hello, {name}") prints the braces literally: Hello, {name}. No error, just a template nobody filled in. If you ever see your curly braces on screen, the missing f is the culprit — every time.

Worked example

Task: reprint 2.3's stretch — Score: 95! — the modern way, then a price line with clean decimals. Thinking: write the sentence as you want it to appear; drop boxes in braces where values go.

2.4 · P1Rewrite with f-strings

Rewrite this comma-and-glue mess as one f-string print that produces the goal exactly — note the no-space ! that commas can't do.

Ada scored 95 in Python!
Show solution
name = "Ada"
marks = 95
subject = "Python"
print(f"{name} scored {marks} in {subject}!")

The sentence reads like a sentence, and punctuation obeys you instead of the comma rule.

2.4 · P2Two decimals, always

A shop wants every price shown with two decimals. Print both prices using :.2f to match the goal — one gets padded, one gets rounded.

Tea: 12.00 Cake: 45.68
Show solution
tea = 12
cake = 45.678
print(f"Tea: {tea:.2f}")
print(f"Cake: {cake:.2f}")

:.2f means "as a decimal number, two places": 12 becomes 12.00, and 45.678 rounds to 45.68.

2.4 · P3Stretch — why money needs :.2f

Run this and look closely at the first line. Then fix the print with :.2f so it shows the goal. (The read below the solution explains the weirdness — it isn't a bug in your code.)

Total: 0.30
Show solution & the why
total = 0.1 + 0.2
print(f"Total: {total:.2f}")

The raw print shows 0.30000000000000004. Computers store decimals in binary, and 0.1 in binary is a repeating fraction — like ⅓ in decimal — so a microscopic rounding error rides along. Every language has this; professionals format money to fixed decimals for exactly this reason. Now you do too.

2.5

Your build — the tip calculator

Read · ~2 minPractice · ~10 min

Everything from this session, one real program: ask for the bill, the tip percentage, and how many people are splitting; compute the tip, the total, and each person's share; print money like money. That's input() + int(), three arithmetic lines, and f-strings with :.2f. Build it in two stages.

2.5 · P1Stage 1 — bill and tip

Ask Bill amount? and Tip percent? (convert both at the door), compute the tip as bill * tip_percent / 100 and the total, and print both with :.2f. Inputs fixed: 1200, then 10.

Bill amount? 1200 Tip percent? 10 Tip: 120.00 Total: 1320.00
Show solution
bill = int(input("Bill amount? "))
tip_percent = int(input("Tip percent? "))
tip = bill * tip_percent / 100
total = bill + tip
print(f"Tip: {tip:.2f}")
print(f"Total: {total:.2f}")

The division by 100 makes tip a float (120.0), and :.2f dresses it as money.

2.5 · P2Stage 2 — split it

Extend Stage 1: also ask How many people? and print each person's share of the total. Inputs fixed: 1200, 10, 4. Paste your Stage 1 code and grow it — that's how real programs are built.

Bill amount? 1200 Tip percent? 10 How many people? 4 Tip: 120.00 Total: 1320.00 Each pays: 330.00
Show solution
bill = int(input("Bill amount? "))
tip_percent = int(input("Tip percent? "))
people = int(input("How many people? "))
tip = bill * tip_percent / 100
total = bill + tip
each = total / people
print(f"Tip: {tip:.2f}")
print(f"Total: {total:.2f}")
print(f"Each pays: {each:.2f}")

Ask → convert → compute → format. This four-beat shape is most of practical programming; you'll recognise it in every unit from here on.

2.5 · P3Stretch — make it yours

Unlock the input field (it's editable here), try your own bill, an awkward head-count like 3, a 12% tip. Watch :.2f keep the output civilised however messy the division gets. No check — this one's for the feel of it.

2.6

Problem bank — everything at once

Practice · ~12 min

The mixed set. Boxes, all seven operators, conversions, f-strings — in combinations. In order; they get meaner.

B1The swap

Make the two boxes trade contents, using a third box as a temporary shelf, so the print matches the goal. (Changing the first two lines is cheating.)

tea coffee
Show solution
a = "coffee"
b = "tea"
temp = a
a = b
b = temp
print(a, b)

Store a's contents on the shelf before overwriting — otherwise "coffee" is gone forever. A classic that interviews still ask.

B2Digits of a number

For any two-digit number in the box, print its tens digit and ones digit using only // and %. Goal shown for 74.

Tens: 7 Ones: 4
Show solution
n = 74
print("Tens:", n // 10)
print("Ones:", n % 10)

Dividing by 10 shifts a digit off the end; the remainder is the digit that fell off. This trick scales to any base and returns in the ML stage.

B3Minutes, humanised

Ask Minutes? , convert, and report hours and minutes using // and % in one f-string. Input fixed to 175.

Minutes? 175 That is 2 h 55 min
Show solution
minutes = int(input("Minutes? "))
print(f"That is {minutes // 60} h {minutes % 60} min")

Whole hours by //, leftover minutes by % — and yes, expressions can live right inside the braces.

B4Stretch — the fuel-cost estimator

Trip of 380 km, mileage 18.5 km per litre, petrol at 102.40 per litre — all as boxes. Litres needed is distance ÷ mileage; cost is litres × price. Print both to two decimals.

Litres: 20.54 Cost: 2103.35
Show solution
distance = 380
mileage = 18.5
price = 102.40
litres = distance / mileage
cost = litres * price
print(f"Litres: {litres:.2f}")
print(f"Cost: {cost:.2f}")

Note the display rounds (20.54) but the box keeps full precision (20.5405…), so the cost is computed from the honest number, not the rounded one. Format at the exit, never in the middle.
