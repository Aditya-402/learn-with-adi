2.1

Labelled boxes

Read · ~2 minPractice · ~8 min

Let's try to understand where a program keeps what it knows.

In Unit 1 you typed your name and used it a line later. It waited somewhere in between, right? Where?

Think of your kitchen shelf. Sugar goes into a dabba with a paper label on it. Nobody opens all six later — they read the label.

Python does the same. price = 40 takes a box, labels it price, puts 40 inside. After that, price means what is in that box.

  • Read = as "store into", not "equals". Right side first, then into the box on the left. So count = count + 1 means: old contents plus one, back in.
  • A box holds one thing. Something new goes in, the old is gone.
  • The label is exact. price and Price are different boxes. No spaces, no leading digit.

That labelled box is what we call a variable.

The form
price = 40 # a box labelled price, holding 40 city = "Chennai" # text keeps its quotes print(price) # no quotes — read the box back

Label on the left, contents on the right.

One box, four lines
  1. score = 10Holds 10.
  2. score = score + 5Right side first: 10 + 5 is 15, back into the same box. The 10 is gone.
  3. bonus = scoreA new box gets a copy. Two boxes now.
  4. print(score, bonus)Both read back, one space at the comma.
What you should see15 15
Fig. 1 — Memory after lines 1, 2 and 3. Keep it in your head as you read code.
Careful here

= is not school's equals sign. It is an arrow pointing left: right side worked out, stored into the left. Read count = count + 1 as "new count = old count + 1".

Now you run it

A game gives 10 points, doubles it, adds 3. Say the answer before pressing Run.

2.2

Numbers & arithmetic

Read · ~3 minPractice · ~10 min

A box that only stores is a shelf. Let's make it earn something.

Think of a shop bill. Three samosas at fifteen, two teas at twelve, add it up, split it two ways. All of that is arithmetic.

Python has two kinds of number. A whole number — 4 — we call an int. One with a decimal point — 4.5 — we call a float.

Think of measuring cups. Whole cups are ints, the marks between them are floats.

Seven operators work on both:

operatordoesexamplegives
+ - *add, subtract, multiply4 * 520
/divide — always a float10 / 42.5
//divide, keep the whole part10 // 42
%what is left over10 % 42
**power2 ** 38

// and % are a pair. Ten sweets, four children: 10 // 4 says each gets 2, 10 % 4 says 2 stay in your hand.

Order is the same as school, and brackets beat everything. 2 + 3 * 4 is 14, but (2 + 3) * 4 is 20. When in doubt use brackets — they cost nothing.

The form
bill = 3 * 15 + 2 * 12 # right side worked out first, then stored each = bill / 2 # divide — always a decimal point

The right side finishes before anything reaches the box.

A real bill, line by line
  1. samosas = 3 * 1545 into the box.
  2. tea = 2 * 1224 into a second box.
  3. bill = samosas + tea45 + 24 is 69.
  4. print(bill, bill / 2)The bill, then a two-way split. Look hard at it.
What you should see69 34.5
Careful here

Why does 10 / 2 print 5.0 and not 5? Because / always gives a float. Python will not switch the kind of answer just because a division came out clean. Want the whole number? Use //.

Now you run it

47 students, each van seats 12. How many full vans, and how many spill into the last one? "How many fit" is //, "who is left over" is %.

2.3

Text vs numbers

Read · ~3 minPractice · ~8 min

Unit 1 left you with one line: quoted is repeated, unquoted is understood. Today it comes back with a bill.

Text is a str, a whole number an int, a decimal number a float. We call this kind its type.

And here is the point. The type decides what an operator means.

For numbers, + adds. For text, + glues. So 7 + 7 is 14, but "7" + "7" is "77". Mix the two and Python refuses to guess.

Now the trap. It catches everybody, exactly once.

The form
7 + 7 # 14 — two numbers, added "7" + "7" # 77 — two pieces of text, glued "7" + 7 # TypeError — Python will not guess which one you meant

To cross over, convert: int("25") gives the number, str(25) the text.

Careful here — this one catches everybody

input() always hands back text. Always. Somebody types 25 and the box holds "25" — two characters, not a number. Add 3 and the program dies with a TypeError. The most common beginner bug in Python, and the fix is one word wide.

The fix — convert at the door
  1. age = int(input("Age? "))Ask, wait, convert straight away. The box holds the number 25, not the text "25".
  2. print("Next year:", age + 1)Honest arithmetic now. 25 + 1.
What you should seeAge? 25 Next year: 26

Drop the int() and line 2 dies with TypeError: can only concatenate str (not "int") to str — glue-plus and maths-plus in the same breath.

Not sure what a box holds? type(x) tells you — ask that first whenever arithmetic misbehaves.

Key idea
The type decides what the operator means. input() always gives you text, so convert at the door with int() before any maths. Half the bugs of your first month live here.
Now you run it

Ask for two numbers and print their real sum, not their gluing. Each input() goes straight into int(). Inputs: 8 and 5.

2.4

f-strings — just write the sentence

Read · ~2 minPractice · ~8 min

So far, building a sentence out of boxes has meant choosing between two annoying tools. Commas put spaces where you did not ask for them. Gluing makes you wrap every number in str().

Surely there is a way to just write the sentence, right?

There is, and it is Python at its most pleasant. Put an f in front of the opening quote. The string becomes a template. Anything inside curly braces gets filled in from your boxes, exactly where you wrote it.

No commas. No gluing. No str() — numbers convert themselves. Spaces and punctuation land precisely where you typed them.

The f stands for formatted, and formatting is the second gift. Put :.2f after a box name and the number is written with exactly two decimal places. That is money. The build below runs on it.

The form
f"Hello, {name} from {city}!" # the box contents drop in, right there f"Price: {price:.2f} rupees" # same, written with exactly two decimals

The f sits outside the quote. The box label sits inside the braces.

One template, filled in
  1. name = "Ada"Text in a box.
  2. each = 106.666666A long, ugly number in another box.
  3. print(f"{name} pays {each:.2f} rupees")Python walks the template left to right. {name} becomes Ada. The plain words stay put. {each:.2f} becomes 106.67 — it rounds, it does not chop.
What you should seeAda pays 106.67 rupees
Careful here

Forgot the f? Then print("Hello, {name}") prints the braces just as they are: Hello, {name}. No error, just a template nobody filled in. If you ever see curly braces on your screen, the missing f is the reason. Every single time.

Now you run it

Print 2.3's Score: 95! the modern way, and a price line with clean decimals. Write the sentence the way you want to read it. Then drop the boxes into braces where the values belong.

2.4 · P1Rewrite with f-strings

Rewrite this comma-and-glue mess as one f-string print.

Ada scored 95 in Python!
Show solution

marks = 95

print(f"{name} scored {marks} in {subject}!")

Now the sentence reads like a sentence, and the punctuation obeys you instead of the comma rule.

2.4 · P2Two decimals, always

A shop wants every price shown with two decimals. Print both using :.2f. One gets padded, one gets rounded.

Tea: 12.00 Cake: 45.68
Show solution
tea = 12
cake = 45.678
print(f"Tea: {tea:.2f}")
print(f"Cake: {cake:.2f}")

:.2f means: as a decimal number, two places. So 12 becomes 12.00 and 45.678 rounds to 45.68.

2.4 · P3Stretch — why money needs :.2f

Run it and look hard at the first line. Then fix the print with :.2f. The weirdness is not your fault.

Total: 0.30
Show solution & the why
total = 0.1 + 0.2
print(f"Total: {total:.2f}")

0.1 in binary repeats forever, the way one-third repeats in decimal, so a microscopic error rides along. Every language has this — which is why money gets fixed decimals.

2.5

Your build — the tip calculator

Read · ~1 minPractice · ~12 min

Time to put the whole session into one program.

You are at a restaurant with three friends. The bill arrives. Somebody wants to add a tip, and everybody has to pay their share. That is your program. Ask for the bill, the tip percent, and how many people. Work out the tip, the total, and each person's share. Print money like money.

That is input() with int(), three lines of arithmetic, and f-strings with :.2f. Nothing new. Build it in two stages, the way real programs get built.

2.5 · P1Stage 1 — bill and tip

Ask Bill amount? and Tip percent? , converting at the door. Tip is bill * tip_percent / 100.

Bill amount? 1200 Tip percent? 10 Tip: 120.00 Total: 1320.00
Show solution
bill = int(input("Bill amount? "))
tip_percent = int(input("Tip percent? "))
tip = bill * tip_percent / 100
total = bill + tip
print(f"Tip: {tip:.2f}")
print(f"Total: {total:.2f}")

Dividing by 100 makes tip a float, 120.0. Then :.2f dresses it up as money.

2.5 · P2Stage 2 — split it

Now grow it. Also ask How many people? and print each share. Paste your Stage 1 code and add to it.

Bill amount? 1200 Tip percent? 10 How many people? 4 Tip: 120.00 Total: 1320.00 Each pays: 330.00
Show solution
bill = int(input("Bill amount? "))
tip_percent = int(input("Tip percent? "))
people = int(input("How many people? "))
tip = bill * tip_percent / 100
total = bill + tip
each = total / people
print(f"Tip: {tip:.2f}")
print(f"Total: {total:.2f}")
print(f"Each pays: {each:.2f}")

Ask, convert, compute, format. That four-beat shape is most of practical programming.

2.6

Problem bank

Practice · ~12 min

Nothing new here. Boxes, all seven operators, converting, f-strings — mixed together. Do them in order. They get meaner.

B1The swap

Make the two boxes trade contents. Use a third box as a temporary shelf. Changing the first two lines is cheating.

tea coffee
Show solution
a = "coffee"
b = "tea"
temp = a
a = b
b = temp
print(a, b)

Shelf the contents before overwriting, or "coffee" is gone for good.

B2Digits of a number

Print the tens digit and the ones digit using only // and %.

Tens: 7 Ones: 4
Show solution
n = 74
print("Tens:", n // 10)
print("Ones:", n % 10)

Dividing by 10 pushes a digit off; the remainder is the digit that fell off.

B3Minutes, humanised

Ask Minutes? , convert, and report hours and minutes using // and % inside one f-string. Input is fixed to 175.

Minutes? 175 That is 2 h 55 min
Show solution
minutes = int(input("Minutes? "))
print(f"That is {minutes // 60} h {minutes % 60} min")

Whole hours from //, leftover minutes from %. And yes — a whole calculation can live inside the braces.

B4Stretch — the fuel-cost estimator

A 380 km trip, 18.5 km per litre, petrol at 102.40. Litres is distance ÷ mileage; cost is litres × price.

Litres: 20.54 Cost: 2103.35
Show solution
distance = 380
mileage = 18.5
price = 102.40
litres = distance / mileage
cost = litres * price
print(f"Litres: {litres:.2f}")
print(f"Cost: {cost:.2f}")

The display rounds, the box keeps 20.5405… Format at the exit, never in the middle.
