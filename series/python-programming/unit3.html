3.1

True/False & the six comparisons

Read · ~4 minPractice · ~10 min

The problem. Every useful program keeps asking yes/no questions. Is the bill over budget? Did the password match? Has the guess found the secret? Before a program can act on a question, it needs a way to ask one — and something to hold the answer.

The idea, in plain words. Python has a third kind of value beside numbers and text: the boolean (bool), and it has exactly two members — True and False, capitalised, no quotes. They're the answers to yes/no questions, and the questions are asked with six comparison operators:

operatorasksexampleanswer
==equal?7 == 7True
!=not equal?7 != 7False
<less than?3 < 7True
>greater than?3 > 7False
<=at most?7 <= 7True
>=at least?6 >= 7False

A comparison is an expression like any other — it produces a value, and the value goes wherever values go: into a print, into a box, or (from 3.2 onward) into an if. Strings compare happily too: guess == "mango" is a perfectly good question, and it's answered character by character, case and all — "Yes" == "yes" is False, Unit 1's case-sensitivity striking again. And the type rules from Unit 2 still reign: "7" == 7 is False — a string of one character and a number are simply not the same thing, however alike they look on screen.

Trace it by hand — three questions, three answers
age = 20 print(age >= 18) print(age == 21) print("7" == 7)

Line 1: box age holds 20.

Line 2: the question "is 20 at least 18?" — yes:

Line 3: "is 20 exactly 21?" — no. Line 4: a string versus an int — never equal, whatever the characters say:

True False False
Common confusion

Unit 2 planted this and here's the payoff: = stores, == asks. x = 5 puts 5 in the box; x == 5 looks in the box and answers True or False, changing nothing. Write = where a question belongs and Python usually stops you with a SyntaxError; write == where a store belongs and — worse — nothing happens at all: the question is asked, answered, and the answer thrown away. One symbol stores, two symbols ask. Say it until it's boring.

Worked example

Task: a clinic flags a fever. Ask three questions about a temperature reading and print all three answers. Thinking: comparisons are just expressions — print them like anything else, or store them in boxes first. Predict all three before running.

3.2

if / else — the fork in the road

Read · ~4 minPractice · ~10 min

The problem. You can now ask questions and see the answers — but nothing changes. A program that prints False and carries on regardless is a spectator. We want: if the marks clear the bar, say pass; otherwise, say fail. Different runs, different behaviour.

The idea, in plain words. The if statement is a fork in the road. Our literal-minded kitchen helper reaches it, evaluates the question, and takes exactly one of the two paths:

if marks >= 35:
    print("Pass")
else:
    print("Fail")

Two pieces of syntax carry all the weight:

  • The colon at the end of the if line (and the else line) says "a block of lines belongs to me". Forget it and Python stops with a SyntaxError pointing at the line end.
  • The indentation — the four spaces — is not decoration. In Python, indentation IS the syntax that says "these lines are inside the branch". Everything indented under the if runs only when the answer is True; everything under else runs only when it's False; and the first line back at the left margin runs either way, because it's after the fork, not inside it.

Mis-indent and you meet a new error report: IndentationError. Read it like every other report — last line first — and it tells you Python expected a block and didn't find one, or found spaces it can't make sense of. It feels fussy for a week; then your eyes start reading indentation as structure, which is exactly what Python's designers intended. Use 4 spaces, always — pick it and never think about it again. One more thing: else is optional. An if alone means "do this extra thing when true; otherwise just carry on".

Trace it by hand — one run, one road
marks = 52 if marks >= 35: print("Pass") else: print("Fail") print("Done")

Line 1: box marks holds 52.

Line 2: the question: is 52 at least 35? True — so the helper steps into the indented block below the if.

Line 3: prints Pass. Lines 4–5: the entire else block is skipped — not run slowly, not run quietly; never looked at.

Line 6: back at the left margin — after the fork, so it runs on every run:

Pass Done
Fig. 1 — One run, one road. The two branches both exist in the code, but each run of the program travels exactly one of them, and the roads rejoin at the first unindented line.
Common confusion

Beginners often expect Python to notice a "nearly indented" line. It won't. print("Pass") flush against the left margin directly after if marks >= 35: is an IndentationError: expected an indented block — Python was promised a block by the colon and got none. And a line accidentally indented where no block was opened is an error too. Indentation is a statement about structure, and Python holds you to it — which is precisely why Python programs are so readable.

Worked example

Task: a wallet check before buying: if the price fits the balance, approve; otherwise say exactly how short we are. Thinking: one comparison, two roads — and the else road computes with the same boxes, f-string at the exit. Change price to 300 and re-run to travel the other road.

3.3

elif — many branches, first True wins

Read · ~4 minPractice · ~10 min

The problem. Pass/fail is a two-way fork. But grades come in bands — A from 90, B from 75, C from 50, D below — and stacking whole if/else forks inside each other gets ugly fast. We want one clean structure that says "try this, else try this, else try this, else give up".

The idea, in plain words. That structure is elif — literally "else, if". It adds more doors to the fork, and the helper checks them top to bottom, taking the first one whose question answers True and skipping everything after it. The else at the bottom is the door for "none of the above".

The consequence is the rule this whole section exists to teach: order matters. Since 95 clears the bar for A, B and C, the ladder works only because the strictest band is asked first. Ask marks >= 50 first and every passing paper on earth gets a C — no error message, just confidently wrong grades. Python can't catch this one for you; only your ordering can.

Trace it by hand — down the ladder
marks = 78 if marks >= 90: grade = "A" elif marks >= 75: grade = "B" elif marks >= 50: grade = "C" else: grade = "D" print(f"Grade: {grade}")

Line 2: is 78 at least 90? False — door stays shut, move down.

Line 4: is 78 at least 75? True — in we go: grade now holds "B". And that's the ladder done: the >= 50 door (which 78 would also open) and the else are never looked at.

Line 10: back at the margin, the f-string reads the box:

Grade: B
Fig. 2 — The ladder is checked top to bottom and the first True door ends the whole affair. Everything below it is skipped, even doors the value could have opened.
Key idea
An if/elif/else ladder takes exactly one door per run: the first whose question is True, or else if none are. Order your questions from strictest to loosest, or the loose ones will steal every run.
Worked example

Task: a weather advisory in bands: 40+ heatwave, 30+ hot, 20+ pleasant, below that cool. Thinking: strictest first, one door per run. Try 43, 25 and 12 in the box and watch a different door open each time.

3.4

and / or / not — combining questions

Read · ~3 minPractice · ~10 min

The problem. Real rules rarely ask one question. A club admits you if you're 18 and holding a ticket. A shop gives the discount if the bill is big or it's Tuesday. "Working age" means at least 18 and at most 60. One comparison can't say any of that.

The idea, in plain words. Three little words weld questions together, and they mean exactly what they mean in English:

  • a and b — True only when both sides are True. One False anywhere sinks it.
  • a or b — True when either side is (or both). Only two Falses make it False.
  • not a — flips the answer: not True is False.

So a range check reads almost like prose: age >= 18 and age <= 60. Python even lets you chain the comparisons the way maths writes them — 18 <= age <= 60 means the same thing and is perfectly good style. Combined questions produce ordinary True/False values, so they slot straight into if, into prints, into boxes — everywhere a lone comparison goes.

Trace it by hand — the discount rule
age = 66 member = age >= 60 big_bill = 480 >= 1000 if member or big_bill: print("Discount applies") else: print("Full price")

Line 2: is 66 at least 60? True — box member holds True. (Booleans live in boxes as happily as numbers do.)

Line 3: 480 against 1000 — box big_bill holds False.

Line 4: True or False — or needs only one — True. Into the first branch:

Discount applies
Common confusion

The English shortcut "age is at least 18 and at most 60" tempts everyone to type age >= 18 and <= 60 — a SyntaxError. Each side of and must be a complete question: age >= 18 and age <= 60, naming the box both times. (Or sidestep it entirely with the chain 18 <= age <= 60.)

Worked example

Task: a shop discounts 10% when the bill is 1000+ or it's Tuesday. Thinking: one or in the condition, then Unit 2 does the rest — arithmetic in the branch, :.2f at the exit. Try changing the day to "friday" and the bill to 800: which road now?

3.5

Your build — two little deciders

Read · ~2 minPractice · ~12 min

Two complete programs, everything from this session in play. First, a guessing game with a secret number and one shot at it — comparisons and a three-door ladder. Second, the classic bouncer: two questions at the door, and both answers must satisfy. Ask → convert → decide → reply: the Unit 2 four-beat, with a fork where "compute" used to be.

3.5 · P1Guess my number, v1

The secret is hard-coded: 7. Take one guess with int(input("Your guess? ")) and reply Too low!, Too high! or Correct! — a three-door ladder. The guess here is fixed to 4; make sure your ladder would answer 9 and 7 correctly too.

Your guess? 4 Too low!
Show solution
secret = 7
guess = int(input("Your guess? "))
if guess < secret:
    print("Too low!")
elif guess > secret:
    print("Too high!")
else:
    print("Correct!")

Three doors cover every possible int, so else can safely mean "equal". One guess per run is annoying, isn't it? Unit 4 fixes exactly that.

3.5 · P2The bouncer

Two questions at the door: Age? (convert!) and Ticket? (yes/no) . Entry only if age is at least 18 and the ticket answer is exactly yes — reply Come on in. or No entry. Inputs fixed: 19, then yes. Then unlock nothing — just re-read your condition and convince yourself a 17-year-old with a ticket, and a 30-year-old without one, are both turned away.

Age? 19 Ticket? (yes/no) yes Come on in.
Show solution
age = int(input("Age? "))
ticket = input("Ticket? (yes/no) ")
if age >= 18 and ticket == "yes":
    print("Come on in.")
else:
    print("No entry.")

Note what stays text and what converts: age does maths, so it's int() at the door; the ticket answer is compared as a string, so it stays as it came. and makes one False anywhere enough to refuse.

3.6

Problem bank — everything at once

Practice · ~12 min

The mixed set: comparisons, forks, ladders and welded questions — with Unit 2's arithmetic and f-strings pulling shifts. In order; they get meaner.

B1Even or odd

Unit 2's % operator, paid off: a number is even exactly when n % 2 == 0. Report the box's verdict in one f-string sentence as shown. (Check your code also gets 40 is even right.)

41 is odd
Show solution
n = 41
if n % 2 == 0:
    print(f"{n} is even")
else:
    print(f"{n} is odd")

The remainder after dividing by 2 is 0 for evens, 1 for odds — so the comparison n % 2 == 0 is the standard evenness question. You'll type it for the rest of your programming life.

B2Biggest of three

Three boxes; print the biggest with the label shown. You'll need and inside a ladder — the first door must establish that a beats both others.

Biggest: 67
Show solution
a = 23
b = 67
c = 41
if a >= b and a >= c:
    print(f"Biggest: {a}")
elif b >= c:
    print(f"Biggest: {b}")
else:
    print(f"Biggest: {c}")

The second door doesn't need to re-check against a — reaching it already proves a lost. Each rung of a ladder inherits everything the rungs above ruled out.

B3The login check

The stored credentials are username adi, password mango42. Ask Username: and Password: , and greet with the f-string shown only if both match exactly; otherwise print Access denied. Inputs fixed to the right pair — but make sure a wrong password would be refused.

Username: adi Password: mango42 Welcome, adi!
Show solution
username = input("Username: ")
password = input("Password: ")
if username == "adi" and password == "mango42":
    print(f"Welcome, {username}!")
else:
    print("Access denied.")

String equality is exact — case, spaces and all — which is precisely what you want from a login. Real systems never store passwords in plain sight like this; that story comes much later.

B4Stretch — the shipping desk

Ask Weight in kg? (convert at the door) and quote shipping by band: up to 1 kg costs 50, up to 5 kg costs 90, up to 10 kg costs 150, heavier is Too heavy to ship. Input fixed to 7. Get the ladder direction right — which end is "strictest" here?

Weight in kg? 7 Shipping: 150
Show solution
weight = int(input("Weight in kg? "))
if weight <= 1:
    print("Shipping: 50")
elif weight <= 5:
    print("Shipping: 90")
elif weight <= 10:
    print("Shipping: 150")
else:
    print("Too heavy to ship")

With <= bands the smallest bound is strictest, so the ladder climbs upward: 7 walks past the 1 kg and 5 kg doors and opens the 10 kg one. Same first-True-wins rule as the grades, mirrored.
