3.1

True/False & the six comparisons

Read · ~2 minPractice · ~10 min

Let's try to understand how a machine decides anything.

Picture the invigilator at the exam hall door. He looks at your hall ticket. He asks one thing — is this name on my list? Yes, or no. There is no "maybe" column on that sheet.

Every decision a computer makes is that same yes-or-no.

So Python keeps two values for it. True and False. Capital letter, no quotes. That little pair has a name. We call it a boolean.

And how do we ask? With six symbols. We call these the comparison operators.

operatorasksexampleanswer
==equal?7 == 7True
!=not equal?7 != 7False
<less than?3 < 7True
>greater than?3 > 7False
<=at most?7 <= 7True
>=at least?6 >= 7False

A comparison is an expression, exactly like 2 + 3. It works out to a value. So the answer goes wherever a value goes — into a print, into a box, or into an if.

Text compares too, character by character, capitals and all. So "Yes" == "yes" is False. And "7" == 7 is False — one is a character, the other a number. They only look alike, right?

The form
left_value == right_value # a question, not a store 7 >= 5 # this whole line is worth True "Yes" == "yes" # and this one is worth False

No if yet. On its own, a comparison is simply a value.

Three questions, three answers
  1. age = 20The box age holds 20.
  2. print(age >= 18)20 clears 18, so True.
  3. print(age == 21)20 is not 21, so False.
  4. print("7" == 7)Text against a number: never equal, no error.
What you should seeTrue False False
Careful here

One symbol stores. Two symbols ask. x = 5 puts 5 into the box. x == 5 looks inside and answers True or False, changing nothing. Now the trap. Type == where you meant = and Python says nothing. The question is asked, answered, and thrown away. Your box never changed. A silent wrong answer is far worse than an error.

3.2

if / else — the fork in the road

Read · ~2 minPractice · ~10 min

You can ask questions now. But nothing changes because of the answer. The program prints False and carries on regardless. That is a passenger, not a driver.

Let's try to understand how it starts driving.

You are on the road to a place you have not been before. The road splits in two. You do not take both. You read the board, you decide, you take one. The other road still exists. You simply never see it today.

That is if and else. One question, two roads, one taken.

Two bits of punctuation carry all the weight here.

  • The colon at the end of the if line. It means "a block of lines belongs to me". Forget it and Python stops with a SyntaxError.
  • The indentation — those four spaces. This is not decoration. In Python the indentation is the syntax.

Now look at the indentation. Whatever sits inside the if — that runs only when the answer is True, right? Whatever sits under else runs only when it is False. Then you come back to the left margin. That line runs either way. Why? Because it is after the fork, not inside it.

Get the spacing wrong and you meet a new report: IndentationError. Read it the way you read every report. Last line first. It will tell you a block was promised and never arrived.

Use four spaces, always. Decide it once and never think about it again.

One more thing. The else is optional. An if standing alone means "do this extra bit when true, otherwise just carry on".

The form
if a_question_that_answers_True_or_False: this line is inside <- four spaces and this one too else: this runs when the answer is False back at the margin <- outside, runs either way

The colon opens the block. The indentation says what is inside it. The margin says you are out of it.

One run, one road — marks = 52
  1. marks = 52The box holds 52.
  2. if marks >= 35:52 clears 35, so take this road.
  3. print("Pass")Indented, so inside the if. It runs.
  4. else:The other road. Not needed today.
  5. print("Fail")Never even looked at.
  6. print("Done")Back at the margin, after the fork. Runs either way.
What you should seePass Done
Fig. 1 — One run, one road. Both branches exist in the code. Each run travels exactly one of them, and the roads rejoin at the first line back at the margin.
Careful here

Python will not notice a "nearly indented" line. Put print("Pass") flat against the margin right after if marks >= 35: and you get IndentationError: expected an indented block. The colon promised a block. Nothing came. A line indented where no block was opened is an error too. Fussy for a week, and then your eyes start reading structure straight off the page.

Now you run it

A wallet check before buying. If the price fits the balance, approve it. Otherwise say exactly how short we are. Then change price to 300 and run again — same code, other road.

3.3

elif — many branches, first True wins

Read · ~2 minPractice · ~10 min

Pass or fail is a two-way fork. But an exam result is not two-way, right? A from 90, B from 75, C from 50, D below that. Four doors, not two.

You could put forks inside forks. By the third one it is unreadable. Python gives us something cleaner: elif. Read it as "else, if".

Picture a corridor of doors. You knock on the first. Shut? Move to the next. The moment one opens, you walk in and the corridor is finished. The else at the end is the door marked "none of the above".

So exactly one branch runs. Every time. Never two.

Which brings us to the one rule this section exists for. Order matters.

A 95 clears 90, and 75, and 50 — all three. So the ladder works only because the strictest question sits at the top. Put marks >= 50 first and every passing paper in the country gets a C. Python will not complain. It will just be confidently wrong.

The form
if strictest_question: ... elif next_question: ... elif loosest_question: ... else: ... # none of the above

Checked top to bottom. The first True door wins, and everything below it is skipped.

Down the ladder — marks = 78
  1. marks = 78The box holds 78.
  2. if marks >= 90:78 misses 90. Door shut, move down.
  3. grade = "A"Skipped.
  4. elif marks >= 75:78 clears 75. This door opens.
  5. grade = "B"Runs. grade now holds "B".
  6. elif marks >= 50:Never checked. 78 would open it, but nobody knocks.
  7. grade = "C"Skipped.
  8. else:Never reached.
  9. grade = "D"Skipped.
  10. print(f"Grade: {grade}")Back at the margin. Reads what the open door stored.
What you should seeGrade: B
Fig. 2 — The ladder is checked top to bottom, and the first True door ends the whole affair. Everything below it is skipped, even doors the value could have opened.
Key idea
One run, one door. The first question that answers True wins, or else if none of them do. So ask the strictest question first, or a loose one will steal every run.
Now you run it

A weather advisory in bands. 40 and above is a heatwave, 30 is hot, 20 is pleasant, below that is cool. Try 43, then 25, then 12. A different door opens each time.

3.4

and / or / not — combining questions

Read · ~2 minPractice · ~10 min

Real rules rarely ask one thing.

Think of the security guard at an office gate. He wants two things — your ID card, and your name in his register. One of them is not enough. Both, or you wait outside.

A shop is the other kind of rule. Discount if the bill is big, or if it is a Tuesday. Either one will do.

Python has three words for exactly this, and they mean what they mean in English.

  • a and b — True only when both sides are True. One False sinks it.
  • a or b — True when either side is. Only two Falses make it False.
  • not a — flips the answer. not True is False.

So a range check almost reads like English: age >= 18 and age <= 60.

Python also lets you write it the way maths does. 18 <= age <= 60 means the same thing, and it is perfectly good style.

A welded question is still only True or False. So it fits anywhere a single comparison fits.

The form
if question_one and question_two: # both must be True if question_one or question_two: # either one will do if not question_one: # flips the answer

Each side of and or or must be a complete question on its own.

Two boxes, one gate — the discount rule
age = 66 member = age >= 60 big_bill = 480 >= 1000 if member or big_bill: print("Discount applies") else: print("Full price")

Line 2: is 66 at least 60? True. So the box member holds True. Booleans sit in boxes as happily as numbers do.

Line 3: 480 against 1000. The box big_bill holds False.

Line 4: so the question is True or False. And or needs only one. We take the first road:

Discount applies
Careful here

English lets you say "at least 18 and at most 60". Python does not. Type age >= 18 and <= 60 and you get a SyntaxError. Each side of and must be a whole question, so name the box both times: age >= 18 and age <= 60. Or dodge it with the chain, 18 <= age <= 60.

Now you run it

A shop gives 10% off when the bill is 1000 or more, or when it is Tuesday. One or in the condition, and Unit 2 does the rest. Change the day to "friday" and the bill to 800. Which road now?
