6.1

Labels instead of positions — the dictionary

Read · ~4 minPractice · ~9 min

The problem. Store three friends' phone numbers in a list and you can get them back — by slot number. But nobody thinks "Ravi is contact number 1". You think "Ravi". A real phone book looks things up by name. Lists can't do that; what can?

The idea, in plain words. A dictionary (type dict) is a box whose inner slots have name-tags instead of numbers. Each slot is a pair: a key (the tag) and a value (what's stored under it). You write one in curly braces, tag:value, comma-separated:

phone = {"Amma": "98450 11111", "Ravi": "72004 22222"}

Reading looks exactly like list indexing, except the square brackets take a key, not a position: phone["Ravi"] hands back "72004 22222". Ask for a tag that isn't there — phone["Zara"] — and Python stops with a KeyError. Same drill as always: read the error report's last line first; it names the missing key in quotes.

When you'd rather get a fallback than a crash, there's a politer reader: phone.get("Zara", "not saved") returns the value if the key exists, and your fallback if it doesn't. Nothing stops, nothing changes — .get() only looks.

When is a dict right and a list wrong? Ask how you'll look things up. Marks in the order students finished? Positions matter — list. Marks by subject name, a price by item, a number by person? You'll always arrive holding a name, never a slot number — dict. The container should match the question you'll ask it.

Trace it by hand — the tagged box
marks = {"maths": 82, "physics": 74} print(marks["maths"]) print(marks["chemistry"])

Line 1: box marks created. Inside it, two tagged slots: "maths" → 82, "physics" → 74.

Line 2: marks["maths"] — find the slot tagged "maths", hand over its contents: 82. Printed.

Line 3: no slot is tagged "chemistry". Python stops and reports — and the last line of the report names the culprit:

82 KeyError: 'chemistry'

Swap line 3 for print(marks.get("chemistry", 0)) and you get a calm 0 instead of a crash. Use [ ] when the key must be there, .get() when it merely might be.

Fig. 1 — Same three numbers, two containers. The list answers "what's in slot 1?"; the dict answers "what's Ravi's number?" — and the second is the question you actually have.
Key idea
A dict stores key → value pairs and fetches by key: d[key] crashes on a missing key (read the last line first), d.get(key, fallback) stays calm. Choose a dict whenever you'll look things up by name rather than by position.
Worked example

Task: a two-person phone book — look up someone who's saved, then someone who isn't, without crashing. Thinking: the sure lookup uses [ ]; the risky one uses .get() with a fallback. Run it, then break it: change the last line to phone["Zara"] and read the report's last line.

6.2

Growing and changing — a dict is alive

Read · ~3 minPractice · ~9 min

The problem. A phone book you can't add to is a museum piece. Real dicts start small and change constantly: new contacts arrive, numbers get corrected, old entries go. How do you edit a tagged box?

The idea, in plain words. With the same assignment you've used since Unit 2 — aimed at a slot instead of a whole box. phone["Zara"] = "99887 33333" means: find the slot tagged "Zara"; if there isn't one, create it; if there is, replace its contents. One syntax, both jobs. The rest of the toolkit is small:

you want toyou writenotes
add or updated[key] = valuecreates the slot, or replaces it
remove a pairdel d[key]KeyError if the tag isn't there
ask "is this tag here?"key in dTrue / False — checks keys, not values
count the pairslen(d)same len() as strings and lists

Old friends, new target: in and len() worked on lists in Unit 5 and they work here too — len() counts pairs, and in asks about keys only. "Ravi" in phone asks "is there a tag Ravi?", never "is Ravi's number in here somewhere?".

Trace it by hand — a stockroom's day
stock = {"pens": 10} stock["pencils"] = 25 stock["pens"] = 8 del stock["pencils"] print(len(stock), "pens" in stock)

Line 1: one tagged slot: "pens" → 10.

Line 2: no slot tagged "pencils" — so one is created: "pencils" → 25. Two pairs now.

Line 3: identical syntax, but "pens" already exists — so its contents are replaced: 10 becomes 8, no warning, the 10 is gone.

Line 4: the "pencils" pair is removed entirely — tag and all. One pair left.

Line 5: len(stock) → 1; "pens" in stock → True:

1 True
Common confusion

d[key] = value never asks whether the key exists — it creates or replaces, silently. Handy when adding a contact; heartbreaking when a typo like phone["ravi"] quietly creates a second entry next to phone["Ravi"] instead of updating the first (case-sensitivity, back again). When an update must hit an existing entry, check first: if key in d:.

Worked example

Task: a shopping cart's afternoon — one more soap, a brand-new shampoo, then abandon the soap entirely. Thinking: updating reads the old value first (cart["soap"] + 1 — the count = count + 1 pattern, aimed at a slot), adding uses the same =, and del takes the pair out. Predict both printed lines before you run.

6.3

Looping a dict — visiting every pair

Read · ~3 minPractice · ~9 min

The problem. Printing a phone book one lookup at a time means writing one line per contact — the Unit 2 count-up ache all over again. Unit 4's for loop cured that for lists. Does it work on tagged boxes?

The idea, in plain words. Yes — three ways, depending on what you want handed to you each time around:

  • for key in d: — the plain loop visits the tags: each pass, the loop box holds one key.
  • for value in d.values(): — just the contents, when you don't care whose they are (totals, averages).
  • for key, value in d.items(): — both at once. d.items() hands over each pair, and the two loop boxes before in catch the two halves — the tag lands in the first, the value in the second. This one you'll use most.

And in what order do the pairs arrive? Insertion order — the order the pairs were first added, exactly. Python promises this, these notes rely on it, and every checked problem below counts on it: add "tea" before "coffee" and the loop visits tea first, always.

Trace it by hand — both halves of each pair
marks = {"maths": 82, "physics": 74} for subject, score in marks.items(): print(subject, score)

Pass 1: the first-added pair arrives: subject holds "maths", score holds 82. The body prints them.

Pass 2: the next pair: subject → "physics", score → 74. Printed. No pairs left — the loop ends.

maths 82 physics 74
Key idea
for key, value in d.items(): is the workhorse — each pass fills both loop boxes from one pair, in insertion order. Plain for key in d: gives tags only; d.values() gives contents only.
Worked example

Task: print a café's menu board line by line, then the cost of ordering everything once. Thinking: the board needs both halves of each pair — .items() with an f-string. The total is Unit 4's accumulator pattern, fed by a dict loop instead of a list.

6.3 · P1Tags only

Print each country name on its own line — the plain dict loop, no .items() needed.

India Japan
Show solution
capitals = {"India": "New Delhi", "Japan": "Tokyo"}
for country in capitals:
    print(country)

Looping a dict directly visits its keys, in insertion order — India was added first, so India prints first.

6.3 · P2The stock report

One .items() loop, one f-string, and the report writes itself — match the goal exactly, colon and all.

pens: 10 pencils: 25
Show solution
stock = {"pens": 10, "pencils": 25}
for item, count in stock.items():
    print(f"{item}: {count}")

Each pass fills item with the tag and count with the value; the f-string lays them out with the colon where you typed it.

6.3 · P3Stretch — values only

Total the till: loop over just the prices with .values() and Unit 4's accumulator, then print the goal line.

Total: 55
Show solution
prices = {"idli": 10, "dosa": 30, "coffee": 15}
total = 0
for p in prices.values():
    total = total + p
print("Total:", total)

The item names never enter the loop — .values() hands over only the numbers, and the accumulator does what it's done since Unit 4.

6.4

Tuples & sets, briefly — two special-purpose boxes

Read · ~4 minPractice · ~8 min

The problem. Two jobs keep coming up that neither lists nor dicts fit well. One: a small fixed record — a point's x and y, a title and its year — that should never grow or shrink. Two: a pile of repeats — every visitor to a page — where you only care who, not how often. Python has a purpose-built container for each.

The idea, in plain words. A tuple is a list in parentheses that is frozen at birth: point = (3, 4). You can read slots (point[0]) but never append, remove or replace — try, and Python refuses. That's not a limitation, it's the feature: a tuple says "these travel together and nobody edits them". Its best trick is unpacking — x, y = point pours the two slots into two boxes in one line, the same both-at-once move that .items() loops use (each pair a loop hands you is, in fact, a tuple).

A set is a bag of values where duplicates simply don't exist — add something twice, it's in there once. The one-liner that earns sets their keep: set(some_list) collapses a repeat-riddled list into just the distinct values. But a set makes no promise about order — none, not insertion order, nothing. So these notes have a house rule: never print a raw set when the output must be exact — wrap it as sorted(the_set), which hands back an ordered list you can trust.

Trace it by hand — frozen at birth
point = (3, 4) x, y = point print(x + y) point.append(5)

Line 1: a two-slot tuple, sealed. Line 2: unpacking — x gets 3, y gets 4, one line, two boxes filled.

Line 3: 3 + 4 → 7, printed. Line 4: tuples don't have an append — Python refuses, and the last line of the report says exactly that:

7 AttributeError: 'tuple' object has no attribute 'append'
Common confusion

"My set prints in a weird order" — yes, and it always will: sets don't have an order, and what you see can differ between runs and machines. It's not a bug to fix, it's a promise Python never made. When order matters — printing, checking, comparing — convert first: sorted(my_set) gives a list, smallest first, same every time.

Worked example

Task: a page's visitor log, with repeats — how many distinct people came, and who were they? Thinking: set() deduplicates in one move; len() counts the survivors; and the printout goes through sorted() because of the house rule. Run it twice and notice the sorted line never wavers.

6.4 · P3Stretch — deduplicate and report

Collapse the repeats, print the distinct numbers in order, then the count — remember the house rule about raw sets.

[1, 2, 4] Distinct: 3
Show solution
raw = [4, 1, 4, 2, 1, 4]
distinct = set(raw)
print(sorted(distinct))
print("Distinct:", len(distinct))

set() keeps one of each; sorted() turns the orderless bag into a dependable list. Print the raw set instead and the check may fail on a different day — that's the whole point of the rule.

6.5

Your build — contact book & word counter

Read · ~2 minPractice · ~10 min

Two small programs, everything from this session. First, a contact book: starts with two saved contacts, takes a new one from the keyboard, looks one up, prints the lot — input(), create-by-assignment, [ ] lookup, and an .items() loop, in one program. We'll keep upgrading this little book in the units ahead as we learn better tools. Second, a word counter — the dict-accumulator pattern that, dressed up only slightly, is how the ML stage turns text into numbers. You're building it today with eight words.

6.5 · P1Contact book v1

Complete the program: ask New contact name? then Their number? , store the new pair, print Ravi's number by key, then print every contact as name: number via an .items() loop. Inputs fixed: Meera, then 99887 33333.

New contact name? Meera Their number? 99887 33333 Ravi's number: 72004 22222 All contacts: Amma: 98450 11111 Ravi: 72004 22222 Meera: 99887 33333
Show solution
contacts = {"Amma": "98450 11111", "Ravi": "72004 22222"}
name = input("New contact name? ")
number = input("Their number? ")
contacts[name] = number
print("Ravi's number:", contacts["Ravi"])
print("All contacts:")
for person, num in contacts.items():
    print(f"{person}: {num}")

The key line is contacts[name] = number — the key comes out of a box, not a quoted literal. No conversion needed: phone numbers are labels you never do maths on, so text is the honest type. Meera prints last because she was added last — insertion order, as promised.

6.5 · P2The word counter

Count how often each word appears. One new tool on loan from Unit 8: sentence.split() chops a string into a list of its words — "the cat sat" becomes ["the", "cat", "sat"]; that's all you need to know today. The counting line is the star: counts.get(word, 0) + 1 reads the word's current tally — 0 if it's new — adds one, and stores it back. Finish the program: count, then print each pair as word: n.

the: 3 cat: 1 sat: 1 on: 1 mat: 1 end: 1
Show solution
sentence = "the cat sat on the mat the end"
counts = {}
for word in sentence.split():
    counts[word] = counts.get(word, 0) + 1
for word, n in counts.items():
    print(f"{word}: {n}")

First time a word appears, .get() supplies 0 and the assignment creates its slot at 1; every repeat replaces the tally with one more — 6.2's create-or-replace doing honest work. Each word keeps the position of its first appearance, which is why the leads with 3. File this pattern away: counting things with a dict is half of early ML.

6.6

Problem bank — everything at once

Practice · ~12 min

The mixed set. Dicts, tuples, sets — plus loops, if, and input() from earlier units. In order; they get meaner.

B1The marks desk

Ask Subject? and print that subject's marks — or not taken for a subject that isn't in the dict, without crashing. Input fixed to biology.

Subject? biology not taken
Show solution
marks = {"maths": 82, "physics": 74, "chemistry": 91}
subject = input("Subject? ")
print(marks.get(subject, "not taken"))

The key arrives from the keyboard, so it might miss — exactly the case .get() exists for. Try unlocking nothing: with input fixed, ask yourself what maths would have printed instead.

B2Under fifty rupees

Print the name of every item costing less than 50, one per line, in the dict's own order — a loop over pairs with an if inside (Unit 3 meets 6.3).

pen eraser marker
Show solution
prices = {"pen": 10, "notebook": 60, "eraser": 5, "marker": 45}
for item, price in prices.items():
    if price < 50:
        print(item)

The loop tests the value but prints the key — you'll flip a dict this way constantly: "which names satisfy a condition on their numbers?". The notebook fails the test and is skipped.

B3The swap, the Pythonic way

Unit 2's B1 swapped two boxes with a third as a temporary shelf. Tuple unpacking retires the shelf: a, b = b, a builds the right side as a tuple first, then unpacks it into the left. Do the swap in one line — no third box.

tea coffee
Show solution
a = "coffee"
b = "tea"
a, b = b, a
print(a, b)

The right side b, a is bundled into a tuple before any storing happens, so neither value is lost mid-swap. Same interview classic as Unit 2 — now with the answer that makes interviewers smile.

B4Stretch — the visitor report

From the raw log: total visits, distinct visitors, then each distinct name on its own line — in sorted order, because the house rule doesn't bend for stretch problems.

Visits: 7 Unique visitors: 4 adi meera ravi zara
Show solution
log = ["adi", "meera", "adi", "zara", "ravi", "meera", "adi"]
people = set(log)
print("Visits:", len(log))
print("Unique visitors:", len(people))
for name in sorted(people):
    print(name)

Two len()s, two different questions: the list counts events, the set counts people. The sorted loop prints one name per line in an order the check can rely on.
