26.1

Keras: describe the model, don't assemble it

Read · ~4 minPractice · ~10 min

The problem. Unit 25's network was honest work: a class with __init__ and forward, then five lines of loop you typed yourself — zero the gradients, forward, loss, backward, step — wrapped in a for over epochs. Twenty-odd lines before anything learns. Most days you don't want to design a training loop. You want a perfectly ordinary network, trained on your perfectly ordinary data, before lunch. Is there a shorter way to say it?

The idea, in plain words. Keras is that shorter way, and its whole personality is in one sentence: you describe the model, you don't assemble it. Think of ordering a cake. PyTorch is the kitchen — you own the oven, the timings, every fold of the batter. Keras is the order form: three layers, this size, this icing, bake it twenty times. You still choose everything that matters about the cake; someone else owns the oven.

The description itself is a thing you already know intimately. keras.Sequential([...]) takes a list — square brackets, commas between items, order matters (Unit 5, cashing in properly at last). The list holds layers, and data flows through them top to bottom, in list order. Around that description sit exactly three verbs:

  • model.compile(optimizer=…, loss=…, metrics=…) — not "compile" in any scary sense. It's the settings form: how should it learn (the optimizer), what counts as wrong (the loss), and what should I be told as it goes (the metrics).
  • model.fit(X, y, epochs=…) — show it the examples, this many times over. Unit 25's entire five-line loop lives inside this one call.
  • model.evaluate(X, y) and model.predict(X_new) — how did it do, and what does it say about data it has never seen. That second one is scikit-learn's word, exactly (Unit 24), and that is not a coincidence.

Be clear-eyed about the trade, because it is a real one. Less to write, less to get wrong — and less control. When you need to do something the order form has no box for, you are writing PyTorch. That's the whole of 26.3, so hold the thought.

Read-only listing · Keras cannot run in this page ▶ Run this in Colab
import numpy as np
from tensorflow import keras
from tensorflow.keras import layers

# the data: 4 students, 2 features each, one 0/1 answer each
X = np.array([[1.0, 7.0], [2.0, 6.0], [4.0, 5.0], [5.0, 7.0]])
y = np.array([0, 0, 1, 1])

# 1. DESCRIBE the model - a LIST of layers
model = keras.Sequential([
    keras.Input(shape=(2,)),
    layers.Dense(8, activation="relu"),
    layers.Dense(1, activation="sigmoid"),
])

# 2. SET UP how it should learn
model.compile(optimizer="adam",
              loss="binary_crossentropy",
              metrics=["accuracy"])

# 3. SHOW it the examples, 200 times over
model.fit(X, y, epochs=200, verbose=0)

# 4. ASK: how did it do, and what about a new student?
loss, acc = model.evaluate(X, y, verbose=0)
print(f"loss {loss:.3f}  accuracy {acc:.2f}")
print(model.predict(np.array([[3.0, 6.0]]), verbose=0))
from tensorflow import keras — Keras ships inside TensorFlow. One install, two names; you'll see both spellings in the wild. keras.Input(shape=(2,)) — the doorway. It says only "each sample is 2 numbers wide"; the batch size is deliberately left out, because the model doesn't care how many rows you hand it. layers.Dense(8, activation="relu") — dense means every input connects to every one of the 8 outputs. Under the hood it is Unit 21's X @ W + b and nothing more exotic; the activation bends the result so the network can learn more than a straight line. layers.Dense(1, activation="sigmoid") — one output, squeezed into 0…1, which is how you say "a probability" for a yes/no question. model.compile(...) — three settings, no learning yet. optimizer is the step rule, loss is the scorer for wrongness, metrics is what gets reported to you. model.fit(X, y, epochs=200) — the whole of Unit 25's loop, folded into one line: 200 passes over the data, each one forward, loss, backward, step. verbose=0 only silences the progress bar. model.evaluate / model.predict — score on data, then answer about new data. predict returns an array of shape (1, 1) here — one row in, one probability out.
loss 0.284 accuracy 1.00 [[0.6127831]]
Fig. 1 — Keras doesn't remove the training loop; it removes you from the training loop. That's the deal in one picture: five lines you no longer type, and five lines you can no longer edit.
Common confusion

compile does not mean "translate my program into machine code", and it does not train anything. It's an unfortunate name for a settings form — three choices recorded and stored on the model, ready for fit. Nothing has learned a thing until fit runs.

Worked example

Task: see for yourself that a Dense layer is Unit 21's matrix arithmetic wearing a hat. Three samples with two features go in; a Dense(4) layer sends four numbers per sample out. Thinking: weights are a (features, units) block, biases are one per unit, and X @ W + b is the whole layer. This is also the unit's first NumPy run — give it ~15 seconds to fetch the library, once.

26.1 · P3Stretch — count the parameters

A Dense layer with n inputs and u units holds n * u weights plus u biases. Starting from 4 input features and the layer sizes [16, 8, 1], print each layer's parameter count and the total. Remember: each layer's output size becomes the next layer's input size.

Dense(16): 80 parameters Dense(8): 136 parameters Dense(1): 9 parameters Total: 225
Show solution
units = [16, 8, 1]
n_in = 4
total = 0
for u in units:
    params = n_in * u + u
    print(f"Dense({u}): {params} parameters")
    total = total + params
    n_in = u
print("Total:", total)

The line n_in = u is the whole idea of a stack: the shape flows forward. This is what model.summary() prints in Keras — and now you know it's arithmetic, not magic.

26.2

The three grammars, side by side

Read · ~4 minPractice · ~10 min

The problem. Five units of this Bridge have handed you three libraries that look nothing alike on the page. scikit-learn is two verbs. PyTorch is a class and a loop. Keras is a list and a settings form. It is entirely reasonable to feel you've learned three unrelated things and to dread learning a fourth. You haven't, and you needn't.

The idea, in plain words. They are three dialects of one sentence. Every one of them says: describe the model, show it examples, ask it about new data. Same three beats, every time. What changes between the libraries is only how much of the middle beat you write yourself — and that is a preference, not a different subject.

26.2 · P3Stretch — fake the progress bar

When Keras runs fit it prints one line per epoch. That printout is the best evidence that fit is a loop someone else wrote. Print it yourself from the losses below, four decimal places, then the closing line. Nothing here is machine learning — that's rather the point.

Epoch 1/3 - loss: 0.9124 Epoch 2/3 - loss: 0.5310 Epoch 3/3 - loss: 0.3078 Done - that printout is all fit() is hiding: a loop.
Show solution
losses = [0.9124, 0.5310, 0.3078]
for i, loss in enumerate(losses, start=1):
    print(f"Epoch {i}/3 - loss: {loss:.4f}")
print("Done - that printout is all fit() is hiding: a loop.")

enumerate(..., start=1) hands you the position and the value together, counting from 1 like humans do. And :.4f keeps 0.531 looking like 0.5310 — format at the exit, as ever.

26.3

Which one, when

Read · ~3 minPractice · ~7 min

The problem. Somebody will ask you, quite soon, "should we use PyTorch or Keras?" — and the internet will offer you a thousand confident, contradictory, slightly heated answers. You need a position that is honest, brief, and yours.

The idea, in plain words. Pick by the shape of the job, not by loyalty. Three rules of thumb cover almost everything you'll meet in your first year:

  • scikit-learn — for classic tabular work. Rows and columns in a spreadsheet, a few thousand of them, a number or a category to predict. Trees and linear models are often better here than a neural network, not merely easier, and they train in a blink. Reach for a network on tabular data only after a scikit-learn model has failed you.
  • Keras — when you want a standard network, fast. An ordinary stack of layers on images, text or numbers, no unusual training tricks. The order form fits the order; take the shortcut and spend the saved hour on the data instead, where it will do more good.
  • PyTorch — when you want to see and control every step. Anything unusual in the loop, anything from a recent paper, anything you need to debug from the inside. It is also, plainly, the language research is written in — which is why the whole of the modern LLM world is PyTorch.

And the honest footnote: it is not a marriage. The libraries share NumPy arrays as their common currency, so the pandas-and-NumPy work you did in Units 21–22 is the part that transfers everywhere, unchanged. Swapping libraries costs you an afternoon. Choosing wrong is not a catastrophe; refusing to start is.

The pointer worth writing down. When you finish the Machine Learning and Deep Learning stages and open the Build an LLM from Scratch series on this site — that series is written in PyTorch, in exactly Unit 25's vocabulary: tensors, autograd, nn.Module as a class, the five-line loop. Nothing further to learn before you start it. That was the plan all along.

Common confusion

"Keras is for beginners, PyTorch is for professionals" is folklore, and wrong in both directions. Keras runs in serious production at serious scale; PyTorch is the friendliest thing in the world once you've written the loop twice. The real axis isn't skill — it's how much of the loop this particular job needs you to control.

26.3 · P1The recommendation, as a function

Write pick(task) — a function (Units 8 & 19) that returns the library name for the three task descriptions below, then loop over them and print each verdict. Rules: "tabular" → scikit-learn; "standard network, fast" → Keras; anything else → PyTorch.

tabular -> scikit-learn standard network, fast -> Keras research -> PyTorch
Show solution
def pick(task):
    if task == "tabular":
        return "scikit-learn"
    elif task == "standard network, fast":
        return "Keras"
    else:
        return "PyTorch"

for t in ["tabular", "standard network, fast", "research"]:
    print(t, "->", pick(t))

The else catching everything unlisted is the honest default: when in doubt, the library that lets you look inside. Note the comma-print puts single spaces around the arrow for you.

26.3 · P2Stretch — a lookup with a humble default

Chains of elif grow ugly fast; a dictionary is the grown-up version. Use CHOICE.get(job, ...) so that jobs nobody listed get the sensible fallback text instead of a KeyError. Print one line per job, in the order given.

spreadsheet of customers: scikit-learn a new idea from a paper: PyTorch an LLM from scratch: PyTorch something nobody listed: read the docs, then pick
Show solution
for job in jobs:
    print(f"{job}: {CHOICE.get(job, 'read the docs, then pick')}")

.get(key, fallback) is the polite lookup: ask, and accept a default rather than crashing (Unit 10). Single quotes inside the f-string's double quotes — different quote characters, no clash.

26.4

Reading ML code in the wild

Read · ~3 minPractice · ~10 min

The problem. Nobody's real work begins with a blank file. It begins with somebody else's notebook — a GitHub repo, a Kaggle kernel, a colleague's forty lines with no comments — and the first two minutes decide whether you're useful or lost. There is a method for those two minutes, and it is embarrassingly mechanical.

The idea, in plain words. Don't read ML code top to bottom like prose. Read it as four questions, in this order, skimming for the answer to each:

  1. Which library? Look only at the imports. sklearn → scikit-learn. torch → PyTorch. keras or tensorflow → Keras. That one line tells you which grammar the rest of the file is written in, and therefore what to expect.
  2. Where does the data come in? Find read_csv, np.load, load_dataset, ImageFolder — and then find where X and y get made. Everything before that point is preparation; everything after it is modelling.
  3. Where is the model described? One line, usually: = SomeEstimator(...), or = Sequential([...]), or a class … (nn.Module). Its shape tells you what's being predicted — a final layer of 1 with sigmoid means yes/no, 10 with softmax means ten categories.
  4. Where does learning happen? Look for .fit(, or a for epoch in range(...). If there's no .fit and no epoch loop, nothing in that file is learning anything — it's loading a model somebody else trained.

Four questions, four answers, and you can now say what a file does even if half its lines are unfamiliar. Skipping the unfamiliar lines is allowed. It's the professional move, in fact — you go back for the details only once you know the shape.

Trace it by hand — four questions on eight lines
1 import numpy as np 2 from tensorflow import keras 3 X = np.load("features.npy") 4 y = np.load("labels.npy") 5 model = keras.Sequential([keras.layers.Dense(1, activation="sigmoid")]) 6 model.compile(optimizer="adam", loss="binary_crossentropy") 7 model.fit(X, y, epochs=5) 8 print(model.predict(X[:3]))

Q1 — which library? Line 2 says keras. So expect a list of layers, a compile, a fit. Confirmed by lines 5–7.

Q2 — where does the data come in? Lines 3–4: two arrays off the disk, already split into features and target. No cleaning at all — which tells you somebody else did the cleaning in an earlier file.

Q3 — where is the model described? Line 5. One Dense(1, activation="sigmoid"): a single probability out, so this is a yes/no question.

Q4 — where does learning happen? Line 7, and nowhere else. Line 6 only records settings; line 8 asks about the first three rows.

Total time: under a minute, and you can describe the file to somebody honestly:

"A Keras yes/no classifier on pre-prepared arrays, five epochs, then a peek at three predictions."
Common confusion

model.compile(...) and opt = optim.SGD(...) look like they're doing something. They aren't — they're arrangements. Learning happens only inside .fit( or inside an epoch loop. When you're skimming for "where does it learn", those setup lines are the most convincing decoys in the file.

26.4 · P3Stretch — label every line automatically

Turn the four questions into a scanner. For each line of the program below, decide its role — data (it loads or shapes data), describe (it creates the model), learn (it calls fit), ask (it calls predict), or setup (everything else) — and print role | line using a comma-print.

Show solution

    if "read_csv" in line or "to_numpy" in line:
        role = "data"
    elif "model =" in line:
        role = "describe"
    elif ".fit(" in line:

    elif ".predict(" in line:

    else:

Your build — everything up to the model

Read · ~2 minPractice · ~12 min

The exit exercise, and it comes in two halves — deliberately, because that split is the honest summary of where you now stand.

26.5 · P1Stage 1 — build the table, clean it

Five students: hours studied, hours slept, and whether they passed. One row has a missing value (that's what None becomes in a pandas column: NaN). Print the row count before and after dropping incomplete rows, then the surviving hours as a plain list.

26.5 · P2Stage 2 — features and target, shapes checked

The moment every library agrees on: a 2-D X of features and a 1-D y of answers, both as NumPy arrays. Make them from the clean table, then print the two shapes and the first row of X. Getting a habit of printing shapes here will save you hours later — mismatched shapes are the single most common error in all of ML.

X shape: (4, 2) y shape: (4,) first row of X: [1. 7.]
Show solution
X = df[["hours", "slept"]].to_numpy()
y = df["passed"].to_numpy()
print("X shape:", X.shape)
print("y shape:", y.shape)
print("first row of X:", X[0])

Double brackets for X because you're asking for a table of two columns; single for y because you want one column as a series. Hence (4, 2) against (4,) — and that lonely trailing comma is NumPy saying "one dimension, four items".

26.5 · P3Stage 3 — put the columns on the same scale

"Hours studied" runs 1–5, "hours slept" runs 5–7 — different ranges confuse most models, so the standard fix is to subtract each column's mean and divide by its standard deviation. Compute mean and std down the columns (axis=0), build the scaled Xs, and print the three values in the goal.

mean hours: 3.00 std hours : 1.5811 first scaled hours: -1.26
Show solution
mean = X.mean(axis=0)
std = X.std(axis=0)
Xs = (X - mean) / std
print(f"mean hours: {mean[0]:.2f}")
print(f"std hours : {std[0]:.4f}")
print(f"first scaled hours: {Xs[0][0]:.2f}")

axis=0 means "collapse the rows, keep the columns" — two means for two features. Then (X - mean) / std broadcasts the two-number row across all four rows at once (Unit 21). A first row of -1.26 means "1.26 standard deviations below average" — the same sentence now true of every column.

Half (b) · read-only listing · this runs in the notebook ▶ Run this in Colab
import pandas as pd
from tensorflow import keras
from tensorflow.keras import layers

# --- everything above the line is what you just did yourself ---
df = pd.DataFrame({
    "hours":  [1.0, 2.0, None, 4.0, 5.0],
    "slept":  [7.0, 6.0, 8.0, 5.0, 7.0],
    "passed": [0, 0, 1, 1, 1],
})
df = df.dropna()
X = df[["hours", "slept"]].to_numpy()
y = df["passed"].to_numpy()
X = (X - X.mean(axis=0)) / X.std(axis=0)
print("X", X.shape, " y", y.shape)

# --- and this is the next stage's subject ---
model = keras.Sequential([
    keras.Input(shape=(2,)),
    layers.Dense(8, activation="relu"),
    layers.Dense(1, activation="sigmoid"),
])
model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
model.fit(X, y, epochs=100, verbose=0)

loss, acc = model.evaluate(X, y, verbose=0)
print(f"loss {loss:.3f}  accuracy {acc:.2f}")

No Keras involved yet, and none needed. the handover — X and y are ordinary NumPy arrays. That's why the same two variables would feed scikit-learn or PyTorch without a single change. Arrays are the common currency of the entire field. lines 18–27 — describe, compile, fit, evaluate. Four calls. Everything that makes those four calls work — what a loss really measures, why 100 epochs and not 10, whether an accuracy of 1.00 on four rows means anything at all (it does not) — is the Machine Learning stage.

B1The dialect phrasebook

Ask Which library? and print how that library describes a model. The dictionary is written for you; the input is fixed to keras. Remember that the prompt and the typed answer share one output line.

Which library? keras Describe: model = Sequential([Dense(1)])
Show solution
lib = input("Which library? ")
print("Describe:", lines[lib])

Put the input() line after the dictionary — the name has to exist before you look anything up in it. Try torch in the notebook, where you can type whatever you like.

B2Shape check for a Dense layer

Five samples, three features, and a Dense(2) layer. Build the zero-filled arrays of the right shapes, compute out = X @ W + b, and print all four shapes plus the parameter count. If the shapes are wrong, NumPy will say so loudly — which is the point of the exercise.

X (5, 3) W (3, 2) b (2,) out (5, 2) params: 8
Show solution
X = np.zeros((n_samples, n_features))
W = np.zeros((n_features, units))
b = np.zeros(units)
out = X @ W + b
print(f"X   {X.shape}")
print(f"W   {W.shape}")
print(f"b   {b.shape}")
print(f"out {out.shape}")
print("params:", n_features * units + units)

The inner numbers have to touch: (5, 3) @ (3, 2) works because 3 meets 3, and what survives is (5, 2) — the outer pair. Samples in, samples out; features in, units out. That one rule explains most shape errors you will ever see.

B3From a table to arrays, with a made feature

Four houses, with a text column a model can't eat. Turn city into a 0/1 column called is_pune (comparing a column to a value gives True/False; .astype(int) turns those into 1/0), then build X from size and is_pune, and y from price. Print the shapes, the first row as a list, and the mean price.

X shape: (4, 2) y shape: (4,) first row: [800, 0] mean price: 58.25
Show solution
df["is_pune"] = (df["city"] == "Pune").astype(int)
X = df[["size", "is_pune"]].to_numpy()
y = df["price"].to_numpy()
print("X shape:", X.shape)
print("y shape:", y.shape)
print("first row:", X[0].tolist())
print("mean price:", y.mean())

Inventing a numeric column from a text one is called feature engineering, and it's most of the craft. .tolist() is used only so the row prints with its commas — NumPy's own printing pads columns, which is lovely on screen and awkward in a checker.

B4Stretch — build your own Sequential

The finale, and it uses nothing but Unit 5 lists, Unit 10 dictionaries and Unit 8 functions. Write summary(layers, n_in) which walks a list of layer dictionaries and prints one line per layer — position, kind, units, activation and parameter count — then the total and the final output size. You are writing model.summary(). It really is this.

1. Dense(32, relu) -> 288 params 2. Dense(16, relu) -> 528 params 3. Dense(3, softmax) -> 51 params Total params: 867 Output size: 3
Show solution
def summary(layers, n_in):
    total = 0
    for i, layer in enumerate(layers, start=1):
        u = layer["units"]
        p = n_in * u + u
        print(f"{i}. {layer['kind']}({u}, {layer['activation']}) -> {p} params")
        total = total + p
        n_in = u
    print(f"Total params: {total}")
    print(f"Output size: {n_in}")

A model description is a list of dictionaries and a rule for how shapes flow through it. Everything Keras adds on top — the actual numbers, the gradients, the GPU — is machinery around this idea, not a replacement for it. If this function makes sense to you, Sequential holds no mystery.
