The shape of the whole thing

A GPT is large, but it isn't complicated — because almost all of it is one block repeated. The entire 124-million-parameter GPT-2 is described by seven settings:

Why GPT-2 and not GPT-3

Architecturally they're the same thing; GPT-3 is GPT-2 scaled from 1.5 billion to 175 billion parameters. But OpenAI released GPT-2's weights, so we can load real pretrained values into our own code in Unit 7. GPT-3 also isn't runnable on a laptop — one estimate puts training it on a single V100 at 355 years.

Layer normalization

Deep networks suffer from vanishing and exploding gradients, which makes training unstable. Layer normalization steadies it by rescaling each token's activations to have mean 0 and variance 1.

Crucially it normalises across the features of one token, not across the batch. That independence from batch size is why it suits LLMs, where hardware often dictates batch size.

Two details in the real class

The LayerNorm module adds eps (1e−5) inside the square root to avoid dividing by zero, and two trainable vectors — scale and shift — so the model can learn to undo or adjust the normalisation if that helps. It also uses unbiased=False, dividing by n rather than n−1, to match the original GPT-2 implementation so pretrained weights load correctly in Unit 7.

GELU and the feed forward network

ReLU zeroes everything negative and has a sharp corner at 0. GPT uses GELU instead — smooth everywhere, and crucially it lets small negative values through rather than flattening them to zero. Neurons receiving negative input can still contribute to learning.

Both curves are computed from the real formulas: ReLU is max(0, x); GELU uses the tanh approximation the original GPT-2 was trained with, 0.5x(1 + tanh(√(2/π)(x + 0.044715x³))).

Expand, activate, contract

The FeedForward module is just two linear layers with a GELU between them. The first expands the embedding by 4× — 768 to 3,072 — and the second squeezes it back to 768. The width in and out is identical, which is what lets the blocks stack without any dimension bookkeeping.

Why expand at all? A wider intermediate space gives the network room to represent richer combinations of features before compressing back down. It's also where most of the model's parameters live — see lab 7.

Shortcut connections

In a deep stack, gradients shrink as they propagate backward, so early layers barely learn. A shortcut connection (also called skip or residual) adds a layer's input to its output, giving gradients a direct path that bypasses the layer entirely.

The transformer block

Everything so far now snaps together. A transformer block runs two sub-blocks, each with the same three-part pattern: normalise → transform → add the input back.

Attention handles relationships between tokens; the feed forward network refines each token individually. The block's output has exactly the same shape as its input, which is what makes stacking trivial.

One transformer block: normalise → attend → add the shortcut → normalise → feed-forward → add the shortcut. Shapes never change, so blocks stack like LEGO — GPT-2 small stacks twelve.

Lab 6 · One pass through the block

Step through it
Shape stays (2, 4, 768) from start to finish. The values are completely re-encoded — each output vector now carries context from the whole sequence — but the dimensions never move.
Pre-LayerNorm vs Post-LayerNorm

Normalisation happens before attention and before the feed forward network. The original 2017 transformer put it after, which is known as Post-LayerNorm and generally trains worse. GPT-2 and essentially every modern LLM use the Pre-LayerNorm arrangement shown here.

Counting the parameters

Stack twelve of those blocks between the embedding layers and an output head and you have the whole model. So how big is it really? The counter below computes every weight matrix in the architecture — nothing is hard-coded.

Worked by hand — where 163,009,536 comes from

Count every weight matrix in the architecture, at emb = 768, vocab = 50,257, context = 1,024, 12 blocks:

token embedding 50,257 × 768 = 38,597,376
position embedding 1,024 × 768 = 786,432
per block: attention (Q,K,V,proj + biases) ≈ 2.36M
feed-forward 768×3072×2 + biases ≈ 4.72M
2 LayerNorms (scale+shift) ≈ 0.003M
12 blocks × ≈7.09M ≈ 85,026,816
final LayerNorm = 1,536
output head 768 × 50,257 = 38,597,376
total = 163,009,536

Two matrices dominate: the embedding table and the output head, each ~38.6M — together nearly half the model. Lab 7 below computes this live for every GPT-2 size.

Common confusion

“Why is it called 124M when the count says 163M?” The original GPT-2 tied the output head to the embedding table — one 38.6M matrix doing both jobs — giving 163M − 38.6M ≈ 124M, the number in the name. Our implementation keeps them separate (untied layers train better), so it genuinely has 163M parameters while being architecturally the same model.

Why "124M" when the count says 163M

The original GPT-2 used weight tying: the output layer reuses the token embedding matrix instead of having its own. Both are 50,257 × 768 = 38,597,376 parameters, so sharing them removes exactly that many — leaving 124,412,160, the number GPT-2 is named for. Our implementation keeps them separate because untied layers train better, which is why our count is the larger one.

Generating text

The model outputs logits: for every position, a 50,257-long vector of raw scores, one per vocabulary entry. Turning that into text is a loop:

  • Take the logits for the last position only — that's the prediction for what comes next.
  • Softmax them into probabilities.
  • Take the argmax — the highest-scoring token ID. This is greedy decoding.
  • Append that ID to the input and repeat.

The softmax step is actually redundant: softmax is monotonic, so the argmax of the probabilities is the argmax of the logits. We include it anyway to make the logic visible.
